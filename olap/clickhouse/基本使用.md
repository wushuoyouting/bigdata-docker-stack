> **本文范围**：单节点容器装好之后怎么用。讲命令行、HTTP、Web UI、建表、导入、查询、用户与日志。本文只操作本机容器，不接外部数据源。

# ClickHouse 基本使用

> **一句话结论**：用 clickhouse-client 执行 SQL，用 HTTP 接口做脚本查询，用内置 Web UI 看查询结果。三种入口连到同一个单节点容器。

> **本文解决什么**：装完 ClickHouse 后怎么连、怎么建表、怎么导数据、怎么查元数据、怎么管用户。
>
> **适用谁**：已完成安装验收、想动手跑查询的用户。
>
> **读完能做什么**：建一张 MergeTree 表，导入 CSV，执行聚合查询，查看片段状态，创建只读用户。

---

## 一、入口总览

| 入口 | 怎么进 | 用来做什么 |
| --- | --- | --- |
| clickhouse-client | docker exec 进容器 | 交互式 SQL、批量导入 |
| HTTP 接口 | curl 调 8123 | 脚本查询、健康检查 |
| Web UI | 浏览器打开 /play | 手写 SQL、看结果表格 |
| 原生协议 | 宿主 19000 或容器别名 9000 | 客户端驱动直连 |

> 容器名 clickhouse。宿主原生协议端口为 19000，容器内仍为 9000。首次连接需要口令。

## 二、命令行查询

先加载本地口令变量。口令写在 .env 文件，该文件不提交仓库。

```bash
set -a
. /Users/wenhuadong/docker/olap/clickhouse/.env
set +a
```

交互式进入客户端。系统会提示输入口令。

```bash
docker exec -it clickhouse clickhouse-client --user default --password
```

进入后提示符为冒号加右上箭头。执行下面的语句做冒烟验证。

```sql
SELECT 1 AS ok;
```

预期输出一行一列，ok 值为 1。

脚本方式把 SQL 直接传给服务端。口令经环境变量传入，不写进命令历史。

```bash
docker exec -i -e CLICKHOUSE_PASSWORD="$CLICKHOUSE_PASSWORD" clickhouse \
  clickhouse-client --user default --query "SELECT 1 AS ok"
```

预期输出 1。

| 参数 | 作用 |
| --- | --- |
| --user | 指定用户，本机为 default |
| --password | 交互式提示输入口令 |
| --query | 执行一条语句后退出 |
| --database | 指定默认数据库 |
| --multiquery | 一条命令执行多条语句 |

> 代码块外的口令占位符写作 &lt;CLICKHOUSE_PASSWORD&gt;。真实值只放本地 .env 文件。

## 三、HTTP 与 Web UI

HTTP 接口把 SQL 放在 query 参数里。URL 中的空格转成百分号编码。

```bash
curl -s 'http://localhost:8123/?query=SELECT%201%20AS%20ok'; echo
```

预期输出 1。

健康检查不查数据，只返回服务状态。

```bash
curl -fsS http://localhost:8123/ping; echo
```

预期输出 Ok.

浏览器打开 http://localhost:8123/play。页面左侧是 SQL 输入框，右侧是结果表格。填入下面的语句后点运行。

```sql
SELECT version();
```

预期输出服务端版本号。

| 地址 | 用途 |
| --- | --- |
| http://localhost:8123/ping | 健康检查 |
| http://localhost:8123/play | 内置查询界面 |
| http://clickhouse:8123 | 同网络容器访问地址 |

> 同网络容器写服务名 clickhouse，不写 localhost。localhost 指向调用方自己。

## 四、建库与建表

先建库，再建 MergeTree 表。表按月份分区，按日期与用户排序。

```sql
CREATE DATABASE IF NOT EXISTS demo;

CREATE TABLE IF NOT EXISTS demo.events
(
    event_date Date,
    user_id UInt64,
    event_type String,
    payload String
)
ENGINE = MergeTree
PARTITION BY toYYYYMM(event_date)
ORDER BY (event_date, user_id);
```

预期输出空结果，表示语句执行成功。

写入一行数据并读回。

```sql
INSERT INTO demo.events VALUES
('2026-11-25', 1001, 'view', 'alpha'),
('2026-11-25', 1002, 'click', 'beta');

SELECT event_type, count() AS cnt
FROM demo.events
WHERE event_date = '2026-11-25'
GROUP BY event_type
ORDER BY cnt DESC;
```

预期输出两行。click 与 view 各计一行。

| 子句 | 取值 | 作用 |
| --- | --- | --- |
| ENGINE | MergeTree | 启用排序片段与后台合并 |
| PARTITION BY | toYYYYMM(event_date) | 按月分目录 |
| ORDER BY | event_date、user_id | 决定磁盘顺序与主键索引 |
| Date | 日期类型 | 存储日粒度时间 |
| UInt64 | 无符号整数 | 存储用户编号 |

> 主键不去重。同一排序键允许多行共存。

## 五、导入样例数据

先在宿主写一份 CSV 文件。文件用逗号分隔，不含表头。

```bash
cat > /Users/wenhuadong/docker/olap/clickhouse/sample-events.csv <<'EOF'
2026-11-25,1003,view,gamma
2026-11-25,1004,click,delta
2026-11-26,1005,view,epsilon
EOF
chmod 644 /Users/wenhuadong/docker/olap/clickhouse/sample-events.csv
```

把文件从标准输入喂进客户端。CSV 列顺序与表定义一致。

```bash
set -a
. /Users/wenhuadong/docker/olap/clickhouse/.env
set +a

docker exec -i -e CLICKHOUSE_PASSWORD="$CLICKHOUSE_PASSWORD" clickhouse \
  clickhouse-client --user default --database demo \
  --query "INSERT INTO events FORMAT CSV" \
  < /Users/wenhuadong/docker/olap/clickhouse/sample-events.csv
```

预期输出空，表示三行已写入。

校验导入行数。

```sql
SELECT count() AS total FROM demo.events;
```

预期输出 5。先前两行加本次三行。

| 参数 | 作用 |
| --- | --- |
| -i | 保持标准输入打开 |
| --database | 指定 demo 库 |
| FORMAT CSV | 声明输入格式为逗号分隔文本 |
| 重定向符号 | 把宿主文件送入容器标准输入 |

> 大文件导入改用 clickhouse-client 的 --query 加压缩格式。本机样例规模小，标准输入足够。

## 六、查看元数据

用系统表看库、片段与查询历史。这些表只读，不改动业务数据。

```sql
SELECT name, engine FROM system.tables WHERE database = 'demo';

SELECT partition, active, rows, bytes_on_disk
FROM system.parts
WHERE database = 'demo' AND table = 'events'
ORDER BY partition;

SELECT query, read_rows, duration_ms
FROM system.query_log
WHERE type = 'QueryFinish'
ORDER BY event_time DESC
LIMIT 5;
```

预期输出三段结果。第一段列出 events 表。第二段列出各分区的活跃片段状态。第三段列出最近五次成功查询。

| 系统表 | 能查什么 |
| --- | --- |
| system.tables | 表名、引擎、建表语句 |
| system.parts | 分区、活跃片段、行数、磁盘占用 |
| system.query_log | 查询文本、读取行数、耗时 |
| system.columns | 字段名、类型、默认值 |

> 片段数持续增长时查 system.parts。合并线程会把小片段合成大片段。

## 七、用户与权限

先创建只读用户。口令用占位符，在客户端里换成实际值。

```sql
CREATE USER analyst IDENTIFIED WITH sha256_password BY '<CH_ANALYST_PWD>';
GRANT SELECT ON demo.* TO analyst;
```

预期输出空，表示用户已创建并授权。

用新用户查询。口令只从宿主环境变量传入。

```bash
docker exec -i -e CLICKHOUSE_PASSWORD="$CH_ANALYST_PWD" clickhouse \
  clickhouse-client --user analyst --database demo \
  --query "SELECT count() FROM events"
```

预期输出当前行数。

回收权限并删除用户。

```sql
REVOKE SELECT ON demo.* FROM analyst;
DROP USER analyst;
```

| 语句 | 作用 |
| --- | --- |
| CREATE USER | 创建带口令的用户 |
| GRANT SELECT | 授予只读权限 |
| REVOKE | 收回权限 |
| DROP USER | 删除用户 |

> 代码块外的口令占位符写作 &lt;CH_ANALYST_PWD&gt;。明文口令不进文档与仓库。

## 八、日志与备份

服务日志落在宿主的 logs-standalone 目录。容器内的路径是 /var/log/clickhouse-server。

```bash
docker logs -f clickhouse --tail 100

docker exec clickhouse sh -c 'ls -lt /var/log/clickhouse-server/ | head'
```

预期输出近期日志条目，内容包括启动信息与查询异常。

冻结表可生成一致性快照。快照落在数据目录下的 shadow 子目录。

```sql
ALTER TABLE demo.events FREEZE;
```

预期输出执行成功。把对应序号的目录复制到备份位置即可留存。

| 位置 | 内容 |
| --- | --- |
| logs-standalone/ | 服务日志与错误堆栈 |
| data-standalone/ | 数据片段与元数据 |
| data-standalone/shadow/ | FREEZE 生成的快照 |

> 快照只覆盖单表。跨表一致性需要逐表冻结，并安排在同一维护窗口。

| 想做什么 | 命令或入口 |

## 十、故障速查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 命令行报 Authentication failed | 口令未传或写错 | 核对 .env 中 CLICKHOUSE_PASSWORD 的值 |
| curl 8123 无响应 | 容器未起或端口不通 | docker ps 与 ping 复查 |
| 容器内访问 8123 被拒 | 写了 localhost | 改 http://clickhouse:8123 |
| 导入 CSV 列错位 | 字段顺序与表定义不一致 | 按表定义重排列 |
| 查询只扫到部分数据 | 分区键取值与过滤条件不符 | 核对 toYYYYMM 表达式 |
| 片段数持续上涨 | 后台合并跟不上写入 | 查 system.parts，降低小批次写入频率 |
| 创建用户报权限不足 | 当前用户没有 ACCESS MANAGEMENT | 用 default 用户执行 |
| Web UI 打不开 | 访问了错误路径 | 用 http://localhost:8123/play |

> 本机原生协议端口为 19000。驱动连接时写宿主 19000，容器内组件写 clickhouse:9000。

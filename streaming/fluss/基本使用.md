# 基本使用

本文用 Flink SQL 操作 Fluss，覆盖建库建表、两类表读写、分区与湖仓分层。适用于已完成安装部署的读者。读完能独立完成日志追加、主键更新、变更订阅与历史回溯。

本文所有语句在 Flink SQL 客户端执行。进入客户端的命令如下。

```
docker exec -it flink-jobmanager /opt/flink/bin/sql-client.sh
```

## 一、准备目录

### 1.1 注册 Catalog

执行以下语句注册 Catalog。

```
CREATE CATALOG fluss_catalog WITH(
  'type'='fluss',
  'bootstrap.servers'='fluss-coordinator:9123'
);
USE CATALOG fluss_catalog;
```

参数说明如下。

| 参数 | 案例值 | 说明 |
| --- | --- | --- |
| type | fluss | 固定值，表示 Fluss Catalog |
| bootstrap.servers | fluss-coordinator:9123 | 集群地址，多个地址用逗号分隔 |
| default-database | fluss | 可选项，切换 Catalog 时的默认库 |

### 1.2 建立数据库

执行以下语句建立并切换数据库。

```
CREATE DATABASE demo;
USE demo;
```

执行 SHOW TABLES 可查看当前库下的表，新建库时输出为空。

## 二、日志表

### 2.1 建表

日志表用于追加场景。每次写入生成一条新记录，不覆盖旧记录。

```
CREATE TABLE order_events (
  order_id BIGINT,
  item_id BIGINT,
  amount INT,
  address STRING
) WITH (
  'bucket.num'='4'
);
```

bucket.num 设为 4，表示表被分成 4 个桶。桶是数据分布与并行度的基本单位。

### 2.2 追加写入

执行以下语句写入三条记录。

```
INSERT INTO order_events VALUES
  (1001, 2001, 35, 'chengdu'),
  (1002, 2002, 68, 'shenzhen'),
  (1003, 2003, 19, 'beijing');
```

作业提交后显示作业编号。写入完成前可查看作业状态。

### 2.3 批量查询

把执行模式切为 batch，再查询全表。

```
SET 'execution.runtime-mode' = 'batch';
SELECT * FROM order_events;
```

预期输出三行记录，字段值与写入一致。

### 2.4 流式消费

把执行模式切回 streaming，从最新位置消费。

```
SET 'execution.runtime-mode' = 'streaming';
SELECT * FROM order_events;
```

客户端持续运行。再开一个会话写入新记录，可看到新行实时追加。按 Ctrl+C 结束查询。

## 三、主键表

### 3.1 建表

主键表用于维护实体当前状态。相同主键的写入按合并引擎更新同一行。

```
CREATE TABLE shop_summary (
  shop_id BIGINT,
  user_id BIGINT,
  num_orders INT,
  total_amount INT,
  PRIMARY KEY (shop_id, user_id) NOT ENFORCED
) WITH (
  'bucket.num'='4'
);
```

主键必须包含全部分区列。未分区时主键即行标识。

### 3.2 更新与点查

写入两条记录，其中一条主键重复。

```
INSERT INTO shop_summary VALUES
  (1, 101, 3, 300),
  (1, 101, 5, 520);
```

切到 batch 模式按键点查。

```
SET 'execution.runtime-mode' = 'batch';
SELECT * FROM shop_summary WHERE shop_id = 1 AND user_id = 101;
```

预期只返回一行，num_orders 为 5，total_amount 为 520。默认合并引擎保留最后一次写入。

### 3.3 读取变更流

主键表把每次更新记入日志。通过虚拟表读取变更记录。

```
SELECT * FROM shop_summary$changelog;
```

输出包含更新前后镜像。变更流可用于下游增量计算，避免全量比对。

## 四、分区表

### 4.1 手工分区

分区列只支持 STRING 类型。执行以下语句建立分区日志表。

```
CREATE TABLE order_events_by_day (
  order_id BIGINT,
  item_id BIGINT,
  amount INT,
  dt STRING
) PARTITIONED BY (dt);
```

用 INSERT INTO 写入不存在的分区，Fluss 会自动创建该分区。

```
INSERT INTO order_events_by_day VALUES (2001, 3001, 42, '2026-11-19');
SHOW PARTITIONS order_events_by_day;
```

预期输出分区 dt=2026-11-19。

### 4.2 自动分区

自动分区由 Fluss 按时间单位预先创建与回收分区。

```
CREATE TABLE order_events_auto (
  order_id BIGINT,
  item_id BIGINT,
  amount INT,
  dt STRING
) PARTITIONED BY (dt) WITH (
  'bucket.num'='4',
  'table.auto-partition.enabled'='true',
  'table.auto-partition.time-unit'='day'
);
```

参数说明如下。

| 参数 | 案例值 | 说明 |
| --- | --- | --- |
| table.auto-partition.enabled | true | 开启自动分区 |
| table.auto-partition.time-unit | day | 分区粒度，支持 day 与 hour |
| table.auto-partition.num-precreate | 1 | 预创建未来分区数 |
| table.auto-partition.num-retention | 7 | 保留历史分区数 |

### 4.3 主键表分区约束

分区主键表的分区列必须包含在主键中。示例如下。

```
CREATE TABLE shop_daily (
  dt STRING,
  shop_id BIGINT,
  user_id BIGINT,
  num_orders INT,
  PRIMARY KEY (dt, shop_id, user_id) NOT ENFORCED
) PARTITIONED BY (dt);
```

同一 user_id 写入不同 dt 时视为不同行。设计时先确认实体的时间边界。

## 五、湖仓分层

### 5.1 开启分层

湖仓分层把 Fluss 数据持续沉降到开放表格式。执行以下语句开启。

```
ALTER TABLE order_events SET ('table.datalake.enabled'='true');
ALTER TABLE order_events SET ('table.datalake.freshness'='5min');
```

freshness 设为 5min，表示湖端数据的目标新鲜度。分层由独立的 Flink 作业执行，不占用写入链路。

### 5.2 联合读取

开启分层后，查询可同时覆盖 Fluss 中的热数据与湖端的历史数据。执行以下语句按 batch 模式读全表。

```
SET 'execution.runtime-mode' = 'batch';
SELECT COUNT(*) FROM order_events;
```

联合读取依赖分层进度。分层完成后，历史记录保留在湖端，本地日志按保留策略清理。

### 5.3 保留策略

不同数据有不同的生命周期。参数说明如下。

| 参数 | 案例值 | 说明 |
| --- | --- | --- |
| table.log.ttl | 7 d | 日志保留期，需覆盖消费延迟与重放需求 |
| table.log.local-ttl | 1 d | 本地日志保留期，超时后仅远端可读 |
| table.log.tiered.local-segments | 5 | 上传后本地保留的日志段数 |
| table.kv.ttl | 30 d | 主键表当前行的过期时间 |

注意：键值过期清理不向变更流发送删除事件。下游若依赖删除事件，需自行处理过期逻辑。

## 六、运维命令

### 6.1 修改桶数

执行以下语句调整目标桶数。

```
ALTER TABLE order_events SET ('bucket.num'='8');
```

该值只对新分区生效，已有分区保持原桶数。非分区表、聚合合并引擎表不支持该操作。

### 6.2 修改表结构

Fluss 支持在末尾追加可空列，不重写已有数据。

```
ALTER TABLE order_events ADD COLUMN coupon_code STRING;
```

已有行的新列读作 null。开启湖仓分层时，所选湖格式也需支持该变更。

### 6.3 常用命令速查

| 操作 | 语句 |
| --- | --- |
| 列出数据库 | SHOW DATABASES |
| 列出表 | SHOW TABLES |
| 查看表结构 | DESCRIBE order_events |
| 查看分区 | SHOW PARTITIONS order_events_by_day |
| 增加分区 | ALTER TABLE order_events_by_day ADD PARTITION (dt='2026-11-20') |
| 删除分区 | ALTER TABLE order_events_by_day DROP PARTITION (dt='2026-11-20') |
| 删除表 | DROP TABLE order_events |
| 重置参数 | ALTER TABLE order_events RESET ('table.datalake.enabled') |

# StarRocks 操作

> 一句话结论：StarRocks 对外提供两类入口。查询走 FE 的 MySQL 协议，管理与导入走 FE 的 HTTP。

---

表 1-1 地址判据

## 二、连接集群

### 2.1 本机客户端

```bash
set -a; . /Users/wenhuadong/docker/olap/starrocks/.env; set +a
MYSQL_PWD="$SR_ROOT_PWD" mysql -h127.0.0.1 -P19030 -uroot -e 'select current_version();'
```

① 宿主须有 mysql 客户端。
② 本机 root 口令已修改。命令从 .env 取 MYSQL_PWD，不回显口令。
③ 默认空口令环境去掉 MYSQL_PWD 前缀即可。
④ 端口写 19030，不写 9030。9030 是容器内部端口。

### 2.2 容器内客户端

```bash
set -a; . /Users/wenhuadong/docker/olap/starrocks/.env; set +a
docker exec -it -e MYSQL_PWD="$SR_ROOT_PWD" starrocks mysql -h127.0.0.1 -P9030 -uroot
```

镜像内置 /usr/bin/mysql。宿主没有客户端时走这条。依据：镜像内文件实测。

### 2.3 图形客户端与 BI

表 2-1 连接写法

| 客户端 | 连接写法 | 备注 |
| --- | --- | --- |
| DBeaver / DataGrip | 主机 127.0.0.1，端口 19030，用户 root | 驱动选 MySQL |
| Superset 同网络数据源 | mysql+pymysql://root:&lt;SR_ROOT_PWD&gt;@starrocks:9030/information_schema?charset=utf8mb4 | 仅写法登记，安装阶段不建数据源 |
| DolphinScheduler SQL 任务 | starrocks:9030 | 仅写法登记，安装阶段不建数据源 |

⚠️ 注意：口令含特殊字符时须做 URL 编码。真值只写本机 starrocks/.env，权限 600。口令不进文档与日志。

### 2.4 改口令与重启约束

```sql
set password for 'root'@'%' = password('<SR_ROOT_PWD>');
```

⚠️ 注意：改口令后重建容器必须带 -e MYSQL_PWD。镜像 director/run.sh 用该变量连 FE 完成 bootstrap。

⚠️ 注意：该语法在 4.1.7 是否可用，本次未实测。

## 三、状态查看

### 3.1 用 SQL 查节点

```sql
show frontends\G
show backends\G
show compute nodes\G
```

\G 是 mysql 客户端的纵向显示指令，在客户端内执行。

表 3-1 节点判据

| 命令 | 关键字段 | 期望值 |
| --- | --- | --- |
| show frontends | Alive、Role | true、LEADER 或 FOLLOWER |
| show backends | Alive、TotalCapacity | true、有可用容量 |
| show compute nodes | 返回行数 | 单容器 allin1 返回空属正常，本次未实测 |

### 3.2 HTTP 健康检查

```bash
curl -fsS http://localhost:18030/api/health
curl -fsS http://localhost:18040/api/health
docker exec starrocks /data/deploy/health_check.sh
```

health_check.sh 同时检查 FE 与 BE，并要求 bootstrap_done 文件存在。依据：镜像 /data/deploy/health_check.sh 实测。

### 3.3 Web UI 与日志

表 3-2 界面与日志位置

| 项 | 地址或路径 |
| --- | --- |

## 四、库表与数据操作

⚠️ 注意：本章全部是示例。安装阶段不执行 create database 与 create table。

### 4.1 建库建表

```sql
show databases;
create database if not exists demo_sr;
use demo_sr;
create table if not exists t_order (
  order_id bigint,
  user_id int,
  amount decimal(10,2),
  order_date date,
  create_time datetime
)
duplicate key(order_id)
distributed by hash(order_id) buckets 4
properties ("replication_num" = "1");
desc t_order;
show create table t_order;
```

① duplicate key 是明细模型。
② replication_num = 1 对应单 BE。镜像 fe.conf 已设 default_replication_num = 1，本例显式写出便于核对。
③ 表名与 SQL 类型都用小写。

### 4.2 写入与查询

```sql
insert into t_order values
  (1001, 7, 128.50, '2026-11-13', '2026-11-13 09:10:00'),
  (1002, 7, 36.00, '2026-11-13', '2026-11-13 10:20:00');

select order_date, count(*) as cnt, sum(amount) as amt
from t_order
group by order_date
order by order_date;

explain select * from t_order where order_id = 1001;
```

### 4.3 Stream Load

本节命令在本机 shell 执行。不要进入 mysql 客户端执行。

⚠️ 注意：FE 把 Stream Load 重定向到 BE 的 8040。本镜像 BE 以 127.0.0.1 注册。从宿主或其他容器发起时，重定向地址指向发起方自己，导入会失败。本例在 starrocks 容器内发起。

```bash
# 读取本机 .env，把 root 口令导入当前 shell
set -a; . /Users/wenhuadong/docker/olap/starrocks/.env; set +a

# 在宿主机上生成样本 CSV，字段顺序与表定义一致
printf '1003,8,59.90,2026-11-13,2026-11-13 11:00:00\n' > ~/temp/order.csv

# 把 CSV 拷入到 starrocks 容器内，容器内路径与下方 -T 参数一致
docker cp ~/temp/order.csv starrocks:/tmp/order.csv

# 在宿主机上发起 Stream Load
# -u 使用 .env 中的 root 口令，空口令会报 Access denied
# 小文件必须带Expect 头，否则会报 100-continue 错误
# label 全局唯一，重跑时换一个新值
docker exec -e MYSQL_PWD="$SR_ROOT_PWD" starrocks curl -sS --location-trusted \
  -u "root:$SR_ROOT_PWD" \
  -H "Expect: 100-continue" \
  -H "label: order_demo_001" \
  -H "column_separator:," \
  -H "columns: order_id,user_id,amount,order_date,create_time" \
  -T /tmp/order.csv \
  http://127.0.0.1:8030/api/demo_sr/t_order/_stream_load
```

① 判据：返回 JSON 中 Status 为 Success，NumberLoadedRows 为 1。

### 4.4 查导入任务

```sql
show load from demo_sr;
```

### 4.5 删除示例对象

```sql
drop table if exists demo_sr.t_order;
drop database if exists demo_sr;
```

## 五、日常运维

### 5.1 启停与分时

表 5-1 运维动作

| 动作 | 命令 | 影响 |
| --- | --- | --- |
| 停止 | docker stop starrocks | 不删数据 |
| 启动 | docker start starrocks | 等 1 到 3 分钟再验 |
| 看状态 | docker ps --filter name=starrocks | 看 Up 与端口映射 |
| 看健康 | docker inspect --format '{{.State.Health.Status}}' starrocks | 期望 healthy |

⚠️ 注意：本机内存 16G。跑 StarRocks 时先停 Superset 等非必要组件。Doris BE 最怕被 OOM 杀掉。

### 5.2 持久化检查

```bash
set -a; . /Users/wenhuadong/docker/olap/starrocks/.env; set +a
du -sh /Users/wenhuadong/docker/olap/starrocks/volumes/fe/meta \
       /Users/wenhuadong/docker/olap/starrocks/volumes/be/storage
docker stop starrocks && docker start starrocks
MYSQL_PWD="$SR_ROOT_PWD" mysql -h127.0.0.1 -P19030 -uroot -e 'show backends\G'
```

判据：Alive 为 true。建过示例表时，该表仍在。

### 5.3 备份与重置

① 备份：先 docker stop starrocks，再拷贝 volumes/ 两个目录到本机其他位置。
② 重置：先停容器，再清空 volumes/ 两个目录。FE 元数据与 BE 数据会全部丢失。

⚠️ 注意：拷贝 FE 元数据前必须停容器。运行中拷贝会拿到不一致的元数据快照。

### 5.4 与其他组件的连接写法

表 5-2 跨组件写法登记

| StarRocks | MinIO | http://minio:9000 |

### 5.5 常见错误

表 5-3 错误表

| 现象 | 根因 | 处理 |
| --- | --- | --- |
| Connection refused on 19030 | 容器未起，或端口写成了 9030 | 用 19030；先查 docker ps |
| Unknown host starrocks | 容器不在 whd-net，或别名没生效 | 查 docker network inspect whd-net；重建时带 --network-alias starrocks |
| Access denied for root | 口令已改 | 加 -p 或 MYSQL_PWD；重建时带 -e MYSQL_PWD |
| FE 反复重启 | hostname 变了，或内存不足 | 固定 --hostname starrocks；降堆；查 supervisor 日志 |
| 建表失败，副本数报错 | 副本数大于可用 BE 数 | 查 show backends；properties 写 replication_num = 1 |
| Stream Load 307 后失败 | 重定向到 127.0.0.1:8040 | 在 starrocks 容器内发起 |
| Stream Load 报 Access denied for root | 使用空口令 -u root:，实际口令已改 | 从 .env 取口令，用 -u root:$SR_ROOT_PWD |
| Stream Load 报 There is no 100-continue header | 小文件时 curl 不发 Expect 头 | 加 -H "Expect: 100-continue" |
| 首次查询很慢 | amd64 模拟启动 | 预留 3 分钟，不与其他大组件同开 |
| 删容器后日志没了 | 日志在容器可写层 | 排查前先导出 docker logs |

## 七、本篇小结

1. 查询走 19030（本机）或 starrocks:9030（同网络容器）。
2. 管理走 18030（FE HTTP）与 18040（BE HTTP）。
3. 库表示例不属于安装阶段。
4. 口令、hostname、两个持久化目录是三条硬约束。
5. 未实测项直说未实测，不猜测结论。

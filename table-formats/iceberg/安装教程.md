# Iceberg 安装教程

本文指导在本机用 Docker 搭起可运行的 Iceberg 环境。适用对象是已安装 Docker 的工程师。读完能启动一套 Flink 加 REST Catalog 加对象存储的编排，并确认各服务就绪。

## 一、方案与取舍

本教程采用 Apache 官方 Flink Quickstart 编排。该编排把计算层、Catalog 层与存储层装在同一个网络里，开箱即用。

计算引擎选 Flink。Flink 对 Iceberg 的读写支持成熟，SQL 客户端可直接验证快照与演进。Spark 方案需要手工挂载 runtime jar，步骤更多。

对象存储选 rustfs。官方编排内置 rustfs，接口兼容 S3。本机已运行 MinIO 并占用 9000 端口，本编排不映射宿主机端口，两者互不冲突。官方编排不复用本机 MinIO，因为容器网络隔离，跨容器访问需额外配置。

REST Catalog 使用官方 fixture 镜像。它把元数据存在对象存储，无需另配数据库，适合本地验证。

## 二、安装前复核

安装前核对本机 Docker 环境。本文按实测环境写，版本如下。

| 项 | 实测值 |
| --- | --- |
| Docker | 29.7.2 |
| Docker Compose | v5.5.0 |
| 系统 | macOS |

执行以下命令复核版本。

```bash
docker --version
docker compose version
```

预期输出分别包含 29.7.2 与 v5.5.0。版本不同也可继续，命令保持兼容。

官方编排只在 iceberg_net 内部通信，不向宿主机映射端口。因此本机 8081、9000 端口占用不影响本环境。执行以下命令可查看本机监听端口。

```bash
lsof -nP -iTCP:8081 -iTCP:8181 -iTCP:9000 -sTCP:LISTEN
```

## 三、获取编排文件

官方编排随 Iceberg 源码发布。执行以下命令拉取源码到工作目录。

```bash
cd /Users/wenhuadong/docker/table_format/Iceberg
git clone --depth 1 https://github.com/apache/iceberg.git
```

编排文件位于 iceberg/docker/iceberg-flink-quickstart/docker-compose.yml。执行以下命令确认文件就位。

```bash
ls iceberg/docker/iceberg-flink-quickstart/docker-compose.yml
```

预期输出为该文件的路径。

## 四、编排说明

编排定义五个服务。各服务职责与镜像如下。

| 服务 | 镜像 | 职责 |
| --- | --- | --- |
| jobmanager | 本地构建 | 调度作业，提供 SQL 客户端 |
| taskmanager | 本地构建 | 执行作业任务 |
| iceberg-rest | apache/iceberg-rest-fixture | 提供 REST Catalog 接口 |
| object-store | rustfs/rustfs:1.0.0 | 存放数据与元数据文件 |
| create-bucket | rustfs/rustfs:1.0.0 | 初始化 warehouse 存储桶 |

Flink 镜像由本地构建。构建时加入 Iceberg 运行时依赖。构建参数写在同目录的 Dockerfile 中。

服务按依赖顺序启动。create-bucket 初始化完成后，iceberg-rest 才启动。iceberg-rest 健康后，jobmanager 才启动。jobmanager 健康后，taskmanager 才启动。

## 五、启动环境

执行以下命令构建镜像并启动全部服务。

```bash
cd /Users/wenhuadong/docker/table_format/Iceberg
docker compose -f iceberg/docker/iceberg-flink-quickstart/docker-compose.yml up -d --build
```

首次运行会下载基础镜像并构建 Flink 镜像，耗时较长。后续运行直接复用已构建镜像。

本组件在 whd-net 的静态地址为 172.30.0.4。compose 内 iceberg-rest 使用该地址。其余服务按静态段从 .4 起顺延取号。重建容器须保留原 IP。依据：/Users/wenhuadong/docker/code-wiki/06-配置基线与例外.md。

容器使用的固定配置如下。这些值写在编排内，无需手工修改。

| 配置项 | 值 | 用途 |
| --- | --- | --- |
| CATALOG_WAREHOUSE | s3://warehouse/ | 数据存放根路径 |
| CATALOG_IO__IMPL | org.apache.iceberg.aws.s3.S3FileIO | 文件读写实现 |
| CATALOG_S3_ENDPOINT | http://object-store:9000 | 对象存储内网地址 |
| CATALOG_S3_ACCESS__KEY__ID | admin | 存储访问账号 |
| CATALOG_S3_SECRET__ACCESS__KEY | password | 存储访问密钥 |
| S3_ENDPOINT | http://object-store:9000 | Flink 侧存储地址 |
| AWS_REGION | us-east-1 | S3 签名区域 |

账号与密钥是官方编排的本地示例值，仅用于容器内通信。生产环境须替换为独立凭据。

## 六、进入 SQL 客户端

服务就绪后，执行以下命令进入 Flink SQL 客户端。

```bash
docker exec -it jobmanager ./bin/sql-client.sh
```

出现 Flink SQL 提示符即进入成功。后续建表与查询操作在该客户端内执行。

## 七、停止环境

验证结束后，执行以下命令停止并移除容器。

```bash
cd /Users/wenhuadong/docker/table_format/Iceberg
docker compose -f iceberg/docker/iceberg-flink-quickstart/docker-compose.yml down
```

该命令不删除镜像与源码。再次启动可直接执行第五步命令。

## 八、验收对照

启动与进入客户端完成后，按以下判据验收。

| 判据 | 检查方式 | 通过标准 |
| --- | --- | --- |
| 服务运行 | docker compose -f iceberg/docker/iceberg-flink-quickstart/docker-compose.yml ps | jobmanager、taskmanager、iceberg-rest、object-store 四者状态为 Up |
| 初始化完成 | 同上命令 | create-bucket 状态为 Exited 且退出码为 0 |
| Catalog 就绪 | docker exec iceberg-rest curl -f http://localhost:8181/v1/config | 返回 json，退出码为 0 |
| 存储就绪 | docker exec object-store curl -f http://localhost:9000/health/ready | 退出码为 0 |
| 作业调度就绪 | docker exec jobmanager curl -f http://localhost:8081/overview | 返回 json，退出码为 0 |
| 客户端可用 | docker exec -it jobmanager ./bin/sql-client.sh | 出现 Flink SQL 提示符 |

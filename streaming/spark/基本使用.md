# Spark 基本使用

> **一句话结论**：spark-sql 写 SQL，spark-shell 与 pyspark 做交互，spark-submit 提交 jar。三个入口都用 docker exec 进入同一个容器，提交到同一个集群。

> **本文解决什么**：装完 Spark 后怎么建表查数、怎么看执行计划、怎么提交作业、怎么回看历史。
>
> **适用谁**：已完成安装教程验收、想动手用集群的用户。
>
> **读完能做什么**：跑通一条建表到查询的链路，看懂执行计划里的 shuffle，提交示例作业并查看历史。

## 一、入口总览

| 入口 | 怎么进 | 用途 |
| --- | --- | --- |
| Master UI | 浏览器打开 http://localhost:18083 | 看 Worker、运行中应用、已完成应用 |
| History Server | 浏览器打开 http://localhost:18084 | 回看已完成应用的执行细节 |
| spark-sql | docker exec 进容器 | 交互式 SQL，建表查数 |
| spark-shell | docker exec 进容器 | Scala 交互，写 RDD 与 DataFrame |
| pyspark | docker exec 进容器 | Python 交互，写 DataFrame |
| spark-submit | docker exec 进容器 | 提交打包好的 jar 作业 |

> 所有入口共用容器 spark。交互式命令加 -it，批量执行用 -i 或 -e。容器内提交到 spark://spark:7077。

## 二、SQL 交互

进入 SQL 交互界面。

```bash
docker exec -it spark /opt/spark/bin/spark-sql --master spark://spark:7077
```

预期输出：提示符变成 spark-sql，并打印版本号与 Spark master 地址。

先确认能查数。

```sql
SELECT 1 AS ok;
SHOW DATABASES;
```

预期输出：返回一行 ok 为 1，以及 default 库。

| 语句 | 作用 |
| --- | --- |
| SHOW DATABASES; | 列出所有库 |
| USE demo; | 切换当前库 |
| SHOW TABLES; | 列出当前库的表 |
| DESCRIBE orders; | 查看表结构与存储格式 |
| EXPLAIN SELECT ...; | 查看逻辑计划与物理计划 |
| quit; | 退出交互界面 |

> 不带库名建表会落在 default 库。表数据落在 /opt/spark/warehouse，对应宿主目录 warehouse。

## 三、建表与查询

复制整段执行。三条语句依次建库、建表、插数。

```sql
CREATE DATABASE IF NOT EXISTS demo;
USE demo;

CREATE TABLE IF NOT EXISTS orders (
  order_id int,
  user_id  int,
  amount   decimal(10,2),
  city     string,
  dt       string
) USING parquet;

INSERT INTO orders VALUES
  (1, 1001, 120.50, '北京', '2026-11-01'),
  (2, 1002,  80.00, '上海', '2026-11-01'),
  (3, 1001, 200.00, '北京', '2026-11-02'),
  (4, 1003,  45.00, '广州', '2026-11-02'),
  (5, 1002, 310.00, '上海', '2026-11-03');
```

预期输出：INSERT 完成后打印一行，说明写入的行数。

查询按城市汇总。

```sql
SELECT city, count(*) AS cnt, sum(amount) AS amt
FROM orders
GROUP BY city
ORDER BY amt DESC;
```

预期输出：三行，上海最高、北京其次、广州最低。

看执行计划，找 shuffle 节点。

```sql
EXPLAIN SELECT city, sum(amount) FROM orders GROUP BY city;
```

预期输出：计划树中出现 Exchange 节点。它代表一次按城市重分发，也就是 shuffle。

再加一列排名。

```sql
SELECT city, dt, sum(amount) AS amt,
       rank() OVER (PARTITION BY city ORDER BY sum(amount) DESC) AS rk
FROM orders
GROUP BY city, dt;
```

预期输出：每行带排名列。rank 在聚合之后计算，不需要再写子查询。

> 表用 parquet 格式存。它是列存，按列读取，压缩比高。小数据量下与文本格式差别不大。数据量越大，差距越大。

## 四、Scala 与 Python 交互

Scala 交互入口。

```bash
docker exec -it spark /opt/spark/bin/spark-shell --master spark://spark:7077
```

输入一段词频统计。

```scala
val rdd = sc.parallelize(Seq("a b", "b c", "c d"))
rdd.flatMap(_.split(" ")).map((_, 1)).reduceByKey(_ + _).collect()
```

预期输出：一个数组，元素为字母与次数组成的二元组。

Python 交互入口。

```bash
docker exec -it spark /opt/spark/bin/pyspark --master spark://spark:7077
```

输入一段 DataFrame 聚合。

```python
df = spark.range(10)
df.selectExpr("sum(id) as total", "count(*) as cnt").show()
```

预期输出：total 为 45，cnt 为 10。

| 语言 | 入口 | 适合 |
| --- | --- | --- |
| Scala | spark-shell | 贴近 Spark 原生 API，调试算子 |
| Python | pyspark | 数据处理脚本，与 pandas 习惯接近 |
| SQL | spark-sql | 分析查询，不用写代码 |

> 退出交互界面用 Ctrl+D 或 quit。容器不退出，集群继续运行。

## 五、提交 jar 作业

镜像自带示例 jar。用它验证提交链路。

```bash
JAR=$(docker exec spark bash -c 'ls /opt/spark/examples/jars/spark-examples_*.jar | head -1')
docker exec spark /opt/spark/bin/spark-submit \
  --master spark://spark:7077 \
  --class org.apache.spark.examples.SparkPi \
  "$JAR" 10
```

预期输出：日志刷过若干阶段，末尾打印 Pi is roughly 3.14。

| 参数 | 作用 |
| --- | --- |
| --master | 提交到哪个集群 |
| --class | 程序入口类 |
| 最后的 10 | 传给 main 的切片数 |

作业结束后在 Master UI 的 Completed Applications 里能查到记录。

> 自制作业需要把 jar 放进容器。复制到 /opt/spark/custom-jars 后软链进 jars，或直接 docker cp 到 /opt/spark/jars。生产做法是构建自定义镜像。

## 六、查看作业与历史

**Master UI** 首页分三块。Workers 显示注册的 Worker 与空闲资源。Running Applications 显示正在跑的应用。Completed Applications 显示已结束的应用。

点应用名后的 Application Detail UI，进入应用自己的界面。页面有 Stages、Storage、Environment、SQL 四个页签。SQL 页签列出执行过的语句与耗时，是排查慢查询的第一入口。

**History Server** 回看已结束的应用。事件日志在应用运行时写入，应用结束后才完整。

| 想看什么 | 去哪看 |
| --- | --- |
| 有几台 Worker、多少空闲核 | Master UI 首页 |
| 当前应用卡在哪个阶段 | 应用详情 Stages 页 |
| 哪条 SQL 最慢 | 应用详情 SQL 页 |
| 已结束应用的完整过程 | History Server http://localhost:18084 |
| 执行计划里的 shuffle | SQL 前加 EXPLAIN，或看 SQL 页的 plan |

> 应用界面不单独映射端口。它通过 Master 的反向代理提供，链接已在 Master UI 内。宿主浏览器直接点即可。

## 七、停止与清理

停止正在运行的应用，在 Master UI 的 Running Applications 里点 Kill。命令行也可提交结束后自动退出。

```bash
docker exec spark /opt/spark/bin/spark-submit --status <APP_ID>
```

代码块内的尖括号保持原样。实际执行时换成应用 ID。

清理练习数据。

```sql
DROP TABLE IF EXISTS demo.orders;
DROP DATABASE IF EXISTS demo CASCADE;
```

预期输出：两条语句各打印一行执行结果。

容器本身按需停止。

```bash
docker stop spark
docker start spark
```

> 停容器不删数据。events 与 warehouse 都在宿主目录里。

## 九、故障速查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 提交后一直 WAITING | 没有空闲核或内存 | 看 Master UI 空闲资源，调大 Worker 的 --cores 与 --memory |
| 执行器反复退出 | 容器内存不足 | 调小 executor.memory，或停其他组件 |
| Table or view not found | 未切换库 | 先 USE demo，或写全库名 |
| 中文显示为问号 | 客户端字符集不对 | 在容器内执行，或设置 LANG 环境变量 |
| 查询很慢且计划有多层 Exchange | 多次 shuffle | 减少 group by 层数，或提前过滤 |
| 应用链接打不开 | 反向代理未生效 | 确认两项 proxy 配置已加载，重建容器 |
| 历史服务里没有新应用 | 应用未结束或未开事件日志 | 等应用结束，核对 eventLog 两项配置 |
| 建表报权限错误 | warehouse 目录不可写 | 给目录 777 权限后重建表 |
| spark-sql 卡住无输出 | 语句未以分号结尾 | 补分号，或按 Ctrl+C 重来 |
| 磁盘占用变大 | 反复插入产生小文件 | 定期 DROP 重建表，或做合并 |

## 十、小结

1. 三个入口共用一个容器与一个集群。SQL 用 spark-sql，代码用 spark-shell 或 pyspark，打包作业用 spark-submit。
2. 建表数据落在挂载目录 warehouse。事件日志落在 events，历史服务从同一目录读取。
3. 看执行计划先找 Exchange。它出现就代表一次 shuffle，是调优重点。
4. 应用界面不单独开端口，通过 Master 反向代理访问。
5. 停容器不丢数据。要重置库表才动 warehouse 目录。

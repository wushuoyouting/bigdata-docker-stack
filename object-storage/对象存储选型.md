# 对象存储选型

本文统一介绍主流开源对象存储方案。文中给出对比、选型要点与迁移步骤。适用对象是搭建湖仓底座或维护对象存储集群的团队。读完能按场景选定方案。信息核验日期为 2026-11-24。

## 一、结论

对象存储选型由场景决定。湖仓新集群优先 SeaweedFS 或 Garage。大规模企业存储选 Ceph RGW。轻量试点选 RustFS。存量兼容迁移按原格式选对应分支。

## 二、方案对比

| 方案 | 许可 | 维护状态 | 核心定位 | 优势 | 局限 |
| --- | --- | --- | --- | --- | --- |
| SeaweedFS | Apache 2.0 | 活跃 | 海量小文件与湖仓底座 | S3 兼容，单节点可起 | 多节点运维需经验 |
| Garage | AGPLv3 | 活跃 | 轻量与跨机房复制 | 单节点可起，复制完整 | 初始配置较复杂 |
| RustFS | Apache 2.0 | 活跃试点 | 轻量替代方案 | 运维形态接近主流 | 生态较新 |
| Ceph RGW | LGPL | 长期活跃 | 企业级统一存储 | 成熟稳定，生态完整 | 部署运维投入最高 |
| SILO | AGPLv3 | 社区维护 | 存量迁移过渡 | API 与磁盘格式兼容 | 依赖小团队维护 |
| MinIO 社区版 | AGPLv3 | 已归档 | 历史方案 | 曾广泛部署 | 不再分发二进制与镜像 |

SeaweedFS 4.47、Garage 2.3.0、RustFS 1.0.1 与 SILO RELEASE.2026-09-16 来自第三方记录。各方案版本以官方发布页为准。

## 三、方案说明

SeaweedFS 采用 Go 实现。该方案定位是海量小文件与湖仓底座。对象存储承载 Iceberg 与 Paimon 文件。

Garage 采用 Rust 实现。该方案定位是轻量部署与跨机房复制。单节点可启动，多站点复制是核心能力。

RustFS 采用 Rust 实现。运维形态保留 9000 与 9001 端口。该方案处于试点阶段。

Ceph RGW 是 Ceph 的对象网关。该方案适合已有 Ceph 团队的场景。运维投入在本表方案中最高。

SILO 是社区维护的兼容分支。该分支保持 API 与磁盘格式兼容。适合存量环境过渡。

MinIO 社区版在 2025-10 转为 source-only 分发。仓库在 2026-04 归档。Docker Hub 仓库在 2026-09 下架。最后镜像含 CVE-2025-62506。新环境无法直接拉取该镜像。

注意：归档与漏洞信息只影响存量部署。密码凭据不得写入配置文件或文档。

## 四、选型要点

湖仓新集群选 SeaweedFS 或 Garage。前者适配海量小文件，后者适配跨机房。

企业核心存储选 Ceph RGW。已有 Ceph 团队时运维成本可控。

轻量试点选 RustFS。先在小范围观察稳定性。

存量迁移按兼容目标选 SILO。该分支兼容原 API 与磁盘格式。

新建生产集群不取已归档方案。镜像下架会导致部署失败。

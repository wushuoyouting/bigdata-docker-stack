> **本文范围**：独立 Flink 装好之后，如何对接 Doris、MinIO 与 Paimon，完成「Doris 读 ADS 结果 → Flink 写 Paimon 湖表 → Doris 只读回查」的闭环。本文属于项目阶段，不在独立安装阶段执行。

# Flink 外部对接

> **一句话结论**：Doris 的 Paimon Catalog 只读，写湖交给 Flink。Flink 侧加 connector jar、建 Paimon Catalog、提交 INSERT 作业。Doris 侧建只读 Catalog 回查对账。

> **本文解决什么**：把 Doris ADS 结果表写进 MinIO 上的 Paimon 湖表，再让 Doris 回查，形成湖仓闭环。
>
> **适用谁**：已完成安装教程、需要跑通写湖链路的用户。
>
> **读完能做什么**：挂齐 jar、建 Catalog、提交写回作业、三层验证、处理参数名与版本不匹配问题。

> **核对时点**：2026-11-17。本机 Doris FE 内置 Paimon 为 1.3.1。MinIO 上的 bucket 为 lakehouse。warehouse 路径固定 s3://lakehouse/paimon。
>
> **待复核项**：Doris 内置 Paimon 版本、Flink 侧 paimon-flink 版本、Paimon 表格式版本三者的兼容矩阵。写湖前按官方矩阵复核，不凭文件名判断。

## 二、jar 规划

> **为什么全部挂载**：SQL Client 与 TaskManager 在同一个容器。两者共用 /opt/flink/lib。jar 从宿主机挂载，容器重建后依赖不丢。直接复制到容器的 jar 会在重建时消失。

| 文件名 | 作用 |
| --- | --- |
| paimon-flink-1.20-1.3.1.jar | Flink 读写 Paimon 表 |
| flink-doris-connector-1.20-25.1.0.jar | Flink 读 Doris 表 |
| flink-s3-fs-hadoop-1.20.5.jar | 让 s3:// 路径被识别 |
| paimon-s3-1.3.1.jar | 注册 Paimon FileIO 并读取 S3 凭据 |
| hadoop-hdfs-client-3.3.4.jar | 补 HdfsConfiguration |
| hadoop-mapreduce-client-core-3.3.4.jar | 补 Parquet 统计提取的 FileInputFormat |
| flink-sql-connector-mysql-cdc-3.6.0-1.20.jar | MySQL CDC 源表 |
| mysql-connector-j-8.0.33.jar | MySQL JDBC 驱动 |
| flink-connector-jdbc-3.4.0-1.20.jar | JDBC 连接器工厂 |
| flink-sql-connector-kafka-3.4.0-1.20.jar | Kafka 源表与结果表 |
| hudi-flink1.20-bundle-1.2.1.jar | Flink 读写 Hudi 表 |
| iceberg-flink-runtime-1.20-1.9.2.jar | Flink 读写 Iceberg 表 |

> **版本收敛**：jars/ 下另有 paimon-flink-1.20-2.0.0.jar，是历史命名。实际使用的 1.3.1 文件名来自 README 的版本收敛登记。以与 Doris FE 内置版本一致的 1.3.1 为准。旧文件归档在 jars/archive/。

### 2.1 挂载 jar

独立安装阶段已把 jars 目录整体挂到 /opt/flink/custom-jars。启动时脚本把其中 jar 软链进 /opt/flink/lib。本节列出实际生效的十二个 jar。安装命令见安装教程第三章。

```bash
docker exec flink ls -l /opt/flink/custom-jars/*.jar
```

预期输出：十二个 jar 全部显示，每个大小非 0。历史版本 paimon 2.0.0 虽在目录中，但启动脚本显式跳过，不进入 lib。

> **为什么软链不直挂**：Flink 从 /opt/flink/lib 加载所有 jar。整目录直挂会覆盖镜像自带的 flink-dist 等核心 jar。软链只追加外部依赖，保留内置 jar。

> **单文件挂载前提**：宿主机 jar 必须已存在且是文件。文件缺失时 Docker 会创建同名目录挂进去，Flink 启动报类加载异常。执行前先 ls -l 核对。

### 2.2 验证 jar 已加载

```bash
docker exec flink ls -l /opt/flink/lib/*.jar
docker exec flink ls -l /opt/flink/sql/*.sql
```

预期输出：lib 下 25 个 jar，sql 下 2 个文件。全部大小非 0。

## 三、建 Paimon Catalog

> **前提**：jar 已挂载，容器已重启，checkpoint 配置保留。

sql/01_paimon_catalog.sql 已挂载到容器 /opt/flink/sql。本次用 stdin 喂进 SQL Client，也可用 -f 读取挂载副本。

```bash
printf "SET 'execution.checkpointing.interval' = '10s';
CREATE CATALOG paimon_lake WITH (
  'type' = 'paimon',
  'metastore' = 'filesystem',
  'warehouse' = 's3://lakehouse/paimon',
  's3.endpoint' = 'http://minio:9000',
  's3.access-key' = '<MINIO_AK>',
  's3.secret-key' = '<MINIO_SK>',
  's3.path.style.access' = 'true'
);
SHOW CATALOGS;
EXIT;
" | docker exec -i flink /opt/flink/bin/sql-client.sh embedded
```

尖括号占位符在代码块内保持原样。实际执行时把 &lt;MINIO_AK&gt; 与 &lt;MINIO_SK&gt; 换成真实凭据，或从参数文件在内存中替换。

预期输出：SHOW CATALOGS 列出 paimon_lake 与 default_catalog。

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| type | paimon | 固定 |
| metastore | filesystem | 元数据落在 warehouse 目录，不用 Hive Metastore |
| warehouse | s3://lakehouse/paimon | 必须与 Doris 侧完全一致 |
| s3.endpoint | http://minio:9000 | 容器内地址，不能写 localhost |
| s3.access-key | 占位符 | Flink 侧用连字符 |
| s3.secret-key | 占位符 | Flink 侧用连字符 |
| s3.path.style.access | true | MinIO 需要路径风格访问 |

> **改参数要重建 Catalog**：CREATE CATALOG IF NOT EXISTS 不会更新已有 Catalog。改配置前先 DROP CATALOG paimon_lake，再重新 CREATE。

## 四、提交写回作业

本目录 sql/02_ads_to_paimon.sql 是脚本副本。链路是 Doris ADS 表 → flink-doris-connector → Paimon Connector → MinIO。

```bash
printf "SET 'execution.checkpointing.interval' = '10s';
SET 'execution.checkpointing.mode' = 'EXACTLY_ONCE';
SET 'parallelism.default' = '2';
CREATE TABLE doris_ads_purchase (
  purchase_date DATE,
  daily_purchase_events BIGINT
) WITH (
  'connector' = 'doris',
  'fenodes' = 'doris-fe:8030',
  'table.identifier' = 'game_db.ADS_MV_USER_PURCHASE_TRENDS',
  'username' = '<FE_USER>',
  'password' = '<FE_PWD>'
);
INSERT INTO paimon_lake.game_db.ADS_USER_PURCHASE_TRENDS
SELECT purchase_date, daily_purchase_events FROM doris_ads_purchase;
EXIT;
" | docker exec -i flink /opt/flink/bin/sql-client.sh embedded
```

> **两个易错地址**：fenodes 用 doris-fe:8030，这是 FE 的 HTTP 端口，不是 MySQL 协议的 9030。s3.endpoint 用 http://minio:9000，这是容器内地址。

### 4.1 三层验证

```bash
# ① 作业状态
curl -fsS http://localhost:8081/jobs/overview | head -c 500; echo

# ② 对象存储有文件
docker run --rm --network whd-net --entrypoint /bin/sh minio/mc:<MC_TAG> -c '
  mc alias set lake http://minio:9000 "<MINIO_AK>" "<MINIO_SK>" &&
  mc ls --recursive lake/lakehouse/paimon/ | head -30'

# ③ checkpoint 完成
curl -fsS http://localhost:8081/jobs/overview | grep -o 'completed' | head -1
```

| 层 | 通过标准 |
| --- | --- |
| 作业 | 无异常；有界源 FINISHED，无界源 RUNNING |
| 文件 | MinIO 出现 data-*.parquet、manifest、snapshot |
| checkpoint | 至少一个 COMPLETED |

> **有界源会自己结束**：Doris connector 是有界源，作业约数秒就 FINISHED。这不是失败。判据是 checkpoint 完成加 snapshot 存在，不是作业长期 RUNNING。

## 五、Doris 侧只读回查

Flink 写完湖后，在 Doris 里建 Paimon Catalog 做对账。两边参数名不同，这是最易错处。

| 含义 | Flink 侧写法 | Doris 侧写法 |
| --- | --- | --- |
| 类型 | 'type' = 'paimon' | "type" = "paimon" |
| 元数据服务 | 'metastore' = 'filesystem' | "paimon.catalog.type" = "filesystem" |
| warehouse | 'warehouse' = 's3://lakehouse/paimon' | "warehouse" = "s3://lakehouse/paimon" |
| 存储开关 | 无 | "fs.minio.support" = "true" |
| endpoint | 's3.endpoint' = 'http://minio:9000' | "minio.endpoint" 与 "paimon.s3.endpoint" 各一份 |
| 密钥 | 's3.access-key' / 's3.secret-key' | "minio.access_key" / "minio.secret_key" 加 "paimon.s3.access-key" / "paimon.s3.secret-key" |
| path-style | 's3.path.style.access' = 'true' | "minio.use_path_style" = "true" 加 "paimon.s3.path.style.access" = 'true' |

> **Doris 4.x 要写四组参数**：只写 s3.access_key 旧名会报 Could not find a file io implementation for scheme s3。必须同时给存储组与 Paimon SDK 透传组。改参数前先 DROP CATALOG。

## 六、故障速查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| No FileSystem for scheme s3 | 缺 S3 文件系统 jar | 挂 flink-s3-fs-hadoop 与 paimon-s3 |
| Unable to load AWS credentials | 缺 paimon-s3 bundle | 挂 paimon-s3-1.3.1.jar |
| ClassNotFoundException: HdfsConfiguration | 缺 HDFS 客户端 | 挂 hadoop-hdfs-client |
| 作业反复 RESTARTING 只产 data 文件 | 缺 FileInputFormat | 挂 hadoop-mapreduce-client-core |
| 单文件挂载后类加载异常 | jar 在宿主机不存在，Docker 建了同名目录 | ls -l 核对是文件 |
| 整目录挂 lib 后起不来 | 覆盖镜像自带 jar | 只挂单个 jar 文件 |
| 作业在跑湖里没文件 | checkpoint 未开或未触发 | 设 10s 间隔，等一个周期 |
| 作业 FINISHED 被判失败 | 有界源自行结束 | 看 checkpoint 与 snapshot |
| fenodes 连不上 | 写成 9030 | 用 8030 |
| SignatureDoesNotMatch | 参数名连字符与下划线混用 | 按对照表写，endpoint 用容器内地址 |
| Flink 写成功 Doris 查不到表 | warehouse 两边不一致 | 统一 s3://lakehouse/paimon |
| 读不了 Doris 物化视图 | connector 版本限制 | 落一张物理表再读 |

## 七、小结

1. Paimon 不是服务。写湖靠 Flink 的 connector jar，不新增容器。
2. 单容器下 jar 挂一次即可，因为 JM 与 TM 在同一容器的 lib 目录。
3. checkpoint 必须开。Paimon 的 commit 绑定 checkpoint，不开就没有可见文件。
4. 两边 warehouse 必须完全一致，参数名按 Flink 与 Doris 各自规范写。
5. 提交后按作业状态、MinIO 文件、checkpoint 完成三层验证，再去 Doris 回查。

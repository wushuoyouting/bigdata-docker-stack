## 3. 第 2 步：把口径定死

### 3.1 网络与 IP

| 项 | 值 | 谁在用 |
| --- | --- | --- |
| 网络 | whd-net（bridge，172.30.0.0/24，网关 .1），external: true | 所有组件 |
| FE | 172.30.0.8，别名 doris-fe、fe1 | DS / Superset / Flink / 客户端 |
| BE | 172.30.0.9，别名 doris-be | FE 注册链路 |
| 其它常驻组件 | DS .2、MinIO .3，新组件从 .19 起顺延 | 见 /Users/wenhuadong/docker/code-wiki/06-配置基线与例外.md |

> 镜像 entry_point.sh 会从 BE_ADDR 推导 PRIORITY_NETWORKS = 前三段 + ".0/24"。**网络子网、ipv4_address、两份 *.conf 的 priority_networks 四处必须同口径**——这是镜像约束，不是风格偏好。

### 3.2 五处对齐

| # | 位置 | 值 |
| --- | --- | --- |
| 1 | docker network create --subnet | 172.30.0.0/24 |
| 2 | 编排 FE_SERVERS + FE ipv4_address | fe1:172.30.0.8:9010 / 172.30.0.8 |
| 3 | 编排 BE_ADDR + BE ipv4_address | 172.30.0.9:9050 / 172.30.0.9 |
| 4 | conf/fe.conf、conf/be.conf 的 priority_networks | 172.30.0.0/24 |
| 5 | conf/be.conf 的 heartbeat_service_address | 172.30.0.8（**FE 的 IP**，独立一项） |

### 3.3 地址判据（照表写）

| 谁访问谁 | 写什么 | 反例 |
| --- | --- | --- |
| 本机浏览器 / 客户端 → UI | localhost:&lt;宿主映射端口&gt; | 写容器别名 |
| 同网络容器 → FE 查询口 | doris-fe:9030 | localhost:9030 |
| Flink Doris connector → FE | doris-fe:8030（HTTP fenodes） | 写 9030（MySQL 协议口） |
| FE / BE → MinIO | http://minio:9000 | http://localhost:9000 |
| FE ↔ BE 内部注册 | 静态 IP 172.30.0.8 / 172.30.0.9 | 写容器名（entrypoint 正则不接受） |
| 容器 → 宿主机服务 | host.docker.internal:&lt;宿主端口&gt; | 写 localhost |

### 3.4 端口表

| 服务 | 容器端口 | 宿主端口 | 用途 |
| --- | --- | --- | --- |
| FE | 8030 | 8030 | HTTP / Web UI / fenodes |
| FE | 9030 | 9030 | MySQL 协议查询口 |
| FE | 9010 | 9010 | edit log |
| BE | 8040 | 8040 | BE Web / 状态 |
| BE | 9050 | 9050 | heartbeat |

> 9030 是查询口、8030 是 HTTP 口，fenodes 写 9030 一定连不上。**S3 Load 的下载由 BE 执行**，宿主机 curl localhost:9000 通不能证明导入能成，必须从 BE 容器内验证 MinIO。

## 4. 编排配置

```
/Users/wenhuadong/docker/olap/doris/          # 全局组件目录，不进 git
├── README.md                            # 唯一安装手册（事实源）
├── 安装教程.md                          # 本文
├── docker-compose.whd.yml               # 本次编排（name: doris / external whd-net）
├── docker-compose.yml                   # 旧编排（172.20.80.0/24），停用保留不删
├── conf/
│   ├── fe.conf                          # FE 配置，可写挂载（E-05）
│   ├── be.conf                          # BE 配置，可写挂载（E-05）
│   └── entry_point.sh                   # BE 启动脚本（修复版），:ro 挂载
├── volumes/fe/{doris-meta,log}/         # 本次方案 FE 元数据 / 日志
├── volumes/be/{storage,log}/            # 本次方案 BE 数据 / 日志
├── fe/, be/, data/                      # 历史数据（约 1.7G + 更早一份），保留不删
```

| 参数 | 作用 | 为什么这么设 |
| --- | --- | --- |
| name: doris | Compose 项目名（容器 label） | 公共组件按组件名命名；ps / down / logs 按它识别容器 |
| networks.whd-net.external: true | 引用外部已创建网络 | down 不会删掉它 |
| ipv4_address | 固定 FE / BE IP | 满足 FE_SERVERS / BE_ADDR 格式，让 priority_networks 可预测 |
| aliases: [doris-fe, fe1] | 同网络别名 | fe1 供 FE_SERVERS 用；业务侧一律写 doris-fe |
| FE_ID: "1" | 单 FE 编号 | 学习环境不做 FE 高可用 |
| entrypoint 显式写死 | init_fe.sh / 挂进去的 entry_point.sh | 避免镜像 tag 更新后默认入口变化 |
| conf/fe.conf、conf/be.conf **可写挂载** | 配置 | 镜像 init 脚本会**改写**这两份文件；:ro 会让 FE 报 Read-only file system 并反复重启（准则例外 E-05）。entry_point.sh 仍 :ro |
| FE healthcheck 探 9030 | BE 的启动闸门 | depends_on: service_healthy 保证 FE 真可用后 BE 才起 |
| restart: unless-stopped | 异常退出自动拉起 | 手动 compose stop 后不会自己复活 |

> 可写挂载的副作用：init 脚本会在 fe.conf / be.conf 末尾追加一行同值 priority_networks，**属正常**，重启后复核内容未被改坏即可，不要反复手删。编排里的卷路径是相对 doris/ 的（-f 指向该目录下的文件），执行时不要换基准目录。

## 5. 清旧建网启动

### 5.1 只删两个容器

```bash
docker rm -f doris-fe doris-be
```

| 目录 | 处理 |
| --- | --- |
| fe/doris-meta、be/storage（旧 bind mount） | 保留；docker rm -f 只删容器层 |
| fe/、be/、data/ | 保留，**不要覆盖、不要 rm -rf** |
| docker-compose.yml（旧编排） | 停用、保留 |
| volumes/{fe,be}/ | 本次方案专用，使用全新目录 |
| datapivot-doris-* | 不删、不改、不启动 |

> **不复用旧 doris-meta**：里面记着 172.20.80.3 这个失效 BE，复用会让新 BE 注册冲突。确需保留旧库见 组件手册末尾。

### 5.2 建网与启动

```bash
F=/Users/wenhuadong/docker/olap/doris/docker-compose.whd.yml
cd /Users/wenhuadong/docker/olap/doris

# 1) 共享网络只建一次；已存在就直接用，不要删了重建
docker network inspect whd-net >/dev/null 2>&1 || \
  docker network create --driver bridge \
    --subnet 172.30.0.0/24 --gateway 172.30.0.1 whd-net
docker network inspect whd-net --format '{{range .IPAM.Config}}{{.Subnet}}{{end}}'
#   判据：172.30.0.0/24

# 2) 预建数据目录（避免 Docker 以 root 创建后权限不对）
mkdir -p volumes/fe/doris-meta volumes/fe/log \
         volumes/be/storage volumes/be/log

# 3) 启动
docker compose -f "$F" up -d

# 4) 看状态与日志
docker compose -f "$F" ps
docker compose -f "$F" logs --tail 50 fe
docker compose -f "$F" logs --tail 50 be
```

**等待点**：FE 首次初始化元数据约 1–2 分钟，healthy 之后 BE 才启动。别一 up -d 就去连 9030。

```bash
# 循环等 FE 查询口就绪（最多 3 分钟；FE 容器内 127.0.0.1 是免密管理通道）
for i in $(seq 1 36); do
  if docker exec doris-fe /usr/bin/mysql -uroot -P9030 -h127.0.0.1 \
       -e 'SELECT 1' >/dev/null 2>&1; then
    echo "FE 查询口就绪"; break
  fi
  echo "第 ${i} 次：FE 还没就绪，等 5s"; sleep 5
done
```

| 步骤 | 判据 | 不通过怎么办 |
| --- | --- | --- |
| 1 建网络 | 子网 172.30.0.0/24 | 网段冲突则换网段并同步改五处网段配置 |
| 3 up -d | 两个容器都创建 | docker compose -f "$F" logs fe |
| 4 等 FE | ps 里 FE healthy | 查 priority_networks、Read-only file system、Invalid FE_SERVERS format |
| BE 启动 | ps 里 BE running | 确认 FE 已 healthy；BE 日志的 Health check timed out 只是告警，不是故障 |

## 6. 首次初始化

> 管理操作一律走 **FE 容器内 127.0.0.1 免密通道**：docker exec doris-fe /usr/bin/mysql -uroot -P9030 -h127.0.0.1 -e '...'。

### 6.1 确认 BE 已注册

```bash
docker exec doris-fe /usr/bin/mysql -uroot -P9030 -h127.0.0.1 -e 'SHOW BACKENDS\G'
# 判据：一行，Host=172.30.0.9，Alive=true，LastStartTime 有值

# 仅当列表为空或 Alive=false 时才手工注册
docker exec doris-fe /usr/bin/mysql -uroot -P9030 -h127.0.0.1 \
  -e 'ALTER SYSTEM ADD BACKEND "172.30.0.9:9050";'
```

| 字段 | 通过标准 |
| --- | --- |
| Host | 172.30.0.9 |
| Alive | true（false 时导入一定失败） |
| 行数 | 1（多出旧 IP = 复用了旧元数据） |

> 镜像 init_be.sh 会自动注册，本机实测已成功；手工 ADD BACKEND 是兜底路径，不是必做步骤。

### 6.2 建业务库

```bash
docker exec doris-fe /usr/bin/mysql -uroot -P9030 -h127.0.0.1 \
  -e 'CREATE DATABASE IF NOT EXISTS game_db;'
docker exec doris-fe /usr/bin/mysql -uroot -P9030 -h127.0.0.1 \
  -e 'SHOW DATABASES LIKE "game_db";'
```

### 6.3 三种鉴权差异

```bash
docker exec doris-fe /usr/bin/mysql -uroot -P9030 -h127.0.0.1 \
  -e "select current_user(), version();"
docker exec doris-fe /usr/bin/mysql -uroot -P9030 -h127.0.0.1 \
  -e 'SHOW ALL GRANTS;'
docker exec doris-fe /usr/bin/mysql -uroot -P9030 -h127.0.0.1 \
  -e "select user, host from mysql.user;"
```

| 来源 | 服务端看到的客户端 | 无口令 | 结论 |
| --- | --- | --- | --- |
| FE 容器内 127.0.0.1 | 127.0.0.1 | **可连**（连错口令也能进） | 管理操作走这条 |
| 同网络容器 doris-fe:9030 | 172.30.0.x | Access denied | **必须带口令** |
| 宿主机 localhost:9030 | 192.168.65.1 | Access denied | **必须带口令** |

| 账号（实测） | Comment / 角色 | 全局权限 | 能力边界 | 口令状态 |
| --- | --- | --- | --- | --- |
| 'root'@'%' | ROOT / operator | Node_priv, Admin_priv | 加删 BE、建库建表、LOAD、建 Catalog | 重建后为空，按 6.4 重设 |
| 'admin'@'%' | ADMIN / admin | Admin_priv（无 Node_priv） | 库表与数据管理，不能管 FE/BE 节点 | **空，且可远程免密登录** |

> 内置默认值：二者对 internal.information_schema / internal.mysql 有 Select_priv，normal 工作组有 Usage_priv。重建后两账号均 Password=No，跨容器可不带口令连接。这是待收口项：按 6.4 设 root 口令、按 6.5 设 admin 口令，再按 6.7 回填三处数据源。

> **「容器内 SELECT 1 成功」不能证明 DS / Superset / 本机客户端能连上**。这是本环境最常见的一处误判，所以必须从三个视角验证。

### 6.4 root 口令

```bash
set -a
. /Users/wenhuadong/docker/olap/doris/.env
set +a
chmod 600 /Users/wenhuadong/docker/olap/doris/.env

# 1) 在 FE 容器内 loopback 通道设置；口令取自 .env 的 FE_PWD
docker exec doris-fe /usr/bin/mysql -uroot -P9030 -h127.0.0.1 \
  -e "SET PASSWORD FOR 'root'@'%' = PASSWORD('$FE_PWD');"

# 2) 立刻从三个来源复测，一个都不能漏
docker exec doris-fe /usr/bin/mysql -uroot -P9030 -h127.0.0.1 \
  -p"$FE_PWD" -e 'select current_user()'
docker exec doris-be /usr/bin/mysql -uroot -P9030 -hdoris-fe \
  -p"$FE_PWD" -e 'select 1'
mysql -h127.0.0.1 -P9030 -uroot -p"$FE_PWD" -e 'select 1'

# 3) 复核权限没被改坏
docker exec doris-fe /usr/bin/mysql -uroot -P9030 -h127.0.0.1 \
  -p"$FE_PWD" -e "SHOW GRANTS FOR 'root'@'%';"
```

| 检查项 | 通过标准 |
| --- | --- |
| 三个来源 | 全部成功、无 Access denied |
| SHOW GRANTS | 仍含 Node_priv, Admin_priv |
| 语法差异 | 实测 4.1.1-rc01；若 SET PASSWORD ... = PASSWORD(...) 报错，改试 SET PASSWORD = PASSWORD('&lt;FE_PWD&gt;') 或 ALTER USER 'root'@'%' IDENTIFIED BY '&lt;FE_PWD&gt;' |

> 改口令会影响 DS 数据源、Superset 数据源、回填表与 sql/ 连接串。**当前 DS / Superset 还没建数据源，正是统一口令的最佳时机**；等配好再改就要四处一起回填。口令不要含 @ / : / # / /。

### 6.5 最小权限账号

```bash
# 本机 .env 存真实口令；本节可重复执行，重复执行时口令按 .env 刷新
set -a
. /Users/wenhuadong/docker/olap/doris/.env
set +a
chmod 600 /Users/wenhuadong/docker/olap/doris/.env

# 管理操作走 FE 容器内 loopback 免密通道，不带 -p
# heredoc 不加引号，让 shell 展开 .env 变量；口令不要含 $ ` \ " 与单引号
docker exec -i doris-fe /usr/bin/mysql -uroot -P9030 -h127.0.0.1 <<SQL
DROP USER IF EXISTS 'doris_ds_etl'@'%';
CREATE USER 'doris_ds_etl'@'%' IDENTIFIED BY '$DORIS_ETL_PWD';
GRANT CREATE_PRIV, DROP_PRIV, ALTER_PRIV, LOAD_PRIV, SELECT_PRIV ON game_db.* TO 'doris_ds_etl'@'%';

DROP USER IF EXISTS 'doris_bi_read'@'%';
CREATE USER 'doris_bi_read'@'%' IDENTIFIED BY '$DORIS_BI_PWD';
GRANT SELECT_PRIV ON game_db.* TO 'doris_bi_read'@'%';

SET PASSWORD FOR 'admin'@'%' = PASSWORD('$FE_ADMIN_PWD');

SHOW GRANTS FOR 'doris_ds_etl'@'%';
SHOW GRANTS FOR 'doris_bi_read'@'%';
SQL
```

| 账号 | 用途 |
| --- | --- |
| doris_ds_etl | 跑建表、LOAD、DWD/ADS 建模 |
| doris_bi_read | Superset 看板、对账查询 |
| root | 节点管理、CREATE CATALOG（Paimon 只读回查需要更高权限） |

| 权限 | 干什么用 | 谁需要 |
| --- | --- | --- |
| Node_priv | ALTER SYSTEM ADD/DROP BACKEND 等节点管理 | 只有 root / 运维 |
| Admin_priv | 建库建表、LOAD、建 Catalog、用户管理 | root / admin |
| CREATE_PRIV / DROP_PRIV / ALTER_PRIV | 库表 DDL | ETL 账号 |
| LOAD_PRIV | LOAD LABEL ... 导入（含 S3 Load） | ETL 账号 |
| SELECT_PRIV | 查询、物化视图刷新结果读取 | BI / 对账账号 |

> 重跑说明：先 DROP USER IF EXISTS 再 CREATE，所以不会报 already exist。重跑会重置这两个账号的口令与授权，须同步回填 DS / Superset 数据源。

> 边界：CREATE CATALOG 通常需要更高权限，用 root 或单独授权，不要把 root 口令发给所有组件。Doris 4.1.1 权限项名与 GRANT 写法跟 MySQL 8 不完全一致，先跑 SHOW GRANTS FOR 复核。

## 9. 停止、重启、重来

```bash
F=/Users/wenhuadong/docker/olap/doris/docker-compose.whd.yml

docker compose -f "$F" stop             # 数据、网络都保留
docker compose -f "$F" start
docker compose -f "$F" logs -f --tail 100

# 完全重来：删容器但保留 volumes/ 与 whd-net（不要加 -v）
docker compose -f "$F" down
docker compose -f "$F" up -d

# 连数据一起清空（谨慎：会丢 game_db，需重跑第 6 节）
docker compose -f "$F" down
rm -rf /Users/wenhuadong/docker/olap/doris/volumes/fe/doris-meta/* \
       /Users/wenhuadong/docker/olap/doris/volumes/be/storage/*
mkdir -p /Users/wenhuadong/docker/olap/doris/volumes/fe/doris-meta \
         /Users/wenhuadong/docker/olap/doris/volumes/be/storage
docker compose -f "$F" up -d
```

**改 Compose 项目名的正确顺序**（whd-lakehouse → doris 已于 2026-11-10 执行过）：

```bash
# 1) 必须在文件还是旧 name 时执行，才能找到旧标签的容器（不加 -v）
docker compose -f "$F" down
# 2) 改文件里的 name: 为组件名
# 3) 重建容器 label
docker compose -f "$F" up -d
# 4) 复核
docker inspect doris-fe --format '{{index .Config.Labels "com.docker.compose.project"}}'
```

| 动作 | 影响范围 | 数据安全 |
| --- | --- | --- |
| stop / start | 只有容器进程 | 全保留 |
| down | 删容器层 | bind mount 数据在 volumes/，保留；FE 元数据、BE 注册、game_db 都在 |
| down -v | 删具名卷 | **禁止**（准则 4.3） |
| rm -rf volumes/... | 元数据 / 数据 | 只有明确要重置时才做，之后要重跑初始化 |

> down **不会删除 whd-net**（external: true）。改了端口映射 / 静态 IP / 项目名，都要按全局基线同步 组件手册与全局 README.md。

## 10. 故障速查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 日志 priority_networks does not include the current IP address | conf 网段与 whd-net 不一致 | 五处网段统一 |
| FE 反复重启、Read-only file system | fe.conf / be.conf 挂了 :ro | 去掉这两份的 :ro（E-05），entry_point.sh 仍 :ro |
| Invalid FE_SERVERS format | 第二段写了容器名 | 必须是 fe1:172.30.0.8:9010 |
| network whd-net not found | 忘了先建网络 | 先建网络；external: true 不会自动建 |
| pool overlaps with other one / 端口占用 | datapivot-doris-* 占 8030/9030 或网段冲突 | 保持另一套停止；换网段要同步五处 |
| SHOW BACKENDS 为空 / Alive=false | 自动注册失败 | 手工 ADD BACKEND |
| BE 日志 Health check timed out ... continuing | 修复版 entry_point.sh 只告警不退出 | 不是故障，以 SHOW BACKENDS 的 Alive 为准 |
| docker rm 后数据没了 | 误以为数据在容器层 | 数据在 volumes/，只有 rm -rf 才真丢 |
| 宿主 / 跨容器无口令报 Access denied | 误把 loopback 免密当全局免密 | 带 -p'&lt;FE_PWD&gt;'，按 6.3 来源判据区分 |
| admin@% 免密可远程登录 | 内置账号未收口 + 9030 映射 0.0.0.0 | 6.5 设口令、6.6 收紧映射 |
| SET PASSWORD ... = PASSWORD(...) 语法错 | 4.1.1 与 3.0.x 基线差异 | 改试备用写法，以实测版本官方文档为准 |
| 口令含 @ / : 导致 DS 建数据源失败 | JDBC URL 未转义 | 先在 mysql 客户端验证，再回填 |
| fenodes 连不上 | 写成 doris-fe:9030 | 用 8030 |
| S3 Load endpoint 不可达 | 只在宿主机测了 MinIO | 下载由 **BE** 执行，从 BE 容器验证 http://minio:9000 |
| conf/*.conf 末尾多一行 priority_networks | init 脚本每次启动追加 | 属正常，不要反复手删 |
| 改 name: 后 compose ps 看不到容器 | 运行中容器 label 仍是旧名 | down（旧 name）→ 改文件 → up -d |
| FE healthy 但 BE 一直不启动 | depends_on: service_healthy 在等 FE | 看 docker compose logs fe；首次元数据初始化约 1–2 分钟 |
| 复用旧 doris-meta 后 BE 注册冲突 | 旧元数据记着 172.20.80.3 | 用全新 volumes/；旧库保留属不推荐的历史例外 |
| 改完 root 口令后 DS / Superset 全报鉴权错 | 只改库没回填数据源 | 四处一起回填，再按 6.7 统一冒烟 |
| DS 连不上 FE | DS 未接 whd-net，或 URL 写了 localhost | DS 由编排直接落网，URL 用 doris-fe:9030，不补接网络 |
| 改 IP 后 FE 一直 unhealthy，日志 feType:UNKNOWN | FE 复用了记着旧 IP 的 doris-meta | 停容器后清空 volumes/fe/doris-meta/*，以新 IP 重新格式化 |
| BE 注册后 Alive=false，FE 日志报 invalid cluster id | BE 的 volumes/be/storage/cluster_id 与 FE 不一致 | 同步清空 volumes/be/storage/* 后重启；旧 tablet 数据不可保留 |

**看日志三个入口**：docker compose -f "$F" logs --tail 100 fe / ... be；volumes/fe/log/fe.log（FE 元数据）；volumes/be/log/be.INFO（BE 注册与心跳）。

回填到 /Users/wenhuadong/prj/asr-resume/prj/湖仓一体/安装手册（**真实口令不要写进版本库**）：

| 占位符 | 本教程默认值 |
| --- | --- |
| &lt;FE_QUERY_HOST&gt; / &lt;FE_QUERY_PORT&gt; | doris-fe / 9030 |
| &lt;FE_HTTP_PORT&gt; | 8030 |
| &lt;FE_PWD&gt; | 统一设置（当前已有非空口令） |
| &lt;ETL_PWD&gt; / &lt;BI_PWD&gt; / &lt;ADMIN_PWD&gt; | 自设 |
| &lt;MINIO_ENDPOINT_IN&gt; | http://minio:9000 |
| 共享网络 / 子网 | whd-net / 172.30.0.0/24 |
| FE / BE 静态 IP | 172.30.0.8 / 172.30.0.9 |
| Compose 项目名 | doris |

1. **固定 IP 是硬约束**：entrypoint 只认点分十进制 IP，whd-net 必须指定子网、FE/BE 必须有 ipv4_address，五处必须对齐。
2. **whd-net 只建一次、全局共用**：compose 用 external: true 引用；DS 由自己的编排直接落在网上；待装组件 docker run 一律带网络参数。
3. **删除范围严格限定**：只删 doris-fe / doris-be；datapivot-doris-* 与历史数据目录保留不删。
4. **启动顺序不能跳**：建网络 → 删旧容器 → up -d → 等 FE healthy → 确认 BE 已注册 → 建库 → 配账号 → 分层验证 → 接入 DS。
5. **账号是最容易误判的一环**：只有 FE 容器内 127.0.0.1 免密，跨容器 / 宿主机必须带口令；admin@% 当前免密且带 Admin_priv，应尽快收口，改口令后四处回填不能漏。
6. **验收要看数据落盘**：Alive=true 只说明心跳正常，INSERT + SELECT count(*) 才证明 BE 可用。

# Paimon 基本使用

> **一句话结论**：本文主体是 Flink SQL，只能在 Flink SQL Client 执行。用 DataGrip 连 StarRocks 时不能直接照抄，须换 StarRocks 语法。

> **本文解决什么**：给出本机 Flink + MinIO 的建表、读写、增量与维护步骤，并标明每段 SQL 用哪个客户端。
>
> **适用谁**：已有 flink:1.20 与 MinIO 的人，以及用 DataGrip 查询湖上数据的人。
>
> **读完能做什么**：分清各段 SQL 的方言，在对的客户端执行，独立排查语法与作业错误。

## 零、方言与客户端对照

本文混用五种方言。执行前先确认客户端，抄错引擎会报 ERROR 1064。

| 章节 | 方言 | 执行客户端 |
| --- | --- | --- |
| 三至八 | Flink SQL | Flink SQL Client |
| 6.4.1 前置检查 | MySQL SQL | MySQL 客户端 |
| 4.2 提交段 | Shell 加 Python | 本机终端 |
| 9.3.2 提交段 | Shell 加 Python | 本机终端 |
| 9.5 | Doris SQL | Doris 查询端口 9030 |
| 十、十一 | StarRocks SQL | DataGrip 或 MySQL 客户端 |

两个高频差异如下。

| 动作 | Flink SQL | StarRocks SQL |
| --- | --- | --- |
| 切换 catalog | USE CATALOG paimon_lake; | SET CATALOG paimon_lake; |
| 建表语法 | CREATE TABLE ... WITH (...) | CREATE TABLE ... PROPERTIES (...) |

注意：三至八章默认 Flink SQL。把它贴进 DataGrip 的 StarRocks 会话，必报语法错误。

## 二、jar 清单

JM 与 TM 各挂六份。缺任一都会在建表或提交时报错。

| jar | 作用 |
| --- | --- |
| paimon-flink.jar | Flink 侧读写 Paimon 表 |
| flink-s3-fs-hadoop.jar | 让 s3:// 被 Hadoop FileSystem 识别 |
| paimon-s3.jar | 识别 s3 凭据并注册 s3 FileIO |
| hadoop-hdfs-client.jar | 补 HdfsConfiguration 类 |
| hadoop-mapreduce-client-core.jar | 补 Parquet 统计提取所需 FileInputFormat |
| flink-doris-connector.jar | Flink 侧读 Doris 表，回查链路用 |

注意：目录里 jars/paimon-flink-1.20-2.0.0.jar 是历史命名，实际内容是 1.3.1。

## 三、开 checkpoint

方言：Flink SQL。客户端：Flink SQL Client。

Paimon 的 commit 绑定 checkpoint。建 catalog 前先设这两项。

```
SET 'execution.checkpointing.interval' = '10s';
SET 'execution.checkpointing.mode' = 'EXACTLY_ONCE';
```

提示：不开 checkpoint，作业在跑但湖里没有数据文件。

## 四、建 catalog 与库

方言：4.1 为 Flink SQL，4.2 为 Shell 加 Python。分别用 SQL Client 与本机终端执行。

### 4.1 建 catalog

```
CREATE CATALOG paimon_lake WITH (
  'type' = 'paimon',
  'metastore' = 'filesystem',
  'warehouse' = 's3://lakehouse/paimon',
  's3.endpoint' = 'http://minio:9000',
  's3.access-key' = '<MINIO_AK>',
  's3.secret-key' = '<MINIO_SK>',
  's3.path.style.access' = 'true'
);

USE CATALOG paimon_lake;
CREATE DATABASE IF NOT EXISTS game_db;
```

预期：SHOW CATALOGS 返回 paimon_lake。

注意：参数名用连字符，如 s3.access-key。Doris 侧用下划线，两套不通用。

### 4.2 凭据不落盘

生产提交用 stdin 喂 SQL，占位符在内存替换。

```
python3 -c "
import os
s = open('01_paimon_catalog.sql').read()
s = s.replace('<MINIO_AK>', os.environ['MINIO_AK'])
s = s.replace('<MINIO_SK>', os.environ['MINIO_SK'])
print(s)
" | docker exec -i flink-jobmanager /opt/flink/bin/sql-client.sh embedded
```

注意：SQL Client 会回显原文，查看输出前要脱敏。

## 五、建表

方言：Flink SQL。客户端：Flink SQL Client。

这里的 WITH (...) 是 Flink 建表语法。不能在 StarRocks 或 Doris 里执行。

### 5.1 主键表

```
CREATE TABLE IF NOT EXISTS game_db.t_order (
  order_id BIGINT,
  user_id BIGINT,
  status STRING,
  amount DECIMAL(18,2),
  updated_at TIMESTAMP,
  PRIMARY KEY (order_id) NOT ENFORCED
) WITH (
  'bucket' = '2',
  'changelog-producer' = 'input'
);
```

关键属性说明。

| 属性 | 作用 |
| --- | --- |
| bucket | 分桶数，决定并行度与文件粒度 |
| changelog-producer | 产出 changelog 的方式，input 表示直接透传输入变更 |

### 5.2 append-only 表

```
CREATE TABLE IF NOT EXISTS game_db.t_event (
  event_id BIGINT,
  event_name STRING,
  event_time TIMESTAMP
) WITH (
  'bucket' = '-1'
);
```

bucket 设 -1 表示不分区，只追加。

## 六、写入与查询

方言：6.1 至 6.4.3 为 Flink SQL。6.4.1 的前置检查用 MySQL 客户端。

### 6.1 批式写入

```
INSERT INTO game_db.t_order VALUES
  (1, 1001, 'paid',   99.00, TIMESTAMP'2026-11-17 09:00:00'),
  (2, 1002, 'created', 20.00, TIMESTAMP'2026-11-17 09:10:00');
```

### 6.2 主键更新

同主键再写一次，覆盖旧值。

```
INSERT INTO game_db.t_order VALUES
  (1, 1001, 'shipped', 99.00, TIMESTAMP'2026-11-17 10:00:00');
```

预期：SELECT 中 order_id 为 1 的行 status 变成 shipped，总数仍为 2。

### 6.3 查询

```
SELECT * FROM game_db.t_order;
```

### 6.4 流式写入

一条 INSERT 语句不能单独完成 CDC。它需要三样前置：MySQL 源表、CDC 连接器 jar、Flink 中的 CDC 源表声明。

INSERT 只负责「从源表读到目标表」这一段。变更捕获由 CDC 源表完成。

完整链路如下。

```
MySQL binlog
  └─ flink-sql-connector-mysql-cdc 读变更
       └─ Flink 源表 mysql_cdc_source.orders
            └─ INSERT INTO game_db.t_order
                 └─ Paimon 主键表按主键 upsert
```

#### 6.4.1 前置条件

① MySQL 开启 binlog，格式为 ROW。

```
SHOW VARIABLES LIKE 'log_bin';
SHOW VARIABLES LIKE 'binlog_format';
```

预期：log_bin 为 ON，binlog_format 为 ROW。

② 放 CDC 连接器 jar 到 JM 与 TM 的 lib 目录。

```
flink-sql-connector-mysql-cdc-3.3.0.jar
```

注意：jar 大版本要与 Flink 对齐。放完必须 stop/start JM 与 TM，重建容器后要重新放。

③ MySQL 建测试源表。

```
CREATE DATABASE IF NOT EXISTS shop;
CREATE TABLE shop.orders (
  order_id BIGINT PRIMARY KEY,
  user_id BIGINT,
  status VARCHAR(32),
  amount DECIMAL(18,2),
  updated_at TIMESTAMP
);
```

#### 6.4.2 建 CDC 源表

```
CREATE CATALOG mysql_cdc_source WITH (
  'type' = 'generic'
);

USE CATALOG mysql_cdc_source;

CREATE DATABASE IF NOT EXISTS shop;

CREATE TABLE shop.orders (
  order_id BIGINT,
  user_id BIGINT,
  status STRING,
  amount DECIMAL(18,2),
  updated_at TIMESTAMP,
  PRIMARY KEY (order_id) NOT ENFORCED
) WITH (
  'connector' = 'mysql-cdc',
  'hostname' = '<MYSQL_HOST>',
  'port' = '3306',
  'username' = '<MYSQL_USER>',
  'password' = '<MYSQL_PWD>',
  'database-name' = 'shop',
  'table-name' = 'orders',
  'server-time-zone' = 'Asia/Shanghai'
);
```

关键参数说明。

| 参数 | 作用 |
| --- | --- |
| connector | 固定为 mysql-cdc |
| database-name | MySQL 库名 |
| table-name | MySQL 表名 |
| server-time-zone | 与 MySQL 时区一致，避免时间偏移 |

预期：SHOW TABLES 返回 orders。

#### 6.4.3 提交写入作业

```
USE CATALOG paimon_lake;

INSERT INTO game_db.t_order
SELECT order_id, user_id, status, amount, updated_at
FROM mysql_cdc_source.shop.orders;
```

预期：Flink UI 出现一个 RUNNING 作业，不会自行结束。

#### 6.4.4 验证命令与输出

① 查作业状态。

```
curl -fsS http://localhost:8081/jobs/overview | head -c 500; echo
```

预期输出：返回 JSON，含 jobs 数组，state 为 RUNNING。

② 查 Paimon 表初始数据。

```
SELECT * FROM game_db.t_order;
```

预期输出：MySQL 源表已有的行。

③ 在 MySQL 侧改一行。

```
UPDATE shop.orders SET status = 'paid' WHERE order_id = 1;
```

预期：MySQL 影响 1 行。

④ 再查 Paimon 表。

```
SELECT * FROM game_db.t_order WHERE order_id = 1;
```

预期输出：status 变为 paid，行数不增加。这就是主键 upsert。

⑤ 确认 checkpoint 在推进。

```
curl -fsS http://localhost:8081/jobs/overview | python3 -c \
  "import json,sys; d=json.load(sys.stdin); print([j.get('state') for j in d.get('jobs',[])])"
```

预期输出：包含 RUNNING。

注意：流作业靠 checkpoint 周期提交，checkpoint 完成才有新快照。验证完可在 Flink UI 点 Cancel 停止作业。

## 九、使用案例

方言：9.3 主体为 Flink SQL，9.5 为 Doris SQL。分别用 Flink SQL Client 与 Doris 客户端执行。

### 9.1 场景背景

这是本机已实测的「湖到仓到湖」闭环。Doris 的 ADS 结果表由 Flink 读出，写进 MinIO 上的 Paimon，再由 Doris 只读回查对账。

### 9.2 数据流

```
Doris FE (doris-fe:8030)
  └─ flink-doris-connector 读 ADS 结果表
       └─ INSERT INTO paimon_lake.game_db.ads_*
            └─ Paimon Connector 写 s3://lakehouse/paimon/
                 └─ Doris 只读 Catalog 回查对账
```

### 9.3 落地步骤

下面全部语句直接写出，不封装进 .sql 文件。执行时用 stdin 整批喂给 SQL Client。

凭据从环境变量读，在内存中替换，不落盘。

#### 9.3.1 确认 jar

```
docker exec flink-jobmanager ls -l /opt/flink/lib/
docker exec flink-taskmanager ls -l /opt/flink/lib/
```

预期：两边都列出 paimon-flink.jar 等六个 jar，大小非 0。

#### 9.3.2 提交整批 SQL

把下面内容存成 shell 变量或 here-doc，替换三个占位符后管道给 SQL Client。

```
python3 - <<'PY' | docker exec -i flink-jobmanager /opt/flink/bin/sql-client.sh embedded
import os
sql = """
SET 'execution.checkpointing.interval' = '10s';
SET 'execution.checkpointing.mode' = 'EXACTLY_ONCE';
SET 'parallelism.default' = '2';

CREATE CATALOG paimon_lake WITH (
  'type' = 'paimon',
  'metastore' = 'filesystem',
  'warehouse' = 's3://lakehouse/paimon',
  's3.endpoint' = 'http://minio:9000',
  's3.access-key' = '__MINIO_AK__',
  's3.secret-key' = '__MINIO_SK__',
  's3.path.style.access' = 'true'
);

USE CATALOG paimon_lake;
CREATE DATABASE IF NOT EXISTS game_db;

CREATE TABLE IF NOT EXISTS game_db.ads_USER_PURCHASE_TRENDS (
  purchase_date DATE,
  daily_purchase_events BIGINT,
  PRIMARY KEY (purchase_date) NOT ENFORCED
) WITH (
  'bucket' = '1'
);

CREATE TABLE doris_ads_purchase (
  purchase_date DATE,
  daily_purchase_events BIGINT
) WITH (
  'connector' = 'doris',
  'fenodes' = 'doris-fe:8030',
  'table.identifier' = 'game_db.ads_MV_USER_PURCHASE_TRENDS',
  'username' = '__FE_USER__',
  'password' = '__FE_PWD__'
);

INSERT INTO paimon_lake.game_db.ads_USER_PURCHASE_TRENDS
SELECT purchase_date, daily_purchase_events
FROM doris_ads_purchase;
"""
for k, v in {
    '__MINIO_AK__': os.environ['MINIO_AK'],
    '__MINIO_SK__': os.environ['MINIO_SK'],
    '__FE_USER__': os.environ['FE_USER'],
    '__FE_PWD__': os.environ['FE_PWD'],
}.items():
    sql = sql.replace(k, v)
print(sql)
PY
```

逐段说明。

① 前三行 SET：开 checkpoint 并设并行度。Paimon 提交依赖 checkpoint。

② CREATE CATALOG：声明 MinIO 上的 filesystem catalog。参数用连字符写法。

③ CREATE TABLE ads：建 Paimon 主键表。主键是 purchase_date，重跑会覆盖不追加。

④ CREATE TABLE doris_ads_purchase：把 Doris 的 ADS 结果表声明为 Flink 源表。fenodes 用 8030，不是 9030。

⑤ INSERT：从 Doris 源表读出，写进 Paimon 目标表。

预期输出：SQL Client 回显原文，随后打印作业提交信息。回显含凭据，查看前要脱敏。

#### 9.3.3 查作业状态

```
curl -fsS http://localhost:8081/jobs/overview | head -c 500; echo
```

预期输出片段：

```
{"jobs":[{"id":"...","status":"FINISHED",...}]}
```

有界源作业会自己结束，显示 FINISHED 属正常。

#### 9.3.4 确认落盘

```
docker run --rm --network whd-net --entrypoint /bin/sh minio/mc:<MC_TAG> -c '
  mc alias set lake http://minio:9000 "<MINIO_AK>" "<MINIO_SK>" &&
  mc ls --recursive lake/lakehouse/paimon/ | head -30
'
```

预期输出：出现 data-*.parquet、manifest 与 snapshot-1。

#### 9.3.5 清理

```
CALL game_db.sys.expire_snapshots('ads_USER_PURCHASE_TRENDS');
```

注意：本机未挂载 /opt/sql，-f 路径不存在，sql-client 的 -e 参数也被忽略。只有 stdin 可靠。

### 9.4 验证判据

| 项 | 判据 |
| --- | --- |
| 作业 | checkpoints.completed 至少为 1 |
| 落盘 | MinIO 有 data、manifest、snapshot 三类文件 |
| 终态 | 有界源作业显示 FINISHED，属正常 |
| 回查 | Doris 只读 Catalog 能查到同一张表 |

注意：Doris connector 是有界源，作业几秒就 FINISHED。判据是 checkpoint 完成加 snapshot 存在，不是作业仍在 RUNNING。

### 9.5 Doris 侧 catalog 参数

Doris 4.1.x 建 Paimon catalog 给一组参数即可，与 Flink 侧不同在 path-style 属性名。

```
CREATE CATALOG paimon_lake PROPERTIES (
  "type" = "paimon",
  "warehouse" = "s3://lakehouse/paimon",
  "s3.endpoint" = "http://minio:9000",
  "s3.access_key" = "<MINIO_AK>",
  "s3.secret_key" = "<MINIO_SK>",
  "s3.path-style-access" = "true"
);
```

也可整体换用 minio. 前缀：minio.endpoint / minio.access_key / minio.secret_key / minio.use_path_style。

注意：改参数前先 DROP CATALOG。CREATE CATALOG IF NOT EXISTS 不会更新已有 catalog。

两边 warehouse 必须完全一致，都是 s3://lakehouse/paimon。

### 9.6 踩坑表

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 作业在跑但湖里没文件 | checkpoint 没开或没完成 | 设 interval，等一个周期，看 Flink UI |
| ClassNotFoundException: org.apache.paimon | jar 只挂了 JM | JM 与 TM 都挂六份 |
| Unable to load AWS credentials | 缺 paimon-s3 bundle | 补 paimon-s3-1.3.1.jar |
| CREATE CATALOG 报 HdfsConfiguration | 缺 HDFS 客户端 | 补 hadoop-hdfs-client-3.3.4.jar |
| 作业反复 RESTARTING，只产 data 文件 | 缺 FileInputFormat | 补 hadoop-mapreduce-client-core-3.3.4.jar |
| No FileSystem for scheme s3 | 缺 S3 支持 jar | 两边都放 paimon-s3 或 flink-s3-fs-hadoop |
| SignatureDoesNotMatch | endpoint 写成 localhost | 统一用 http://minio:9000 |
| Doris 报 scheme s3 无实现 | path-style 属性名写错 | 写 s3.path-style-access（连字符），不是 s3.path.style.access |
| Doris 建好 catalog 查不到表 | 两边 warehouse 不一致 | 统一为 s3://lakehouse/paimon |
| 作业 FINISHED 被误判失败 | 有界源会自己结束 | 看 checkpoint 与 snapshot，不看 RUNNING |
| 单文件挂载后类加载异常 | 宿主机 jar 不存在，Docker 建了同名目录 | 起容器前 ls -l 确认是文件 |

## 十、StarRocks 对接

方言：StarRocks SQL。客户端：DataGrip 或 MySQL 客户端。

StarRocks 接管查询侧。写入仍由 Flink 承担。

本章结论在本机 starrocks/allin1-ubuntu:4.1.7 开源版实测通过。实测日期为 2026-11-17。

### 10.1 能力边界

| 能力 | StarRocks 4.1.7 实测 | Flink |
| --- | --- | --- |
| 查询 Paimon | 支持 | 支持 |
| 建 Paimon 库 | 不支持 | 支持 |
| 建 Paimon 表 | 不支持 | 支持 |
| 向 Paimon 表 INSERT | 不支持 | 支持 |
| 读 Paimon 写回内表 | 支持 | 不适用 |
| 流式 CDC 写入 | 不支持 | 支持，主力方案 |

结论是 Flink 写、StarRocks 读。StarRocks 只能把 Paimon 当只读外部数据源。

注意：阿里云 EMR 文档称 3.2.9 起可建表与 INSERT。该能力属定制版。开源版 4.1.7 实测不支持，不要照抄。

### 10.2 建 catalog

前提：StarRocks 容器已接入 whd-net。

```
CREATE EXTERNAL CATALOG paimon_lake PROPERTIES (
  "type" = "paimon",
  "paimon.catalog.type" = "filesystem",
  "paimon.catalog.warehouse" = "s3://lakehouse/paimon",
  "aws.s3.enable_ssl" = "false",
  "aws.s3.enable_path_style_access" = "true",
  "aws.s3.endpoint" = "http://minio:9000",
  "aws.s3.access_key" = "<MINIO_AK>",
  "aws.s3.secret_key" = "<MINIO_SK>"
);
```

预期：SHOW CATALOGS 返回 paimon_lake 一行，Type 为 Paimon。

实测输出：

```
Catalog          Type    Comment
default_catalog  Internal An internal catalog contains this cluster's self-managed tables.
paimon_lake      Paimon  NULL
```

注意：MinIO 用 HTTP 时 enable_ssl 设为 false。path_style_access 必须设 true，否则桶会被解析成子域名。

endpoint 用容器内地址 http://minio:9000。写 localhost 会指向 StarRocks 自己。

### 10.3 三套参数前缀

| 引擎 | 凭据参数 | endpoint 参数 | path-style 参数 |
| --- | --- | --- | --- |
| Flink | s3.access-key（连字符） | s3.endpoint | s3.path.style.access（点号） |
| Doris | s3.access_key（下划线） | s3.endpoint | s3.path-style-access（连字符） |
| StarRocks | aws.s3.access_key | aws.s3.endpoint | aws.s3.enable_path_style_access |

三者的 warehouse 必须完全相同，都是 s3://lakehouse/paimon。

### 10.4 读取验证

```
SET CATALOG paimon_lake;
SHOW DATABASES;
USE game_db;
SHOW TABLES;
SELECT * FROM ADS_USER_PURCHASE_TRENDS LIMIT 10;
```

实测输出：库列表含 game_db，表列表含 ADS_USER_PURCHASE_TRENDS，SELECT 返回湖上数据。

```
purchase_date  daily_purchase_events
2024-08-01     75
2024-08-02     85
2024-08-03     167
```

### 10.5 写能力实测

以下三条语句均实测失败，证实开源版不支持回写 Paimon。

```
CREATE DATABASE IF NOT EXISTS paimon_lake.sr_test_db;
```

实测报错：ERROR 1064 This connector doesn't support creating databases。

```
CREATE TABLE paimon_lake.game_db.sr_write_test (id BIGINT) ENGINE=paimon;
```

实测报错：ERROR 1064 This connector doesn't support creating tables。

```
INSERT INTO paimon_lake.game_db.ADS_USER_PURCHASE_TRENDS VALUES ('2024-08-11', 999);
```

实测报错：ERROR 1064 fail to begin transaction。

支持的方向是反向加载，即从 Paimon 读、写进 StarRocks 内表。

```
CREATE DATABASE IF NOT EXISTS sr_lake_test;
CREATE TABLE sr_lake_test.ads_copy (
  purchase_date DATE,
  daily_purchase_events BIGINT
) DISTRIBUTED BY HASH(purchase_date)
PROPERTIES("replication_num"="1");

INSERT INTO sr_lake_test.ads_copy
SELECT purchase_date, daily_purchase_events
FROM paimon_lake.game_db.ADS_USER_PURCHASE_TRENDS
WHERE purchase_date <= '2024-08-05';

SELECT COUNT(*) FROM sr_lake_test.ads_copy;
```

实测输出：copied_rows 为 5。验证后已 DROP DATABASE sr_lake_test 清理。

### 10.6 三种访问方式

Paimon 不是服务，没有端口和连接串。它通过计算引擎访问。

① SQL 客户端。本机用 stdin 喂给 Flink SQL Client。

② Python。用 PyFlink 提交 SQL 作业，不是直连 Paimon。

```
from pyflink.table import EnvironmentSettings, TableEnvironment
t_env = TableEnvironment.create(EnvironmentSettings.in_streaming_mode())
t_env.execute_sql("SET 'execution.checkpointing.interval' = '10s'")
t_env.execute_sql("""
CREATE CATALOG paimon_lake WITH (
  'type' = 'paimon',
  'metastore' = 'filesystem',
  'warehouse' = 's3://lakehouse/paimon',
  's3.endpoint' = 'http://minio:9000',
  's3.access-key' = '<MINIO_AK>',
  's3.secret-key' = '<MINIO_SK>',
  's3.path.style.access' = 'true'
)
""")
```

③ Shell 脚本。把 docker exec 加 stdin 写进 .sh，供调度重复执行。

提示：Python 与 Shell 都是包装器，底层仍走 Flink 作业。

## 十一、DataGrip 查询湖表

方言：StarRocks SQL。客户端：DataGrip 的 MySQL 数据源。

本章给一套从建连接到查数的完整操作。以下参数与输出在本机 4.1.7 实测通过。

### 11.1 新建连接

DataGrip 用 MySQL 驱动连 StarRocks。新建数据源选 MySQL，填下列参数。

| 参数 | 取值 |
| --- | --- |
| Host | 127.0.0.1 |
| Port | 19030 |
| User | root |
| Password | 读 /Users/wenhuadong/docker/olap/starrocks/.env 的 SR_ROOT_PWD |
| Database | 留空 |

注意：端口填 19030，不是 8030 或 18030。19030 映射到 FE 的 MySQL 查询端口 9030。

18030 是 HTTP 端口，给浏览器和 REST 用。JDBC 连它会报协议错误。

### 11.2 验证连接

建好数据源后，打开查询控制台执行：

```
SELECT VERSION();
```

实测输出：

```
version()
8.0.33
```

返回版本号即连通。8.0.33 是 StarRocks 模拟的 MySQL 版本，不是真实 MySQL。

再确认前后端存活：

```
SHOW FRONTENDS;
SHOW BACKENDS;
```

判据：FE 的 Alive 为 true，BE 的 Alive 为 true。

### 11.3 切换 catalog

StarRocks 用 SET CATALOG，不是 USE CATALOG。

```
SET CATALOG paimon_lake;
SHOW DATABASES;
```

实测输出：库列表含 game_db。

然后切库：

```
USE game_db;
SHOW TABLES;
```

预期：表列表含 ADS_USER_PURCHASE_TRENDS。

注意：SET CATALOG 是会话级设置。DataGrip 每个查询窗口是独立会话。换窗口或重连后要重新执行。

### 11.4 查询湖表

```
SELECT * FROM ADS_USER_PURCHASE_TRENDS LIMIT 10;
```

实测输出前 3 行：

```
purchase_date  daily_purchase_events
2024-08-01     75
2024-08-02     85
2024-08-03     167
```

数据来自 MinIO 上的 s3://lakehouse/paimon/，无需导入 StarRocks。

### 11.5 只读边界

在 DataGrip 里向湖表写入会失败。以下语句均实测报错：

```
CREATE DATABASE paimon_lake.sr_test_db;
```

报错：This connector doesn't support creating databases。

```
CREATE TABLE paimon_lake.game_db.sr_write_test (id BIGINT) ENGINE=paimon;
```

报错：This connector doesn't support creating tables。

```
INSERT INTO paimon_lake.game_db.ADS_USER_PURCHASE_TRENDS VALUES ('2024-08-11', 999);
```

报错：[42000][1064] Getting analyzing error. Detail message: fail to begin transaction. databaseTransactionMgr[100000049] does not exist.

原因：开源版 4.1.7 的 Paimon catalog 只读。写入仍走 Flink，见第三至九章。

支持的方向是从湖表读、写进 StarRocks 内表：

```
INSERT INTO sr_lake_test.ads_copy
SELECT purchase_date, daily_purchase_events
FROM paimon_lake.game_db.ADS_USER_PURCHASE_TRENDS;
```

前提是 sr_lake_test 库与 ads_copy 表已在 default_catalog 下建好。

### 11.6 常见报错

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| ERROR 1064 Unexpected input CATALOG | 用了 USE CATALOG | 改 SET CATALOG |
| ERROR 1064 at WITH (...) | 贴了 Flink 建表语句 | StarRocks 不支持 WITH，湖表只读 |
| 连接被拒绝 | 端口填成 18030 或 8030 | 改 19030 |
| Access denied for user root | 口令未填或填错 | 读 .env 的 SR_ROOT_PWD |
| Unknown database game_db | 未切到 paimon_lake | 先 SET CATALOG |
| 换窗口后找不到表 | SET CATALOG 是会话级 | 新窗口重设一次 |

## 十二、本篇小结

① Paimon 用法是挂 jar、开 checkpoint、建 catalog、建表读写。

② 本机六个 jar 已在 JM 与 TM 各一份，warehouse 是 s3://lakehouse/paimon/。

③ 提交绑定 checkpoint，不开就没有可见数据。

④ 主键表支持 upsert 与 changelog，bucket 决定并行度与文件粒度。

⑤ Doris 侧参数用下划线加 paimon.s3.* 透传组，与 Flink 侧连字符不同。

⑥ StarRocks 开源版 4.1.7 对 Paimon 只读，用 aws.s3.* 前缀；写入仍由 Flink 承担。

⑦ 三至八章是 Flink SQL。DataGrip 连 StarRocks 要换 SET CATALOG，见第十一章。

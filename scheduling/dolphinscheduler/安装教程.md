## 0. 动手前先记住三条红线

| # | 红线 | 原因 |
| --- | --- | --- |
| 1 | 不 CREATE DATABASE、不 DROP DATABASE、不执行 sql/dolphinscheduler_postgresql.sql | 库已存在且是 3.4.3 的 64 张表；该 SQL 开头是一串 DROP TABLE IF EXISTS，跑一次就清库重建 |
| 2 | 不改宿主 postgresql.conf / pg_hba.conf | 现有 listen_addresses=localhost + pg_hba trust 已放行容器连接（Docker Desktop 把流量转发成 127.0.0.1）；改全局规则会牵连 datapivot 等其它库 |
| 3 | 编排里 SPRING_SQL_INIT_MODE=never、JAVA_OPTS=-Xmx2g 两条不能删 | 前者防启动时刷库，后者防镜像默认 -Xmx4g 把 Docker Desktop 打 OOM（旧容器 Exited(137)） |

口令、SECRET_KEY 只写在 conf/dolphinscheduler.env 与本机回填表；**项目仓库侧一律用 &lt;DS_DB_PWD&gt; 等占位符**。

### 4.2 路径 B：空库

> 仅当目标机器上**根本没有** dolphinscheduler 库时使用；本机已存在，执行会清掉 64 张表。执行前确认没有其它会话连着该库。&lt;DS_DB_PWD&gt; 用占位符，真值同步写进 conf/dolphinscheduler.env。

```bash
# 1) 建角色与库（以宿主 PG 超级用户执行）
psql -w -h 127.0.0.1 -U wenhuadong -d postgres -v ON_ERROR_STOP=1 <<'SQL'
CREATE ROLE root WITH LOGIN PASSWORD '<DS_DB_PWD>';
CREATE DATABASE dolphinscheduler OWNER root;
SQL

# 2) 导入官方初始化 SQL（只在空库上做一次）
psql -w -h 127.0.0.1 -U root -d dolphinscheduler -v ON_ERROR_STOP=1 \
  -f /Users/wenhuadong/docker/scheduling/dolphinscheduler/sql/dolphinscheduler_postgresql.sql

# 3) 复核
psql -w -h 127.0.0.1 -U root -d dolphinscheduler \
  -tAc "select version from t_ds_version;"
psql -w -h 127.0.0.1 -U root -d dolphinscheduler \
  -tAc "select count(*) from pg_tables where schemaname='public';"
#   期望：3.4.3 ／ 64

# 4) 把 conf/dolphinscheduler.env 的 SPRING_DATASOURCE_PASSWORD 改成同一个 <DS_DB_PWD>
grep '^SPRING_DATASOURCE_' /Users/wenhuadong/docker/scheduling/dolphinscheduler/conf/dolphinscheduler.env
```

| 边界 | 说明 |
| --- | --- |
| SQL 内容 | 开头 11 条 DROP TABLE IF EXISTS QRTZ_*，全文件还有几十条 DROP TABLE IF EXISTS t_ds_* 与默认 admin INSERT |
| 执行次数 | 只一次；之后靠 SPRING_SQL_INIT_MODE=never 隔离 |
| 账号 | 用普通角色 root 做库/表 owner，不把 Superuser 交给应用 |
| 版本 | SQL 里的 t_ds_version 必须与镜像 tag 一致，否则升级时还要跑版本迁移脚本 |

### 4.3 明确不做的事

| 不做 | 原因 |
| --- | --- |

## 5. 启动就绪

```bash
F=/Users/wenhuadong/docker/scheduling/dolphinscheduler/conf/docker-compose.whd.yml

# 1) 语法自检
docker compose -f "$F" config -q

# 2) 起容器
docker compose -f "$F" up -d

# 3) 看状态与日志
docker compose -f "$F" ps
docker logs -f --tail 100 ds-standalone

# 4) 循环等 UI 就绪（最多 3 分钟）
for i in $(seq 1 36); do
  code=$(curl -s -o /dev/null -w '%{http_code}' \
    http://localhost:12345/dolphinscheduler/ui/login 2>/dev/null || true)
  [ "$code" = "200" ] && { echo "DS UI 就绪"; break; }
  echo "第 ${i} 次：还没就绪，等 5s"; sleep 5
done
```

**等待点**：standalone 内含 Master / Worker / API / Alert 与 Quartz，首次启动约 1–2 分钟；healthy 之前别去点 UI。

| 步骤 | 判据 | 不通过怎么办 |
| --- | --- | --- |
| 1 语法 | 无输出 | 检查 YAML 缩进；口令若写在 env 里含特殊字符要加引号 |
| 2 up -d | 容器创建成功 | docker logs ds-standalone --tail 100；报端口占用回账号与库准备步骤 |
| 3 等 UI | compose ps 为 healthy、HTTP 200 | 日志里查 Communications link failure（数据源）、OutOfMemoryError（堆）、relation ... does not exist（库表） |

> 日志出现 OverLoad ... cpu usage 1.0 是 Master 采到宿主 CPU 过高触发的过载保护告警，**不影响 UI / 登录**，UI 200 且能建项目即视为可用。

## 8. 停止、重启与重来

```bash
F=/Users/wenhuadong/docker/scheduling/dolphinscheduler/conf/docker-compose.whd.yml

docker compose -f "$F" stop          # 停容器；宿主 PG 与元数据不动
docker compose -f "$F" start
docker compose -f "$F" restart       # 持久化复核用这个

docker compose -f "$F" down          # 删容器；**不要加 -v**
docker compose -f "$F" up -d         # 重建容器，元数据仍在宿主 PG
```

| 动作 | 影响范围 | 数据安全 |
| --- | --- | --- |
| stop / start / restart | 只有容器进程 | 全保留 |
| down | 删容器层 | volumes/ds/ 是 bind mount，保留；宿主 PG 不受影响 |
| down -v | 连带删具名卷 | **禁止**（准则 4.3） |
| rm -rf volumes/ds/* | 日志与资源文件 | 只在明确要清时做，元数据不在这里 |
| 处理 dolphinscheduler 库 | 宿主 PG | 本教程不提供清库命令；删库等于删掉全部项目/工作流定义 |

**重来（换机器 / 重装）最短路径**：核查 → 建空库（仅新机器）→ down（旧 name 时执行）→ up -d → 验收。

**改 Compose 项目名**：必须先用**旧 name** 执行 down，再改文件里的 name:，最后 up -d 重建 label，不加 -v；只改文件不重建会让 compose ps 看不到容器。

## 9. 故障速查

| 现象 | 先查 | 处理 |
| --- | --- | --- |
| FATAL: role "root" does not exist | 账号准备 | 新机器建空库；本机只复核 |
| CREATE DATABASE 报已存在 | 误走路径 B | 回到路径 A，不建不删 |
| 表被清空 / admin 口令被重置 | SPRING_SQL_INIT_MODE 被删 | 恢复 never；初始化 SQL 安装流程不执行 |
| permission denied for table t_ds_* | 表属主 | 复核 4.1 的 owner 与 has_table_privilege |
| JDBC localhost:5432 连不上 | 地址写错 | 改 host.docker.internal:5432 |
| Exited (137) / OutOfMemoryError | 堆太大 | JAVA_OPTS 限到 -Xmx2g |
| UI 502 / 登录页打不开 | 启动慢 | 等 1–2 分钟，以 healthcheck 为准 |
| 重启后项目消失 | 用了内存 H2 | 确认 SPRING_PROFILES_ACTIVE=postgresql |
| DS 建 Doris 数据源 Access denied | 未填口令 | 填 &lt;FE_PWD&gt，只有 FE 容器内 loopback 免密 |
| compose ps 看不到容器 | 改过 name: 没重建 | 旧 name down → 改文件 → up -d |

**看日志三个入口**：docker compose -f "$F" logs --tail 100；volumes/ds/logs/ 下的 standalone 日志；宿主 PG 的 pg_stat_activity 看连接池会话是否建立。

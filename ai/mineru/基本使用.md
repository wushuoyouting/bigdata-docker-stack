# MinerU 基本使用

> **一句话结论**：mineru-kit 做一次性转换，mineru 做文档库与检索，WebUI 做图形化上传。三者共用同一份安装包。

> **本文解决什么**：装完后怎么转 PDF、怎么读结果、怎么批量处理、怎么开界面。
>
> **适用谁**：已完成安装教程验收的用户。
>
> **读完能做什么**：命令行转换单文件与目录，检索已解析内容，启动 WebUI 与接口。

> **前提**：虚拟环境已激活，工作目录为 /Users/wenhuadong/docker/ai/mineru。

---

## 一、入口总览

| 入口 | 命令或地址 | 用途 |
| --- | --- | --- |
| 转换命令 | mineru-kit | 一次性转换，不建库 |
| 文档库命令 | mineru | 解析入本地库，支持检索与续读 |
| WebUI | http://localhost:7860 | 浏览器上传与预览 |
| 接口 | http://127.0.0.1:8000 | 脚本化转换请求 |

> mineru-kit 无状态，转完即走。mineru 把解析结果写进本地库，用文档编号续读。两者服务不同目标。

---

## 二、一次性转换

**前提**：组件目录已有 sample.pdf。

```bash
mineru-kit parse sample.pdf -o sample.md --tier flash --ocr-mode txt
```

预期输出：生成 sample.md，含文档正文与标题层级。

| 参数 | 作用 |
| --- | --- |
| -o | 单文件给文件路径，目录批量给目录路径 |
| --tier | 质量档位，取值 flash、basic、standard、advanced |
| --ocr-mode | txt 只读文本层，ocr 走识别模型 |
| --format zip | 批量转换时打包输出 |

**批量转换**：

```bash
mineru-kit parse ./documents -o ./output --format zip
```

预期输出：output 目录生成 zip 包。

> 目录输入时 -o 必须是目录。单文件输入时 -o 写文件路径。混用会报错。

---

## 三、文档库解析

```bash
mineru parse "sample.pdf" --json

mineru parse "sample.pdf" --output ./sample-lib.md

mineru parse "sample.pdf" --tier standard
```

预期输出：--json 返回结构化结果。--output 写文件。默认解析入本地库并返回文档编号。

| 参数 | 作用 |
| --- | --- |
| --json | 输出结构化结果，便于脚本读取 |
| --output | 指定输出文件路径 |
| --pages | 指定页范围，如 1-10 或 all |
| --limit | 限制返回字符数 |
| --tier | 质量档位 |
| --no-wait | 提交后立即返回，不等待完成 |
| --force | 对已解析文件触发重新解析 |

> 文档库命令会保存解析记录。同一文件重复解析时加 --force。

---

## 四、续读与检索

**说明**：文档编号来自解析结果，格式以 doc: 开头。

```bash
mineru read "doc:ab12cd3/tier:standard/page:11" --limit 12000 --json

mineru search "转换质量" --min-tier basic --json

mineru find "sample" --ext pdf

mineru list docs --json
```

预期输出：read 返回指定页内容。search 返回命中列表。find 返回文件列表。list 返回文档清单。

| 命令 | 用途 |
| --- | --- |
| mineru read | 按定位串读页、块或字符片段 |
| mineru search | 全文检索已解析内容 |
| mineru find | 按文件名与扩展名找文件 |
| mineru list docs | 列出文档库清单 |

> 定位串由文档编号、档位、页码、块号组成，用斜杠分隔。块级定位在末尾加 block 段。

## 五、质量档位

| 档位 | 用途 |
| --- | --- |
| flash | 快速预览，网页与纯文本层场景 |
| basic | 基础结构提取 |
| standard | 默认档位，通用文档 |
| advanced | 高精度，复杂版面 |

> flash 档配合 --ocr-mode txt 不触发模型下载。其余档位首次使用会下载权重。

## 六、WebUI

**前提**：7860 端口空闲。

```bash
mineru-kit webui --server-name 0.0.0.0 --server-port 7860
```

浏览器打开 http://localhost:7860。

| 区域 | 用途 |
| --- | --- |
| 上传区 | 选 PDF、Word、图片等文件 |
| 解析等级 | 滑块取值 0 到 3，对应 flash 到 advanced |
| 结果区 | 预览 Markdown 与下载结果 |

**注意**：默认解析等级是 2，对应 standard。本机本地引擎未启用时，standard 会转向远程接口。远程未配置密钥时，转换报 upstream_unavailable。上传涉密 PDF 前，先把解析等级拖到 0，即 flash 极速档。flash 档只读文本层，文档不外传。

**实测**：本机选 flash 档转换 47 页 PDF，产出正文 12.4 万字符，状态走完至完成。Markdown 结果渲染在页面的 iframe 内，读取正文要取 iframe 的 srcdoc。

> WebUI 适合个别文件与人工校对。批量任务用命令行。WebUI 与命令行共用同一份模型缓存。

## 七、服务与接口

**前提**：本机转换服务由文档库命令托管。

```bash
mineru server start

mineru server status --json

mineru server stop
```

预期输出：status 返回 JSON，含服务运行状态。

| 命令 | 用途 |
| --- | --- |
| mineru server start | 启动本地托管解析服务 |
| mineru server status --json | 查看服务状态 |
| mineru server stop | 停止服务 |

**健康检查**：

```bash
curl http://127.0.0.1:8000/v1/health
```

预期输出：返回健康状态 JSON。该地址由容器接口的 api 服务提供。

| 地址 | 用途 |
| --- | --- |
| http://127.0.0.1:8000/v1/health | 接口健康检查 |
| http://127.0.0.1:7860 | WebUI |

> 容器内其他服务访问宿主接口时写宿主机地址。写 localhost 会指向容器自己。

## 八、模型管理

```bash
mineru-kit models download --tier standard

mineru-kit models verify --tier standard

mineru-kit hardware detect
```

| 命令 | 用途 |
| --- | --- |
| models download | 下载指定档位模型权重 |
| models verify | 校验模型文件完整性 |
| hardware detect | 探测本机可用算力 |

> verify 只查文件，不跑推理。校验通过不代表转换质量达标。

## 九、常用操作速查

| 想做什么 | 命令或入口 |
| --- | --- |
| 转一个 PDF | mineru-kit parse sample.pdf -o sample.md --tier flash --ocr-mode txt |
| 转整个目录 | mineru-kit parse ./documents -o ./output --format zip |

| 看文档清单 | mineru list docs --json |
| 开图形界面 | mineru-kit webui |
| 查服务状态 | mineru server status --json |

## 十、故障速查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| WebUI 报 upstream_unavailable | 本地引擎未启用，standard 转向未配密钥的远程接口 | 解析等级拖到 0 用 flash 档，或配置远程密钥 |
| WebUI 任务未启动 | 文件上传未同步就点了转换 | 等文件显示已上传，再点转换 |
| PDF 报缺模型 | 档位需要权重且未下载 | mineru-kit models download --tier standard |
| 扫描件转出空文本 | 用了 txt 模式 | 改用 --ocr-mode ocr |
| 批量转换报错 | -o 写了文件路径 | 目录输入的 -o 改成目录 |
| mineru 命令找不到 | 虚拟环境未激活 | source .mineru/bin/activate |
| WebUI 打不开 | 端口占用或只监听回环 | 查 7860 并用 0.0.0.0 启动 |
| 重复解析返回旧结果 | 未加 --force | 解析命令加 --force |
| 检索无结果 | 未先解析入库 | 先执行 mineru parse |

---

## 十一、小结

1. mineru-kit 做一次性转换，mineru 做文档库与检索。
2. 网页与 PDF 文本层读取不下载模型，其余档位首用下载。
3. 单文件 -o 写路径，目录 -o 写目录，批量可打包 zip。
4. WebUI 人工校对，命令行批量处理，两者共用模型缓存。
5. 服务状态用 mineru server status --json 查，模型用 models verify 校验。

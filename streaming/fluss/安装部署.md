# 安装与部署

本文在本机拉起一个可用的 Fluss 1.0.0 集群，并接入已运行的 Flink。适用于已安装 Docker Compose 的 macOS 环境。读完能完成部署、验证连通，并进入 Flink SQL 客户端。

本文采用单 CoordinatorServer 加单 TabletServer 的部署形态。该形态用于学习与开发验证，不承担生产高可用职责。

## 一、安装前复核

### 1.1 核对软件版本

执行以下命令，确认 Docker 与 Compose 可用。

```
docker --version
docker compose version
```

本机实测输出如下。

```
Docker version 29.7.2, build a7dcaa6
Docker Compose version v5.5.0
```

官方示例在 Docker 27.4.0 与 Compose v2.30.3 上测试。本文版本高于该基线，命令保持兼容。

### 1.2 核对端口占用

执行以下命令，确认待分配端口空闲。

```
for p in 9123 9124 2181; do lsof -nP -iTCP:$p -sTCP:LISTEN; done
```

本机实测无输出，三个端口均空闲。端口分配与避让关系如下。

| 端口 | 用途 | 避让说明 |
| --- | --- | --- |
| 9123 | CoordinatorServer 客户端 | 实测空闲，映射到宿主机 |
| 9124 | TabletServer 客户端 | 实测空闲，映射到宿主机 |
| 2181 | ZooKeeper 客户端 | 实测空闲，仅在容器网络内使用 |
| 8081 | Flink Web UI | 已被 Flink 占用，不分配 |
| 9000 | MinIO API | 已被占用，不分配 |
| 3306 | MySQL | 已被本机服务占用，不分配 |
| 5432 | PostgreSQL | 已被本机服务占用，不分配 |

### 1.3 核对已有服务

执行以下命令，确认 Flink 容器正在运行。

```
docker ps --format '{{.Names}}\t{{.Image}}' | grep flink
```

本机实测输出如下。

```
flink-taskmanager  flink:1.20.5-java11
flink-jobmanager   flink:1.20.5-java11
```

Flink 已以容器方式运行，本文不再启动新的 Flink 集群。Fluss 容器与现有 Flink 容器通过自定义网桥互通。

## 二、部署集群

### 2.1 建立目录与编排文件

执行以下命令，建立工作目录。

```
mkdir -p /Users/wenhuadong/docker/streaming/fluss
cd /Users/wenhuadong/docker/streaming/fluss
```

用 heredoc 写入编排文件。该文件给出完整案例值，可直接复制。

```
cat > docker-compose.yml <<'EOF'
services:
  fluss-zookeeper:
    container_name: fluss-zookeeper
    image: zookeeper:3.9.2
    restart: always
    networks:
      - fluss-net
  fluss-coordinator:
    container_name: fluss-coordinator
    image: apache/fluss:1.0.0
    command: coordinatorServer
    depends_on:
      - fluss-zookeeper
    environment:
      - |
        FLUSS_PROPERTIES=
        zookeeper.address: fluss-zookeeper:2181
        bind.listeners: INTERNAL://fluss-coordinator:0, CLIENT://fluss-coordinator:9123
        advertised.listeners: CLIENT://fluss-coordinator:9123
        internal.listener.name: INTERNAL
        remote.data.dir: /tmp/fluss/remote-data
    ports:
      - "9123:9123"
    networks:
      - fluss-net
  fluss-tablet:
    container_name: fluss-tablet
    image: apache/fluss:1.0.0
    command: tabletServer
    depends_on:
      - fluss-coordinator
    environment:
      - |
        FLUSS_PROPERTIES=
        zookeeper.address: fluss-zookeeper:2181
        bind.listeners: INTERNAL://fluss-tablet:0, CLIENT://fluss-tablet:9123
        advertised.listeners: CLIENT://fluss-tablet:9123
        internal.listener.name: INTERNAL
        tablet-server.id: 0
        kv.snapshot.interval: 0s
        data.dir: /tmp/fluss/data
        remote.data.dir: /tmp/fluss/remote-data
    ports:
      - "9124:9123"
    volumes:
      - shared-tmpfs:/tmp/fluss
    networks:
      - fluss-net
volumes:
  shared-tmpfs:
    driver: local
    driver_opts:
      type: "tmpfs"
      device: "tmpfs"
networks:
  fluss-net:
    driver: bridge
EOF
chmod 644 docker-compose.yml
```

关键参数说明如下。

| 参数 | 案例值 | 说明 |
| --- | --- | --- |
| zookeeper.address | fluss-zookeeper:2181 | 元数据服务地址，使用容器服务名 |
| bind.listeners | INTERNAL://fluss-coordinator:0 | 内部通信监听地址，端口 0 表示动态分配 |
| advertised.listeners | CLIENT://fluss-coordinator:9123 | 返回给客户端的地址，必须可被解析 |
| internal.listener.name | INTERNAL | 指定内部通信使用的监听器名称 |
| tablet-server.id | 0 | TabletServer 唯一编号，多实例时不可重复 |
| kv.snapshot.interval | 0s | 关闭周期快照，仅用于学习环境 |
| data.dir | /tmp/fluss/data | 本地日志与键值状态目录 |
| remote.data.dir | /tmp/fluss/remote-data | 远端数据目录，此处落在 tmpfs 卷 |

本文把 advertised.listeners 设为容器服务名。官方单节点示例设为 localhost，两者取值不同。原因有三条。
① 本文的客户端是容器内的 Flink。
② localhost 指向 Flink 容器自身，无法解析到 Fluss。
③ 使用服务名后，Flink 与 Fluss 容器在同一网络中可直接互访。
宿主机上的客户端通过 9123 与 9124 端口访问。

注意：shared-tmpfs 使用内存文件系统。容器删除或宿主机重启后数据丢失。学习环境可接受，生产环境需换成持久卷。

### 2.2 拉取镜像

执行以下命令，提前拉取镜像。

```
docker compose pull
```

预期输出包含 apache/fluss:1.0.0 与 zookeeper:3.9.2 的下载或校验信息。

### 2.3 启动集群

本组件在 whd-net 的静态地址为 172.30.0.13。compose 内各服务按静态段从 .13 起顺延取号。重建容器须保留原 IP。依据：code-wiki/06 的 IP 分配表。

执行以下命令，后台启动三个容器。

```
docker compose up -d
```

预期输出显示三个容器被创建并启动，最后状态为 Started。

## 三、接入已有 Flink

### 3.1 连接容器网络

执行以下命令，把 Flink 容器接入 Fluss 网络。

```
docker network connect fluss-net flink-jobmanager
docker network connect fluss-net flink-taskmanager
```

无输出即表示成功。该操作在容器运行时生效，容器重建后需重新执行。

### 3.2 部署连接器

Flink 1.20.5 对应连接器 fluss-flink-1.20-1.0.0。执行以下命令下载并放入 Flink 的 lib 目录。

```
cd /Users/wenhuadong/docker/streaming/fluss
curl -fLO https://repo1.maven.org/maven2/org/apache/fluss/fluss-flink-1.20/1.0.0/fluss-flink-1.20-1.0.0.jar
docker cp fluss-flink-1.20-1.0.0.jar flink-jobmanager:/opt/flink/lib/
docker cp fluss-flink-1.20-1.0.0.jar flink-taskmanager:/opt/flink/lib/
```

注意：连接器jar 需同时放入 JobManager 与 TaskManager。仅放一侧会导致作业提交后类找不到。

注意：重启会中断 Flink 上正在运行的作业。请在无作业或低峰时段执行重启。

```
docker restart flink-jobmanager flink-taskmanager
```

### 3.3 进入 SQL 客户端

执行以下命令，进入 JobManager 容器内的 SQL 客户端。

```
docker exec -it flink-jobmanager /opt/flink/bin/sql-client.sh
```

在客户端内执行以下语句，注册 Catalog 并查看结果。

```
CREATE CATALOG fluss_catalog WITH(
  'type'='fluss',
  'bootstrap.servers'='fluss-coordinator:9123'
);
SHOW CATALOGS;
```

预期输出列出 fluss_catalog。bootstrap.servers 指向 CoordinatorServer 的服务名，与编排文件中的 advertised.listeners 对应。

## 四、验收

以下检查在全部安装与配置步骤完成后执行。逐项确认通过，再进入日常使用。

| 判据 | 检查方式 | 通过标准 |
| --- | --- | --- |
| 三个容器正常运行 | docker compose ps | zookeeper、coordinator、tablet 状态均为 Up |
| 客户端端口可达 | nc -z localhost 9123 与 nc -z localhost 9124 | 两条命令均无报错 |
| Catalog 注册成功 | 在 SQL 客户端执行 SHOW CATALOGS | 输出包含 fluss_catalog |
| 建表写入可读回 | 在 SQL 客户端依次执行下方建表与查询 SQL | COUNT 返回 1 |

建表与查询 SQL 如下，用于最后一项验收。

```
USE CATALOG fluss_catalog;
CREATE DATABASE IF NOT EXISTS demo;
USE demo;
CREATE TABLE t_check (
  id BIGINT,
  name STRING,
  PRIMARY KEY (id) NOT ENFORCED
) WITH (
  'bucket.num'='1',
  'table.replication.factor'='1'
);
INSERT INTO t_check VALUES (1, 'ok');
SET 'execution.runtime-mode' = 'batch';
SELECT COUNT(*) FROM t_check;
```

table.replication.factor 设为 1，与本集群的单 TabletServer 匹配。生产集群需按副本数要求调整该值。

## 五、故障速查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 容器反复重启 | ZooKeeper 未就绪 | 查看 coordinator 日志，确认 zookeeper.address 可解析 |
| SQL 客户端报无法发现 factory | 连接器 jar 未在 lib 目录 | 检查两个 Flink 容器的 /opt/flink/lib 是否含 jar 并重启 |
| 写入报连接被拒绝 | 客户端地址不可解析 | 核对 advertised.listeners 与 bootstrap.servers 是否一致 |
| 写入报副本不足 | 副本因子大于 TabletServer 数量 | 建表时把 table.replication.factor 设为 1 |
| 容器重启后数据清空 | 数据目录落在 tmpfs | 把 shared-tmpfs 换成命名卷或绑定挂载 |

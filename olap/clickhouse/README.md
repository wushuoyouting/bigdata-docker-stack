# ClickHouse 组件

> **一句话定位**：ClickHouse 是列式分析数据库。本机用它处理日志、埋点、时序与超高基数单表。它补齐 Doris 与 StarRocks 不擅长的场景。

> **边界**：本文只做导航。安装命令放安装教程。操作命令放基本使用。取舍依据放基本原理。

## 二、部署形态

> **本机选型**：一个容器跑单节点服务。ClickHouse 单节点原生支持多核并行。演示环境不拆分片与副本。

| 形态 | 容器数 | 适用 |
| --- | --- | --- |
| 单机单容器 | 1 | 本机演示、学习、SQL 调试 |
| 分片加副本集群 | 多容器 | 生产、海量数据、高可用 |

**为什么集群要分开**：分片承担横向扩容。副本承担故障切换。两者依赖 Keeper 做协调。演示环境不需要这些角色。

**为什么本机合并**：单节点已提供列存、向量化执行与索引能力。多起容器只增加内存与配置成本。这些成本不提升本机验证价值。

> 单机代价是没有分片与副本。数据只落在容器挂载目录。单机故障时靠目录备份恢复。本机接受该代价。

## 六、边界说明

**独立安装阶段**：装单节点容器。挂载配置、数据与日志目录。验到 HTTP ping 返回 Ok。再用 clickhouse-client 执行 SELECT 1。不建业务表，不接外部数据源。

**基本使用阶段**：建库建表、导入样例数据、执行查询、管理用户。该阶段只操作本机容器。

> 数据目录与日志目录只在本地保留。两者不提交到仓库。

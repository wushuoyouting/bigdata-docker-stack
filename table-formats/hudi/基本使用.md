# Hudi 基本使用

> **一句话结论**：Hudi 用法是「加 bundle jar、配 catalog、建表、upsert」。对象存储统一用 MinIO，warehouse 指向 s3://lakehouse/hudi/。Spark SQL 与 Flink SQL 都能写，下面以 Spark 为主。

> **本文解决什么**：给出从零建表到 upsert、增量查询、compaction 的完整命令。
>
> **适用谁**：已装好 MinIO，用 Spark 做 CDC 入湖或行级更新的人。
>
> **读完能做什么**：独立建表、写 upsert、做增量查询、跑表服务，并排查常见错误。

---

## 一、前置条件

| 项 | 取值 |
| --- | --- |
| 对象存储 | MinIO，桶 lakehouse |
| S3 API | http://minio:9000 |
| 凭据 | 占位符 &lt;MINIO_AK&gt; 与 &lt;MINIO_SK&gt; |
| warehouse | s3://lakehouse/hudi/ |
| 计算引擎 | Spark 3.5 |
| Hudi 版本 | 0.14.x 或 1.x，与 Spark 大版本匹配 |

前提：lakehouse 桶已建，path-style 已开启。

## 二、依赖 jar 与 Spark 配置

### 2.1 jar

下 hudi-spark bundle jar，放进 Spark 的 jars 目录。

```
hudi-spark3.5-bundle_2.12-<HUDI_VERSION>.jar
```

### 2.2 启动配置

```
spark-sql \
  --jars /path/to/hudi-spark3.5-bundle_2.12-<HUDI_VERSION>.jar \
  --conf spark.serializer=org.apache.spark.serializer.KryoSerializer \
  --conf spark.sql.catalog.spark_catalog=org.apache.spark.sql.hudi.catalog.HoodieCatalog \
  --conf spark.sql.extensions=org.apache.spark.sql.hudi.HoodieSparkSessionExtension \
  --conf spark.hadoop.fs.s3a.endpoint=http://minio:9000 \
  --conf spark.hadoop.fs.s3a.access.key=<MINIO_AK> \
  --conf spark.hadoop.fs.s3a.secret.key=<MINIO_SK> \
  --conf spark.hadoop.fs.s3a.path.style.access=true \
  --conf spark.hadoop.fs.s3a.impl=org.apache.hadoop.fs.s3a.S3AFileSystem
```

注意：KryoSerializer 与 HoodieSparkSessionExtension 两项必配。缺任一都会报语法或序列化错误。

## 三、建表

### 3.1 COW 表

```
CREATE TABLE hudi_cow (
  id BIGINT,
  name STRING,
  price DECIMAL(18,2),
  updated_at TIMESTAMP,
  dt STRING
) USING hudi
TBLPROPERTIES (
  type = 'cow',
  primaryKey = 'id',
  preCombineField = 'updated_at',
  hoodie.table.name = 'hudi_cow'
)
PARTITIONED BY (dt)
LOCATION 's3://lakehouse/hudi/demo_db/hudi_cow';
```

### 3.2 MOR 表

```
CREATE TABLE hudi_mor (
  id BIGINT,
  name STRING,
  price DECIMAL(18,2),
  updated_at TIMESTAMP,
  dt STRING
) USING hudi
TBLPROPERTIES (
  type = 'mor',
  primaryKey = 'id',
  preCombineField = 'updated_at',
  hoodie.table.name = 'hudi_mor'
)
PARTITIONED BY (dt)
LOCATION 's3://lakehouse/hudi/demo_db/hudi_mor';
```

关键属性说明。

| 属性 | 作用 |
| --- | --- |
| type | cow 或 mor |
| primaryKey | 记录键，决定更新落到哪个文件组 |
| preCombineField | 同键多条时的取舍字段，取最大值 |
| hoodie.table.name | 表名，须与 CREATE 的表名一致 |

注意：primaryKey 要选稳定且分布均匀的列。选错会导致热点文件组。

## 四、写入与 upsert

### 4.1 插入

```
INSERT INTO hudi_cow VALUES
  (1, 'apple',  5.00, TIMESTAMP'2026-11-17 09:00:00', '2026-11-17'),
  (2, 'banana', 3.00, TIMESTAMP'2026-11-17 09:05:00', '2026-11-17');
```

预期：SELECT count(*) 返回 2。

### 4.2 upsert

Hudi 用 MERGE INTO 做 upsert。

```
MERGE INTO hudi_cow AS t
USING (
  SELECT 1 AS id, 'apple' AS name, 6.00 AS price,
         TIMESTAMP'2026-11-17 10:00:00' AS updated_at,
         '2026-11-17' AS dt
) AS s
ON t.id = s.id
WHEN MATCHED THEN UPDATE SET *
WHEN NOT MATCHED THEN INSERT *;
```

预期：id 为 1 的行 price 变成 6.00，总数仍为 2。

### 4.3 删除

```
DELETE FROM hudi_cow WHERE id = 2;
```

### 4.4 更新预合并字段

同键多条记录同时到达时，preCombineField 值大的胜出。

这个机制保证乱序到达时，旧更新不会覆盖新更新。

## 五、四种查询

### 5.1 快照查询

```
SELECT * FROM hudi_cow;
```

读最新已完成提交的状态。

### 5.2 Read Optimized 查询

```
SELECT * FROM hudi_mor_read_optimized;
```

建表时另建一个 _ro 后缀表，或设置查询选项。只读基础文件，速度最快。

### 5.3 增量查询

```
SELECT * FROM hudi_cow
WHERE _hoodie_commit_time > '20261117090000';
```

预期：只返回该提交时间之后发生变化的记录。

### 5.4 时间点查询

```
SELECT * FROM hudi_cow TIMESTAMP AS OF '2026-11-17 09:30:00';
```

## 六、表服务

### 6.1 同步 compaction

写 MOR 表时带上 compaction 配置。

```
SET hoodie.compact.inline=true;
SET hoodie.compact.inline.max.delta.commits=5;
```

含义：每 5 次 deltacommit 后触发一次 compaction。

### 6.2 异步 compaction

生产环境用 Hudi 的 HoodieCompactor 工具单独跑，避免阻塞写入。

### 6.3 clean 与 archive

```
SET hoodie.clean.automatic=true;
SET hoodie.cleaner.commits.retained=10;
SET hoodie.archive.automatic=true;
```

含义：保留最近 10 次提交的文件切片，更早的清理掉。

## 七、使用案例

### 7.1 场景背景

订单表持续更新。要求行级 upsert，下游按增量方式消费，不重复扫全表。

### 7.2 数据流

```
MySQL binlog
  └─ Flink CDC 捕获变更
       └─ Hudi MOR 表 s3://lakehouse/hudi/demo_db/orders/
            ├─ 快照查询看最新状态
            └─ 增量查询供下游 ETL
```

### 7.3 落地步骤

① 建 MOR 表，开启 inline compaction。

```
CREATE TABLE orders (
  order_id BIGINT,
  status STRING,
  amount DECIMAL(18,2),
  updated_at TIMESTAMP
) USING hudi
TBLPROPERTIES (
  type = 'mor',
  primaryKey = 'order_id',
  preCombineField = 'updated_at',
  hoodie.table.name = 'orders',
  hoodie.compact.inline = 'true',
  hoodie.compact.inline.max.delta.commits = '5'
)
LOCATION 's3://lakehouse/hudi/demo_db/orders';
```

② 用 Flink CDC 作业持续写入。

③ 查当前状态。

```
SELECT status, count(*) FROM orders GROUP BY status;
```

④ 增量消费。记录上次读到的 commit time，下次只读之后的变更。

```
SELECT * FROM orders WHERE _hoodie_commit_time > '<LAST_COMMIT_TIME>';
```

⑤ 在 MinIO 上确认文件分层。

```
docker run --rm --network whd-net --entrypoint /bin/sh minio/mc:<MC_TAG> -c '
  mc alias set lake http://minio:9000 "<MINIO_AK>" "<MINIO_SK>" &&
  mc ls --recursive lake/lakehouse/hudi/demo_db/orders/ | head -40
'
```

预期：看到 .parquet 基础文件与 .log 日志文件并存。

### 7.4 验证判据

| 项 | 判据 |
| --- | --- |
| 写入 | SELECT count(*) 与源表一致 |
| upsert | 改源表一行，湖上值同步变化 |
| 增量 | 增量查询只返回变更记录 |
| 落盘 | MinIO 上有 parquet 与 log 文件 |

### 7.5 踩坑表

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 报 ClassNotFoundException: KryoSerializer | 未设 spark.serializer | 加 KryoSerializer 配置 |
| MERGE INTO 语法不识别 | 缺 SessionExtension | 加 HoodieSparkSessionExtension |
| 写入极慢，个别文件组巨大 | primaryKey 倾斜 | 换成分布均匀的键或用 Bucket 索引 |
| MOR 查询越来越慢 | 日志文件堆积 | 开 inline compaction 或单独跑 compactor |
| No FileSystem for scheme s3a | 缺 hadoop-aws | 补 hadoop-aws 与 aws-java-sdk-bundle |
| SignatureDoesNotMatch | 未开 path-style | 设 fs.s3a.path.style.access=true |
| 增量查询返回空 | commit time 写错 | 用 SELECT max(_hoodie_commit_time) 核对 |

## 八、本篇小结

① Hudi 用法是加 bundle、配两项 Spark 配置、建表、MERGE upsert。

② primaryKey 决定更新落到哪个文件组，选错会造成热点。

③ preCombineField 保证乱序到达时新值胜出。

④ COW 写慢读快，MOR 写快读慢，需 compaction 兜底。

⑤ 增量查询让下游只消费变化部分，是 CDC 场景的核心能力。

# 四种开放表格式总介绍

> **一句话结论**：Iceberg、Hudi、Delta Lake、Paimon 都是开放表格式。它们不是服务，不独立部署。它们定义数据文件如何组织、元数据如何提交、引擎如何并发读写。对象存储统一用 MinIO，四者都把文件落在 s3://lakehouse/ 下。

> **本文解决什么**：讲清四种表格式各自的定位与差异，给出可执行的选型依据。
>
> **适用谁**：已装好 MinIO、准备在湖上做批流读写或增量更新的人。
>
> **读完能做什么**：看懂四者的取舍，按场景选定一种，再进入对应目录读原理与使用。

---

## 一、什么是表格式

表格式是数据文件与计算引擎之间的一层协议。

它管三件事。

① 数据如何组织。定义文件布局、分区方式、列存格式。

② 元数据如何提交。记录每次写入产生的快照与文件清单。

③ 引擎如何并发。提供 ACID 与时间旅行，避免读写互相破坏。

表格式本体以 jar 交付。它挂进 Flink、Spark 的 classpath 才能工作。

原始文件存对象存储。本文统一用 MinIO，桶名 lakehouse。

四者的 warehouse 前缀规划如下。

```
s3://lakehouse/iceberg/
s3://lakehouse/hudi/
s3://lakehouse/delta/
s3://lakehouse/paimon/
```

## 二、四者定位对比

| 项 | Iceberg | Hudi | Delta Lake | Paimon |
| --- | --- | --- | --- | --- |
| 发起方 | Netflix | Uber | Databricks | 阿里巴巴 |
| 核心定位 | 引擎中立的分析表 | 增量更新与流式入湖 | Spark 生态湖仓 | 流式湖仓主键表 |
| 元数据模型 | 快照加 manifest 树 | Timeline 加文件组 | DeltaLog 加 checkpoint | snapshot 加 manifest |
| 更新机制 | COW 或 MOR | COW 或 MOR | COW 加删除向量 | LSM 加 bucket |
| 主键能力 | 无原生主键 | 记录键加分区 | 无原生主键 | 原生主键表 |
| 主力引擎 | Spark / Flink / Trino / Doris | Spark / Flink | Spark | Spark / Flink |
| catalog 实现 | rest / jdbc / hms / glue / hadoop | hms / filesystem | hms / Unity Catalog | filesystem / hms / jdbc |
| 典型场景 | 大规模分析表 | CDC 入湖近实时 | Spark 数仓 upsert | Flink 写湖 Doris/StarRocks 回查 |

四者都能跑在 MinIO 上。差异在更新机制与主力引擎，不在存储底座。

### 2.1 四个概念的关系

四者本体都是 jar。它们不是服务，没有常驻进程。jar 挂进引擎的 classpath 才工作。

容易混淆的是元数据模型、Catalog 与更新机制。三者职责不同。

| 概念 | 回答什么 | 由谁决定 |
| --- | --- | --- |
| 元数据模型 | 快照与文件清单怎么组织 | 表格式自身 |
| Catalog | 表名去哪里找当前元数据 | 可插拔实现 |
| 更新机制 | 一次更新产生哪些文件 | 写路径设计 |

更新机制不由 Catalog 决定。同一张 Iceberg 表，Catalog 从 REST 换成 JDBC，COW 仍是 COW。Catalog 只负责入口映射，换实现不改数据布局。

更新机制由元数据模型与写路径决定。Iceberg 保留旧快照，所以更新写新文件。Hudi 用文件组加索引，所以更新能定位到具体文件组。Delta 用事务日志加删除向量，所以行删除不必重写 Parquet。Paimon 用 LSM 加 bucket，所以更新先进内存再刷盘。

### 2.2 Catalog 的三种落地

Catalog 记录表名到当前元数据的映射。它是表格式规范的一部分，不是可选的第三方件。

| 落地方式 | 是否要独立服务 | Iceberg 例子 |
| --- | --- | --- |
| 目录约定 | 不要 | hadoop，靠 warehouse 下的固定路径 |
| 外部存储 | 不要新增容器，复用已有服务 | jdbc，元数据表落在现有 PostgreSQL |
| 独立服务 | 要 | rest、hms，需部署服务 |

本机选择 JDBC 型。它复用现有 PostgreSQL，靠数据库事务保证提交原子性，不新增容器。Hadoop 型更省事，但 S3 没有原子 rename，并发写有风险。

## 三、共性原理

四种表格式共享六项能力。理解这六项，再看任一格式都会快。

### 3.1 快照隔离

每次提交生成一个新快照。读者锁定一个快照读取，不受后续写入影响。

写者创建新元数据文件，最后做一次原子替换。这就是乐观并发控制。

### 3.2 ACID 事务

提交以元数据文件的原子写为界。写失败就留下半途文件，但不改当前快照。

读者只看已提交的快照，因此看不到中间态。

### 3.3 时间旅行

历史快照保留后，读方能按快照号或时间戳读旧数据。

这依赖快照与数据文件都不被立刻删除。

### 3.4 schema 演进

表格式把 schema 存进元数据。加列、改列类型不必重写全部数据文件。

分区演进与排序演进同理，只影响新写入的文件。

### 3.5 元数据分层

快照指向文件清单，文件清单指向数据文件。分层让大表不必遍历全部文件。

Iceberg 分三层，Paimon 与 Delta 也采用类似的分层思路。

### 3.6 后台维护

小文件会拖慢查询。四者都提供合并动作。

Hudi 叫 compaction 与 clustering，Delta 叫 OPTIMIZE，Paimon 叫 compaction，Iceberg 用 rewrite 过程。

## 四、选型决策

按场景选，不按热度选。

| 场景 | 首选 | 理由 |
| --- | --- | --- |
| 多引擎共读同一张表 | Iceberg | catalog 可插拔，引擎支持最广 |
| CDC 增量入湖、近实时可见 | Hudi 或 Paimon | 索引与主键支撑行级 upsert |
| 已重度使用 Spark | Delta Lake | 与 Spark SQL、Structured Streaming 一体 |
| 已重度使用 Flink | Paimon | 主键表与 checkpoint 提交原生支持 |
| 需要 Doris 只读回查对账 | Paimon | Doris 内置 Paimon 依赖，链路最短 |
| 需要 REST Catalog 统一管理 | Iceberg | REST 规范最成熟 |
| 本地学习、只装 MinIO | Paimon | 本机已装齐 jar，可直接跑通 |

选湖表格式时，还要看 OLAP 引擎能否直接写入。这决定了要不要多维护一个 Flink 或 Spark。

### 4.1 OLAP 引擎写入能力

| 表格式 | Doris 写入 | StarRocks 写入 | 写入主力 |
| --- | --- | --- | --- |
| Iceberg | 支持，有完整 DML | 支持，3.1 起仅 Parquet | Flink、Spark 或两者 |
| Hudi | 只读 | 只读 | Flink、Spark |
| Delta Lake | 只读 | 只读 | Spark、Flink |
| Paimon | 只读 | 只读，本机 4.1.7 实测 | Flink |

四种里只有 Iceberg 能被 Doris 或 StarRocks 写入。

Doris 对 Iceberg 的写入最完整。INSERT INTO、INSERT OVERWRITE、CTAS 都支持。UPDATE、DELETE、MERGE INTO 从 4.1.0 起实验支持，要求 format-version ≥ 2。写入还看 catalog 类型：hms、rest、hadoop 可写，glue、dlf 只读。

StarRocks 从 3.1 起支持向 Iceberg 表 INSERT，只支持 Parquet 格式。

注意：只读不等于不能导数据。两种引擎都能从湖表 SELECT 写回自己的内表。差别只在「能否 INSERT INTO 湖表」。

其余三种的写入依赖流引擎。Hudi 靠索引与 Timeline，Delta 靠事务日志，Paimon 依赖 checkpoint 提交。这些机制要流处理引擎承接，OLAP 引擎不实现。

选型还要看四个维度：数据规模、更新频率、共享范围、合规要求。

四项都低时，轻量方案够用。任一项高，表格式加对象存储就值得投。

## 五、对象存储统一约定

四篇基本使用文档都按以下约定写，不再重复解释。

| 项 | 取值 |
| --- | --- |
| 对象存储 | MinIO |
| 桶 | lakehouse |
| S3 API 地址 | http://minio:9000 |
| 控制台地址 | http://localhost:9001 |
| 凭据 | 占位符 &lt;MINIO_AK&gt; 与 &lt;MINIO_SK&gt; |
| path-style | 开启 |
| 容器内 DNS 别名 | minio |

控制台端口 9001 只给浏览器。S3 客户端一律指向 9000。

## 七、本篇小结

① 四者都是开放表格式，本体是 jar，不是独立服务。

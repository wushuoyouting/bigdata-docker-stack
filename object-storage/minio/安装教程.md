# MinIO 安装

---

## 步骤 0：装前复核（只读）

```bash
docker version --format 'Server {{.Server.Version}}'
docker network inspect whd-net --format '{{range .Containers}}{{.Name}} | {{.IPv4Address}}{{println}}{{end}}'
lsof -nP -iTCP:9000 -iTCP:9001 -sTCP:LISTEN || echo '9000/9001 空闲'
docker ps -a --filter name=minio --format '{{.Names}}\t{{.Status}}'
docker images --format '{{.Repository}}:{{.Tag}}' | grep -i minio || echo '本地无镜像'
docker ps --filter name=doris-be --format '{{.Names}}\t{{.Status}}'
```

| 检查项 | 期望 | 不满足时 |
| --- | --- | --- |
| Docker Server | 有版本输出 | 先启动 Docker Desktop |
| whd-net | 已存在 172.30.0.0/24 | 按 doris/安装教程.md 创建；不要删了重建 |
| 9000 / 9001 | 空闲 | 冲突时只改 -p 左侧宿主端口 |
| 同名容器 | 不存在 | 有残留按步骤 5 docker rm -f minio 清理 |
| doris-be | Up | 否则步骤 4 的 BE 视角验证无法做 |

## 步骤 1：准备参数

创建 /Users/wenhuadong/docker/object-storage/minio/.env（权限 600），内容：

```dotenv
MINIO_TAG=RELEASE.2025-02-07T23-21-09Z
MINIO_AK=<随机字符串，≥8 位>
MINIO_SK=<随机字符串，≥8 位，且与 AK 不同>
```

> 安装与验收只需要上面 3 个变量。步骤 4 的连通性验证用 busybox / curl 临时容器，**不需要 mc 镜像**；mc 是可选客户端，见 使用教程.md。

加载并确认：

```bash
set -a
. /Users/wenhuadong/docker/object-storage/minio/.env
set +a
chmod 600 /Users/wenhuadong/docker/object-storage/minio/.env
DATA=/Users/wenhuadong/docker/object-storage/minio/data
echo "MINIO_TAG=$MINIO_TAG  AK 已加载=${MINIO_AK:+yes}"
```

| 变量 | 规则 |
| --- | --- |
| MINIO_TAG | 固定 RELEASE.YYYY-MM-DDTHH-MM-SSZ，不用 latest |
| MINIO_AK / MINIO_SK | 随机、≥8 位、不用默认值、不含引号与 shell 特殊字符 |
| DATA | 写在命令里，不进 .env：/Users/wenhuadong/docker/object-storage/minio/data |

## 步骤 2：启动并等待就绪

```bash
mkdir -p "$DATA"

# 拉取镜像（本机为 arm64，需显式指定 amd64 架构；本地已有可跳过此步）
docker pull --platform linux/amd64 "minio/minio:$MINIO_TAG"

docker run -d \
  --platform linux/amd64 \
  --name minio \
  --network whd-net \
  --network-alias minio \
  --ip 172.30.0.3 \
  -p 9000:9000 \
  -p 9001:9001 \
  -e MINIO_ROOT_USER="$MINIO_AK" \
  -e MINIO_ROOT_PASSWORD="$MINIO_SK" \
  -v "$DATA:/data" \
  "minio/minio:$MINIO_TAG" \
  server /data --console-address ":9001"

# 等健康接口（最多 2 分钟）
for i in $(seq 1 24); do
  code=$(curl -s -o /dev/null -w '%{http_code}' \
    http://localhost:9000/minio/health/live 2>/dev/null || true)
  [ "$code" = "200" ] && { echo "MinIO 就绪"; break; }
  echo "第 ${i} 次：还没就绪，等 5s"; sleep 5
done

docker ps --filter name=minio --format '{{.Names}}\t{{.Status}}\t{{.Ports}}'
docker logs --tail 50 minio
```

| 参数 | 为什么 |
| --- | --- |
| --platform linux/amd64 | 本机 arm64 跑 amd64 镜像需模拟；换 arm64 原生镜像时删掉此行 |
| --network whd-net --network-alias minio | 容器内统一用 http://minio:9000 互访 |
| --ip 172.30.0.3 | 固定 IP（全局基线）；重建必带，漏带会动态漂移 |
| -p 9000:9000 | **S3 API**，Doris / Flink / mc 全走它 |
| -p 9001:9001 | **Console**，只给浏览器；严禁写进任何 S3 配置 |
| MINIO_ROOT_USER/PASSWORD | 组件级根凭据，首次启动即为随机值 |
| -v "$DATA:/data" | 对象数据持久化；绝对路径，删容器不丢 |
| server /data --console-address ":9001" | 不写则 Console 随机端口，-p 9001 白映射 |

| 不通过 | 排查 |
| --- | --- |
| 容器起不来 | docker logs minio：口令过短、卷权限、Address already in use |
| health 一直非 200 | 镜像 tag 不存在 / 拉取失败；df -h 查磁盘 |
| exec format error | 架构不对，检查 --platform |

## 步骤 3：初始化

1. 浏览器打开 <http://localhost:9001>，用 .env 里的 MINIO_AK / MINIO_SK 登录。
2. 确认能看到 Console 首页即可；**不建桶、不建 Access Keys**（凭据启动已是随机值）。
3. 如需轮换口令，改 .env 后 docker rm -f minio 并按步骤 2 重启（数据卷保留）。

## 步骤 4：逐项验收

```bash
# ① 本机 health
curl -fsS http://localhost:9000/minio/health/live -o /dev/null -w '%{http_code}\n'

# ② Console 登录页可达（登录动作在浏览器做，见步骤 3）
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:9001/login

# ③ 同网络容器 DNS + 端口
docker run --rm --network whd-net busybox:1.36 sh -c 'nslookup minio && nc -zv minio 9000'
docker run --rm --network whd-net busybox:1.36 \
  wget -qO- http://minio:9000/minio/health/live && echo OK

# ④ Doris BE 视角（必做：S3 数据实际由 BE 下载）
docker exec doris-be sh -c 'getent hosts minio || nslookup minio'
docker exec doris-be bash -c 'echo > /dev/tcp/minio/9000 && echo OK'
docker exec doris-be sh -c 'wget -qO- http://minio:9000/minio/health/live && echo OK'

# ⑤ stop/start 后数据卷保留
ls -A "$DATA" | head
docker stop minio && docker start minio
curl -fsS http://localhost:9000/minio/health/live -o /dev/null -w '%{http_code}\n'
ls -A "$DATA" | head

# 网络全貌
docker network inspect whd-net \
  --format '{{range .Containers}}{{.Name}} | {{.IPv4Address}}{{println}}{{end}}'
```

| # | 通过标准 |
| --- | --- |
| ① | 200 |
| ② | Console 登录页 200，且浏览器能用 .env 凭据登录 |
| ③ | minio 解析出 IP、nc open、HTTP 200 |
| ④ | doris-be 能解析 minio，/dev/tcp 或 wget 输出 OK |
| ⑤ | stop/start 前后 minio/data 下都有内容、health 仍 200 |
| 网络 | 成员新增 minio，固定 IP 172.30.0.3（全局基线）；.2/.3/.4 无漂移 |

> 只做 ① 就宣布可用是错的：S3 Load 由 **BE** 下载，**必做 ④**。若 BE 镜像既无 wget 也无 bash，用 ③ 的同网络临时容器替代，结论等价。

## 步骤 5：停止重来

```bash
docker stop minio && docker start minio          # 首选：数据、凭据、可写层全保留
docker logs -f minio --tail 100

# 完全重来（保留数据）：删容器后重跑步骤 2
docker rm -f minio                              # 不加 -v

# 连数据一起清空（谨慎）
docker rm -f minio
rm -rf /Users/wenhuadong/docker/object-storage/minio/data/*
mkdir -p /Users/wenhuadong/docker/object-storage/minio/data
```

| 动作 | 数据安全 |
| --- | --- |
| stop / start | 全保留 |
| docker rm -f minio | minio/data 是 bind mount，保留 |
| rm -rf .../data/* | 只有显式执行才清数据 |

> 单独停 / 删 minio 不影响已装的 Doris、DS；whd-net 不会被删。

## 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| BE 侧 UnknownHost: minio / Connection refused | 容器没接 whd-net，或 endpoint 写 localhost | endpoint 用 http://minio:9000；按 ④ 核查网络 |
| 本机 curl 通但容器不通 | 验证视角错了 | 必做 ④ |
| 把 9001 写进 s3.endpoint | Console 口不是 S3 API | 改 9000 |
| 容器起不来 | MINIO_ROOT_PASSWORD 太短 | 换 ≥8 位 |
| exec format error | 拉到 amd64 专属镜像 | 检查 --platform |
| 挂卷后反复重启 | 目录权限 / 磁盘满 | docker logs minio；df -h |
| 删容器后以为数据清空了 | 数据卷还在 | 只有显式 rm -rf 才清 |

## 小结

1. 一条 docker run，不建桶、不上传、不建 key。
2. 9000 / 9001 严禁混用；固定 release tag；卷用绝对路径；凭据只留本机 .env。
3. BE 视角是必做判据，本机通不能代替容器内通。
4. 验收 5 条逐项 PASS，含 stop/start 持久化；装完把实际 tag 与变量名登记到 组件手册。

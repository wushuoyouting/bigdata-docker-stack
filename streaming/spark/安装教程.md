> 官方中文文档：https://spark.apache.org/docs/latest/

> **本文范围**：装一套能独立运行的 Spark standalone 集群。一个容器同时跑 Master、Worker 与 History Server。客户端从同一个容器进入。装完验到 Master UI 有一个存活 Worker、SQL 能出结果、历史服务能打开。不接 MinIO、不接 Paimon、不挂 connector jar。

# Spark 安装教程

> **一句话结论**：一个 apache/spark 容器，用镜像自带的 sbin 脚本起 Master、Worker 与 History Server。对外只映射 18083 与 18084 两个端口。验收三条：Master UI 有 1 个存活 Worker，SQL 返回结果，History Server 能打开。

> **本文解决什么**：本机需要一套独立 Spark 做 SQL 练习与作业提交。本文给出单容器安装法，不用分角色起多个容器。
>
> **适用谁**：已装 Docker Desktop、会用基本 docker 命令、想在本机跑 Spark SQL 的用户。
>
> **读完能做什么**：一条命令拉起集群、逐条验收、停止后原样重建、处理常见启动故障。

> **核对时点**：2026-11-27。macOS arm64 与 Docker Desktop。whd-net 已存在，固定 IP 表中 .21 未被占用。宿主 18083、18084 空闲。
>
> **镜像状态**：本机镜像源对 apache/spark 返回限流与拒绝，3.5.10 的拉取未完成。3.5.3 曾实测为 linux/arm64 原生镜像、JDK 11。3.5.10 属同一标签系列。拉取失败时按本文的回退办法处理，命令与配置不用改。

## 一、适用范围

| 项 | 取值 |
| --- | --- |
| Spark 版本 | 3.5.10，回退 3.5.8 |
| 基础镜像 | apache/spark:3.5.10 |
| 部署形态 | 单容器 standalone |
| 容器内角色 | Master、Worker、History Server |
| 操作系统 | macOS arm64 与 Docker Desktop |
| 内存下限 | 宿主 16G，容器内实占约 4G |
| 网络 | whd-net，固定 IP 172.30.0.21 |
| 宿主端口 | 18083 给 Master UI，18084 给 History Server |

**为什么不装 Spark 4**：Spark 4 要求 Java 17 与 Scala 2.13。本仓库 Flink 1.20 与 Paimon 1.3.1 的基线是 Java 11 加 Scala 2.12。3.5 系列沿用同一基线，jar 可复用。

**为什么用 standalone 而不是 local**：local 模式只有线程池，看不到 Master 与 Worker 的协作。standalone 能看清注册、派发、执行三段。两种模式在同一个容器里都可用。

## 二、安装前复核

```bash
lsof -nP -iTCP:18083 -sTCP:LISTEN || echo '18083 空闲'
lsof -nP -iTCP:18084 -sTCP:LISTEN || echo '18084 空闲'

docker ps -a --filter name=spark \
  --format '{{.Names}}\t{{.Status}}\t{{.Ports}}'

docker network inspect whd-net \
  --format '{{range .Containers}}{{.Name}} | {{.IPv4Address}}{{println}}{{end}}'

docker image inspect apache/spark:3.5.10 \
  --format '{{.Os}}/{{.Architecture}}' 2>/dev/null || echo '镜像未拉取'

ls -ld /Users/wenhuadong/docker/streaming/spark/{conf,jars,events,warehouse} 2>/dev/null
```

| 检查项 | 期望 | 不满足时 |
| --- | --- | --- |
| 18083 | 空闲 | 换 18085 并同步改两处映射 |
| 18084 | 空闲 | 换 18086 并同步改配置里的历史端口 |
| 旧容器 | 不存在 spark | 先 docker rm -f spark |
| 固定 IP | 172.30.0.21 未被占用 | 按 IP 表顺延取下一个空号并登记 |
| 镜像 | linux/arm64 | amd64 时加 --platform linux/amd64 |
| 四个目录 | 存在且当前用户可写 | 用 mkdir -p 创建 |

> **注意**：固定 IP 必须与登记表一致。漏带 --ip 会让容器在重建时拿到动态地址，进而抢占其他组件的静态地址。

## 三、安装步骤

### 3.1 拉取镜像

```bash
docker pull apache/spark:3.5.10
```

预期输出：若干层下载完成，最后一行为 Image is up to date 或 Pull complete。

镜像源限流时按顺序处理。先重试一次，再换镜像源前缀。

```bash
docker pull docker.m.daocloud.io/apache/spark:3.5.10
```

仍拉不到时改用 3.5.8。本文命令里的版本号只有这一处需要改。

```bash
docker pull apache/spark:3.5.8
```

> 本机 Docker 已配置三个镜像源。返回 429 表示限流，返回 denied 表示该源不放行该标签。两种都不属于配置错误，不需要改 Docker 守护进程配置。

### 3.2 创建挂载目录

```bash
mkdir -p /Users/wenhuadong/docker/streaming/spark/{conf,jars,events,warehouse}
chmod 777 /Users/wenhuadong/docker/streaming/spark/events \
          /Users/wenhuadong/docker/streaming/spark/warehouse
```

预期输出：命令无回显，四个目录存在。

| 目录 | 挂载点 | 内容 |
| --- | --- | --- |
| conf | /opt/spark/conf/spark-defaults.conf | 集群配置，只读挂载 |
| jars | /opt/spark/custom-jars | 扩展 jar，启动时软链进 /opt/spark/jars |
| events | /opt/spark/events | 事件日志，History Server 读取 |
| warehouse | /opt/spark/warehouse | 默认库目录，建表数据落这里 |

> 容器内进程以 spark 用户运行，宿主目录属主不是它。events 与 warehouse 要给写权限，否则历史服务启动失败、建表报权限错误。

### 3.3 写入配置

配置从宿主挂载进容器。容器重建后配置不丢。

```bash
cat > /Users/wenhuadong/docker/streaming/spark/conf/spark-defaults.conf <<'EOF'
spark.master                     spark://spark:7077

spark.eventLog.enabled           true
spark.eventLog.dir               file:///opt/spark/events
spark.history.fs.logDirectory    file:///opt/spark/events
spark.history.ui.port            18080

spark.sql.warehouse.dir          file:///opt/spark/warehouse
spark.sql.shuffle.partitions     8
spark.sql.adaptive.enabled       true

spark.driver.memory              1g
spark.driver.host                spark
spark.executor.memory            2g
spark.executor.cores             2
spark.executor.instances          1
spark.cores.max                  2

spark.master.ui.port             8080
spark.ui.reverseProxy            true
spark.ui.reverseProxyUrl         http://localhost:18083
EOF
```

| 参数 | 取值 | 作用 |
| --- | --- | --- |
| spark.master | spark://spark:7077 | 客户端默认提交到本集群 |
| spark.eventLog.enabled | true | 记录应用事件，供历史服务回放 |
| spark.eventLog.dir | file:///opt/spark/events | 事件文件落在挂载目录 |
| spark.history.fs.logDirectory | file:///opt/spark/events | 历史服务从同一目录读取 |
| spark.history.ui.port | 18080 | 历史服务容器内端口 |
| spark.sql.warehouse.dir | file:///opt/spark/warehouse | 建表数据的默认位置 |
| spark.sql.shuffle.partitions | 8 | 小数据量下减少分区数 |
| spark.sql.adaptive.enabled | true | 运行时按数据量调整分区与连接策略 |
| spark.executor.memory | 2g | 单个执行器堆内存 |
| spark.executor.cores | 2 | 单个执行器占用的核数 |
| spark.cores.max | 2 | 单应用最多申请的核数 |
| spark.driver.host | spark | 执行器按容器主机名回连 Driver |
| spark.ui.reverseProxy | true | Master 代理 Worker 与应用界面 |
| spark.ui.reverseProxyUrl | http://localhost:18083 | 代理链接按宿主地址重写 |

> spark.driver.host 必须写容器主机名。写 localhost 时执行器回连自己，任务一直卡在注册阶段。

### 3.4 启动容器

```bash
docker run -d \
  --name spark \
  --hostname spark \
  --network whd-net \
  --network-alias spark \
  --ip 172.30.0.21 \
  -p 18083:8080 \
  -p 18084:18080 \
  -e SPARK_DAEMON_MEMORY=512m \
  --entrypoint bash \
  -v /Users/wenhuadong/docker/streaming/spark/conf/spark-defaults.conf:/opt/spark/conf/spark-defaults.conf:ro \
  -v /Users/wenhuadong/docker/streaming/spark/jars:/opt/spark/custom-jars:ro \
  -v /Users/wenhuadong/docker/streaming/spark/events:/opt/spark/events \
  -v /Users/wenhuadong/docker/streaming/spark/warehouse:/opt/spark/warehouse \
  apache/spark:3.5.10 \
  -c 'for j in /opt/spark/custom-jars/*.jar; do
        [ -e "$j" ] || continue
        ln -sf "$j" "/opt/spark/jars/$(basename "$j")"
      done
      /opt/spark/sbin/start-master.sh
      /opt/spark/sbin/start-worker.sh spark://spark:7077 --cores 2 --memory 3g
      /opt/spark/sbin/start-history-server.sh
      tail -f /dev/null'
```

预期输出：返回一串容器 ID。docker ps 显示容器 Up。

| 参数 | 作用 |
| --- | --- |
| --hostname spark | 容器主机名，执行器按此名回连 |
| --ip 172.30.0.21 | 固定地址，重建不漂移 |
| -p 18083:8080 | 宿主访问 Master UI，避开默认 8080 |
| -p 18084:18080 | 宿主访问历史服务 |
| -e SPARK_DAEMON_MEMORY=512m | 三个后台进程各限 512m |
| --entrypoint bash | 绕过镜像入口，按脚本起三个角色 |
| conf 挂载 | 配置来自宿主，容器重建不丢 |
| custom-jars 挂载 | 扩展依赖来自宿主，启动时软链进 jars |
| events 与 warehouse 挂载 | 数据落宿主，删容器不丢 |
| --memory 3g | Worker 可分配的总额，须大于执行器内存 |
| tail -f /dev/null | 保持前台进程不退出 |

> 不直接挂载 /opt/spark/jars。直接挂会覆盖镜像自带的 Spark 核心 jar。启动脚本只把扩展 jar 逐个软链进去，与 Flink 的做法一致。

### 3.5 等待就绪

```bash
for i in $(seq 1 20); do
  curl -fsS http://localhost:18083/json/ -o /dev/null 2>/dev/null && {
    echo 'Master 就绪'; break
  }
  echo "第 ${i} 次：未就绪，等 3s"; sleep 3
done
```

预期输出：最后一行显示 Master 就绪。

Worker 注册比 Master 启动晚几秒。就绪后再等一下，让 Worker 完成注册。

```bash
sleep 5
curl -fsS http://localhost:18083/json/ | grep -o '"aliveworkers" : [0-9]*'
```

预期输出：aliveworkers 为 1。

## 四、启动后检查

### 4.1 三个进程

```bash
docker exec spark bash -c 'jps -l | grep -E "Master|Worker|HistoryServer"'
```

预期输出：三行，分别含 SparkSubmit 与 Master、Worker、HistoryServer 字样。

### 4.2 事件目录

```bash
ls -l /Users/wenhuadong/docker/streaming/spark/events
```

预期输出：首次启动为空。执行过一次应用后出现 application 开头的目录或事件文件。

### 4.3 停止与重来

```bash
docker stop spark
docker start spark

docker logs spark --tail 50
```

| 动作 | 数据影响 |
| --- | --- |
| stop 与 start | 容器可写层、events、warehouse 全保留 |
| docker rm -f spark | events 与 warehouse 是绑定挂载，保留 |
| docker rm -v spark | 禁止，会删命名卷 |
| rm -rf warehouse/* | 只有明确重置库表时才做 |

> 容器重建后需要重新执行一次启动容器的命令。配置、事件、表数据都在宿主目录里，不会丢。

## 六、故障速查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 拉取报 429 | 镜像源限流 | 等几分钟重试，或换另一个源前缀 |
| 拉取报 denied | 该源不放行此标签 | 换源，或改用 3.5.8 |
| 容器起后立即退出 | 启动脚本报错 | docker logs spark 看首行错误 |
| Master UI 打不开 | 端口冲突或进程未起 | 查 docker ps 与 jps 输出 |
| aliveworkers 为 0 | Worker 未注册 | 看 Worker 日志中 spark://spark:7077 是否可解析 |
| 执行器一直起不来 | Worker 内存小于执行器申请 | 调大 --memory，或调小 executor.memory |
| 应用卡在注册阶段 | driver.host 写成 localhost | 改成容器主机名 spark |
| 历史服务 500 | events 目录不可写 | 给 events 目录 777 权限后重启容器 |
| 建表报权限错误 | warehouse 目录不可写 | 给 warehouse 目录 777 权限后重建表 |
| 点应用链接打不开 | 未开反向代理 | 确认 reverseProxy 两项配置已生效 |
| exec format error | arm64 上用了 amd64 镜像 | docker run 加 --platform linux/amd64 |
| 端口被占 | 旧容器或本地进程占用 | lsof 查占用，改宿主端口或停旧进程 |

## 七、小结

1. 只起一个容器。Master、Worker、History Server 由 sbin 脚本在同一容器内启动。
2. 客户端不是服务。spark-sql、spark-shell、spark-submit 都是镜像自带命令，用 docker exec 进入调用。
3. 对外只映射 18083 与 18084。7077 与 4040 留在容器内，界面通过反向代理访问。
4. 固定 IP 取 172.30.0.21，与登记表一致。重建必须带 --ip。
5. 配置、扩展 jar、事件、表数据全部挂载在宿主。删容器不影响这四类数据。

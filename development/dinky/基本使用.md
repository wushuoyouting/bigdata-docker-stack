# Dinky 基本使用

> **一句话结论**：Dinky 的用法分三块。作业开发用查询看 SELECT 结果，运维中心看运行记录，History Server 查已完成作业。历史查询要先用归档目录，否则页面空白。

> **本文解决什么**：装完 Dinky 后怎么登录、怎么建作业、怎么开启历史作业查询、8082 端口怎么用。
>
> **适用谁**：已完成 Dinky 安装、集群注册正常、需要日常查询 Flink 作业的用户。
>
> **读完能做什么**：从界面建并执行作业，配置归档目录让历史查询有数据，判断 8082 要不要映射，排查历史页空白。

> **核对时点**：2026-11-18。macOS arm64 / Docker Desktop。本机 Dinky 容器已 Up，8888 映射正常。内置 History Server 已开启，容器内 8082 已监听。Flink 仍是 flink-jobmanager 与 flink-taskmanager 两个容器，未配置归档目录。

## 一、入口总览

| 入口 | 地址 | 用途 |
| --- | --- | --- |
| Dinky 首页 | http://localhost:8888 | 登录、作业开发、运维中心 |
| Flink Dashboard | http://localhost:8081 | 看运行中作业、TM 状态 |
| Dinky 内置 History Server | 容器内 http://localhost:8082 | 查已完成作业，由 Dinky 页面调用 |

> 8082 跑在 Dinky 容器内，不是 Flink 容器。Dinky 页面自己调用它，不需要从宿主机直接访问。当前容器只映射 8888，8082 未映射，这是正常的。

## 二、首次登录与集群状态

① 浏览器打开 http://localhost:8888，用初始账号登录。首次登录后立即修改口令。

② 进注册中心 → 集群实例，确认 local-flink-120 状态正常。

③ 点集群行的 Flink Web UI，确认跳到 http://localhost:8081。

| 检查点 | 通过标准 |
| --- | --- |
| 登录 | 进入首页，无掉线 |
| 集群状态 | 状态列显示正常 |
| Web UI 跳转 | 打开 Flink Dashboard |

> 集群地址写 flink-jobmanager:8081，不带协议前缀。这是 Dinky 容器内的服务名，写 localhost 会指向 Dinky 自己。

## 三、作业开发

### 3.1 新建并执行作业

① 数据开发 → 目录 → 右键新建作业。

② 作业类型选 FlinkSQL，名称填 preview_select。

③ 右侧执行模式选 Local，并行度填 1。

④ 填入以下 SQL。

```sql
CREATE TABLE Orders (
  order_number BIGINT,
  price DECIMAL(32,2),
  buyer ROW<first_name STRING, last_name STRING>,
  order_time TIMESTAMP(3)
) WITH (
  'connector' = 'datagen',
  'rows-per-second' = '1',
  'number-of-rows' = '5'
);

SELECT order_number, price, buyer.first_name, order_time FROM Orders;
```

⑤ 点工具条的查询按钮，快捷键 Shift+F9。完成后切到结果页。

预期输出：结果页显示 5 行订单数据，底部显示共 5 条。

> 查询按钮是带放大镜的绿色三角。红色方块是执行作业，两者用途不同。SELECT 看结果用查询，INSERT 提交用执行。

### 3.2 执行模式选择

| 模式 | 在哪里执行 | 用途 |
| --- | --- | --- |
| Local | Dinky 容器内迷你集群 | 调试 SQL、看结果，不占用 TM |
| Standalone | 注册的 flink-jobmanager 集群 | 正式提交作业 |

> Local 查询适合语法调试，作业跑在 Dinky 容器内迷你集群，不落在外部 Flink。要验证作业在集群里跑，用 Standalone 模式执行 INSERT 作业。

### 3.3 插入数据再查询

> **注意**：datagen 只造数，写完查不回来。要插入后查询，用 filesystem connector 建可写表，先 INSERT 落盘，再 SELECT 读回。

① 数据开发 → 新建作业 insert_demo，执行模式选 Local。

② 填入建表与插入语句。

```sql
CREATE TABLE user_score (
  id BIGINT,
  name STRING,
  score INT
) WITH (
  'connector' = 'filesystem',
  'path' = '/tmp/dinky_user_score',
  'format' = 'csv'
);

INSERT INTO user_score VALUES
  (1, 'alice', 90),
  (2, 'bob', 85),
  (3, 'carol', 95);
```

③ 点红色执行按钮。有界 INSERT 会自己结束，状态变 FINISHED 属正常。

④ 再新建作业 query_score，同样选 Local，填入查询语句。

```sql
CREATE TABLE user_score (
  id BIGINT,
  name STRING,
  score INT
) WITH (
  'connector' = 'filesystem',
  'path' = '/tmp/dinky_user_score',
  'format' = 'csv'
);

SELECT * FROM user_score;
```

⑤ 点查询按钮（Shift+F9），结果页显示三行数据。

**为什么要写两次建表**：Flink 默认用内存 Catalog。表定义只在当前作业会话有效，新作业看不到上次建的表。所以查询作业要重新声明同一张表。两次的 path 与字段完全一致，才能读到数据。

| 检查点 | 通过标准 |
| --- | --- |
| INSERT 作业 | 状态 FINISHED，日志无异常 |
| 数据落盘 | Dinky 容器内 /tmp/dinky_user_score 有文件 |
| SELECT 结果 | 显示 alice、bob、carol 三行 |

> Local 模式把数据写在 Dinky 容器的 /tmp。容器重建后数据丢失。要持久化得给 Dinky 挂数据目录。只想快速看几行数据时，用 VALUES 更省事：SELECT * FROM (VALUES (1,'alice'),(2,'bob')) AS t(id,name)。

### 3.4 作业类型与发布

**作业类型**：新建作业时下拉可选。常用的是 FlinkSql，用于写 Flink SQL。FlinkJar 用于提交 jar 包。FlinkSqlEnv 用于放公共 SET 与 DDL。Jdbc Query Type 下的 Mysql、PostgreSql、Doris 等用于直连查询对应数据库。Other Type 下的 Java、Scala、Python 用于对应语言作业。本教程只用 FlinkSql。

**发布**：工具栏的纸飞机按钮。发布后作业锁定，不允许再修改。发布是上线的第一步，用于把开发态作业固化。需要改 SQL 时先撤回发布或新建版本。演示阶段不要点发布，保持作业可编辑。

| 按钮 | 作用 | 演示阶段 |
| --- | --- | --- |
| 查询（Shift+F9） | 执行 SELECT 并回传结果 | 常用 |
| 执行（红色方块） | 提交作业到选定模式 | 提交 INSERT 时用 |
| 发布（纸飞机） | 锁定作业，禁止修改 | 不要点 |
| 保存（软盘） | 保存当前 SQL 与配置 | 常用 |

> 本机 Dinky 1.2.4 没有独立的 SQL CLI 控制台入口。从容器外调 sql-client.sh embedded 会报 Multiple factories 冲突，这是镜像 classpath 问题。日常执行 SQL 用作业开发页面的查询与执行按钮。

## 四、历史作业查询

### 4.1 为什么现在查不到

Dinky 已开启内置 History Server，容器内 8082 已监听，日志出现 Starting Flink History service。但 Flink 未配置归档目录，没有已完成作业的信息可查，所以历史页会空白。

History Server 监控的目录由 Dinky 分配。日志显示当前是 rs:/tmp/flink-job-archive。要让历史查询有数据，必须让 Flink 把已完成作业归档到 History Server 能读到的位置。

> **要不要映射 8082**：不需要。Dinky 前端页面内部调用容器里的 8082。宿主机不访问这个端口。只有直接在宿主机调 History Server REST 接口时才需要加 -p 8082:8082。

### 4.2 配置归档目录

归档目录要同时满足两个条件：Flink JobManager 能写，Dinky 容器能读。本机用宿主机目录绑定挂载实现。

**第一步：建归档目录**

```bash
mkdir -p /Users/wenhuadong/docker/streaming/flink/archive
```

**第二步：给 JobManager 加归档配置**

Flink 的 config.yaml 要加下面两项。当前是双容器架构，配置写在 flink-jobmanager 容器。

```
jobmanager.archive.fs.dir: file:///opt/flink/archive
historyserver.archive.fs.dir: file:///opt/flink/archive
```

**第三步：重建 JobManager 容器并挂载目录**

```bash
FLINK_PROPERTIES="jobmanager.rpc.address: flink-jobmanager
rest.address: 0.0.0.0
rest.bind-address: 0.0.0.0
taskmanager.numberOfTaskSlots: 2
parallelism.default: 2
state.checkpoints.dir: file:///checkpoints
jobmanager.archive.fs.dir: file:///opt/flink/archive
historyserver.archive.fs.dir: file:///opt/flink/archive"

docker rm -f flink-jobmanager

docker run -d \
  --name flink-jobmanager \
  --network whd-net \
  --network-alias flink-jobmanager \
  --ip 172.30.0.14 \
  -p 8081:8081 \
  -e FLINK_PROPERTIES="$FLINK_PROPERTIES" \
  -v /Users/wenhuadong/docker/streaming/flink/checkpoints:/checkpoints \
  -v /Users/wenhuadong/docker/streaming/flink/archive:/opt/flink/archive \
  flink:1.20.5-java11 jobmanager
```

预期输出：返回容器 ID。http://localhost:8081/overview 可访问。

> 重建会丢运行中作业。执行前确认无重要作业在跑。TaskManager 容器不重建，但要确认它仍能连上 JobManager。

**第四步：给 Dinky 容器挂同一目录**

Dinky 内置 History Server 要读归档目录。当前 Dinky 只挂了 customJar，要重建并加挂归档目录。

```
docker rm -f dinky
```

重建命令与安装文档一致，只增加一行挂载。完整的启动命令在安装文档里，这里只给出新增的挂载参数。

```
-v /Users/wenhuadong/docker/streaming/flink/archive:/opt/flink/archive \
```

> 归档目录在两边都挂到 /opt/flink/archive，路径一致。这样 Flink 写入的归档文件，Dinky 能直接读到。

### 4.3 验证历史查询

① 在 Dinky 用 Standalone 模式提交一个有界作业，比如 datagen 到 blackhole。

② 等作业变 FINISHED。有界源会自己结束，这是正常终态。

③ 检查归档目录有文件。

```bash
ls -l /Users/wenhuadong/docker/streaming/flink/archive/
```

预期输出：出现以作业 ID 命名的目录。

④ 进 Dinky 运维中心 → 作业历史，找到刚提交的作业。点开看作业详情、算子图、异常信息。

| 检查点 | 通过标准 |
| --- | --- |
| 归档目录 | 出现作业 ID 目录 |
| 作业历史列表 | 显示已完成的作业 |
| 作业详情 | 能看到算子图和耗时 |

> 归档由 Flink 在作业完成时写入。历史列表有刷新延迟，提交后等几秒再看。

## 六、故障速查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 历史页空白 | Flink 未配归档目录 | 按 4.2 配置并重建容器 |
| 归档目录为空 | 作业未完成或配置未生效 | 提交有界作业，查 JM 日志 |
| 历史列表看不到新作业 | 刷新延迟或路径不一致 | 等几秒；确认两边挂载同一路径 |
| 宿主机访问 8082 不通 | 未映射该端口 | 正常现象，用 8888 页面查询 |
| Dinky 页面调 8082 失败 | History Server 未启动 | 查日志是否含 Starting Flink History service |
| 集群状态异常 | JM 地址写错 | 写 flink-jobmanager:8081，不带协议前缀 |
| INSERT 后 SELECT 查不到 | 新作业看不到旧表定义 | 查询作业重新声明同一张表 |
| 容器外 SQL CLI 报 Multiple factories | 镜像 classpath 冲突 | 用作业开发页面，不用容器外 CLI |
| 点执行后结果页无数据 | SELECT 被当作业提交 | 改用查询按钮（Shift+F9） |
| 外部 Flink 看不到 Local 作业 | 作业跑在容器内迷你集群 | 用 Standalone 模式提交 INSERT |
| 结果页空白 | WebSocket 被代理拦截 | 本机直连 8888，不配 Nginx |
| 作业 FINISHED 被判失败 | 有界源自行结束 | 看状态 FINISHED 且日志无异常 |

## 七、小结

1. Dinky 日常用法分三块。作业开发、运维中心、历史作业查询。
2. SELECT 看结果用查询按钮（Shift+F9），INSERT 提交用执行按钮。
3. 插入后查询用 filesystem 表。先 INSERT 落盘，再 SELECT 读回。
4. 表定义只在当前会话有效。查询作业要重新声明同一张表。
5. 发布会锁定作业，禁止修改。演示阶段不要点发布。
6. 8082 是 Dinky 内置 History Server，跑在 Dinky 容器内，不用映射宿主机。
7. 历史查询必须有归档目录。Flink 写归档，Dinky 读归档，两边挂同一路径。
8. 有界作业 FINISHED 是正常终态，不是失败。
9. Local 查询不落在外部 Flink。要验证集群执行用 Standalone 提交。
10. 容器外 SQL CLI 有 jar 冲突。日常执行 SQL 用作业开发页面。

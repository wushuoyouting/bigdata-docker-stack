> 官方中文教程：https://flink.apache.org/zh/

> **本文范围**：把一个完整、独立的 Flink 集群装起来。集群用一个容器同时跑 JobManager 与 TaskManager。SQL Client 从同一个容器进入。装完验到 Web UI 有槽位、SQL Client 能查询。不接 Doris、不接 Paimon、不挂任何 connector jar。

# Flink 安装教程

> **一句话结论**：一个 flink:1.20.5-java11 容器，用镜像自带的 start-cluster.sh 起本地 JM 与 TM。对外只映射 8081。验收两条：Web UI 有 2 个槽位，SQL Client 能执行 SHOW CATALOGS。

> **本文解决什么**：本机需要一套能独立运行的 Flink，用于学习和调试。本文给出单容器安装法，无需分角色起多个容器。
>
> **适用谁**：已装 Docker Desktop、懂基本 docker 命令、想在本机跑 Flink SQL 的用户。
>
> **读完能做什么**：一条 docker run 起完整集群、验证安装、停止与重来、处理常见启动故障。

> **核对时点**：2026-11-17。macOS arm64 / Docker Desktop。whd-net 已含 minio .5、superset .6、starrocks .9；8081 被旧容器占用，需先清理。
>
> **本机实测**：flink:1.20.5-java11 为 linux/arm64 原生镜像。已用临时容器验证 start-cluster.sh 单容器方案：overview 返回 taskmanagers=1、slots-total=2。SQL Client 在同一容器执行 SHOW CATALOGS 返回 default_catalog。

## 二、安装前复核

```bash
lsof -nP -iTCP:8081 -sTCP:LISTEN || echo '8081 空闲'

docker ps -a --filter name=flink \
  --format '{{.Names}}\t{{.Status}}\t{{.Ports}}'

docker network inspect whd-net \
  --format '{{range .Containers}}{{.Name}} | {{.IPv4Address}}{{println}}{{end}}'

docker image inspect flink:1.20.5-java11 \
  --format '{{.Os}}/{{.Architecture}}' 2>/dev/null || echo '镜像未拉取'

ls -ld /Users/wenhuadong/docker/streaming/flink/checkpoints/
```

| 检查项 | 期望 | 不满足时 |
| --- | --- | --- |
| 8081 | 空闲或仅旧 flink 占用 | 停旧容器后复查 |
| 旧容器 | flink-jobmanager、flink-taskmanager 不存在 | 执行 docker rm -f 两个旧容器名 |
| whd-net | 存在，172.30.0.14 未被占用 | 占用时换一个 .10 以后的地址 |
| 镜像架构 | linux/arm64 | amd64 时加 --platform linux/amd64 |
| checkpoints/ | 目录存在 | mkdir -p 创建 |

> **注意**：旧容器 flink-jobmanager 与 flink-taskmanager 必须先停掉并删除。它们占用 8081 和 172.30.0.14。删除时不要加 -v。checkpoints/ 是绑定挂载，不受容器删除影响。

## 三、启动集群

### 3.1 为什么这样启动

Flink 官方镜像的 entrypoint 只识别四个命令：jobmanager、taskmanager、standalone-job、historyserver。它不提供一条命令同起 JM 与 TM。

镜像内置发行版脚本 start-cluster.sh。该脚本能在同一个 JVM 进程组里启动本地 JM 与 TM。本方案用 --entrypoint bash 绕过镜像 entrypoint。配置从宿主机 config.yaml 挂载，不被启动脚本改写。容器内先把挂载的 jar 软链进 lib，再调 start-cluster.sh。

### 3.2 一条命令启动

配置文件在 conf/config.yaml。首次启动时从镜像导出一份到宿主机。导出命令如下。

```bash
mkdir -p /Users/wenhuadong/docker/streaming/flink/conf
docker run --rm --entrypoint cat flink:1.20.5-java11 \
  /opt/flink/conf/config.yaml \
  > /Users/wenhuadong/docker/streaming/flink/conf/config.yaml
```

按实际环境修改 conf/config.yaml。必须设置的项见表后。随后用一条命令启动。

```bash
docker run -d \
  --name flink \
  --network whd-net \
  --network-alias flink \
  --ip 172.30.0.14 \
  -p 8081:8081 \
  --entrypoint bash \
  -v /Users/wenhuadong/docker/streaming/flink/conf/config.yaml:/opt/flink/conf/config.yaml:ro \
  -v /Users/wenhuadong/docker/streaming/flink/jars:/opt/flink/custom-jars:ro \
  -v /Users/wenhuadong/docker/streaming/flink/sql:/opt/flink/sql:ro \
  -v /Users/wenhuadong/docker/streaming/flink/checkpoints:/checkpoints \
  flink:1.20.5-java11 \
  -c 'for j in /opt/flink/custom-jars/*.jar; do
       n=$(basename "$j")
       [ "$n" = "paimon-flink-1.20-2.0.0.jar" ] && continue
       ln -sf "$j" "/opt/flink/lib/$n"
     done
     /opt/flink/bin/start-cluster.sh && tail -f /dev/null'
```

预期输出：docker run 返回一串容器 ID。docker ps 显示容器 Up。

> 配置、jar、sql 都从宿主机挂载。容器重建后三者都不丢失。jar 目录挂到 /opt/flink/custom-jars，不直接覆盖 /opt/flink/lib。直接挂 lib 会冲掉镜像自带的 flink-dist 等核心 jar。启动脚本把 jar 逐个软链进 lib，并跳过历史版本 paimon 2.0.0。

| 参数 | 作用 |
| --- | --- |
| 容器名与别名 flink | 同网络其他容器按此名访问 REST 接口 |
| --ip 172.30.0.14 | 固定 IP，重建不漂移 |
| -p 8081:8081 | 暴露 Web UI 与 REST |
| --entrypoint bash | 绕过镜像 entrypoint，直接使用挂载配置 |
| conf/config.yaml 挂载 | 配置从宿主机读取，容器重建不丢 |
| jobmanager.rpc.address: localhost | JM 与 TM 同容器，用回环地址通信 |
| rest.bind-address: 0.0.0.0 | 允许容器外访问 Web UI |
| taskmanager.numberOfTaskSlots: 2 | 单机给 2 个槽位 |
| taskmanager.memory.process.size: 1024m | 限 1G，避免挤掉 Doris BE |
| state.checkpoints.dir | checkpoint 落在挂载目录 |
| sql 目录挂载 | 脚本从宿主机读取，容器重建不丢 |
| custom-jars 目录挂载 | 依赖从宿主机读取，启动时软链进 lib |
| tail -f /dev/null | 保持前台进程不退出 |

> start-cluster.sh 启动的是本地集群。JM 与 TM 在同一个容器内，用 localhost 通信。6163、6123 等内部端口不需要映射，也不需要配置跨容器 RPC 地址。

### 3.3 等待就绪

```bash
for i in $(seq 1 24); do
  curl -fsS http://localhost:8081/overview -o /dev/null 2>/dev/null && {
    echo 'JM 就绪'; break
  }
  echo "第 ${i} 次：未就绪，等 3s"; sleep 3

```

预期输出：最后一行显示 JM 就绪。

## 四、逐条验收

```bash
# ① 容器状态
docker ps --filter name=flink --format '{{.Names}}\t{{.Status}}\t{{.Ports}}'

# ② overview
curl -fsS http://localhost:8081/overview; echo

# ③ TM 注册日志
docker logs flink --tail 200 | grep -iE 'Registering|Registered|started' | tail -10

# ④ SQL Client 只读冒烟
printf 'SHOW CATALOGS;\nEXIT;\n' \
  | docker exec -i flink /opt/flink/bin/sql-client.sh embedded
```

| # | 通过标准 |
| --- | --- |
| ① | 状态 Up，端口显示 0.0.0.0:8081-&gt;8081/tcp |
| ② | JSON 中 taskmanagers=1、slots-total=2 |
| ③ | 日志含 Registering TaskManager 与 Registering task executor |
| ④ | 输出 default_catalog，无 ClassNotFoundException |

> SQL Client 的 embedded 模式会在当前容器内启动一个嵌入式迷你集群。它用于语法调试和只读查询，不占用 8081 上的集群槽位。正式提交作业用 flink run 或 REST 接口。

## 五、停止与重来

```bash
# 停与起
docker stop flink
docker start flink

# 看日志
docker logs -f flink --tail 100

# 完全重来，保留 checkpoints
docker rm -f flink
# 重跑第 3.2 节的 docker run
```

| 动作 | 数据安全 |
| --- | --- |
| stop / start | 容器可写层与 checkpoints 全保留 |
| docker rm -f | checkpoints 是绑定挂载，保留 |
| docker rm -v | 禁止，会删命名卷 |
| rm -rf checkpoints/* | 只有明确重置才做 |

> 起停顺序只有容器一个，不再有先 JM 后 TM 的要求。容器重启后作业状态从 checkpoints 恢复。独立安装阶段没有作业，重来无数据风险。

## 六、故障速查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 端口被占 | 旧容器还在跑 | docker stop 旧容器，确认 8081 空闲 |
| 容器起后立刻退出 | start-cluster.sh 报错 | docker logs flink 看首行错误 |
| overview 无 taskmanagers | TM 未注册 | 查日志中 jobmanager.rpc.address 是否为 localhost |
| 宿主访问不了 8081 | 未设 rest.bind-address | 配置为 0.0.0.0，重建容器 |
| exec format error | arm64 上用了 amd64 镜像 | docker run 加 --platform linux/amd64 |
| SQL Client 报 No FileSystem for scheme s3 | jar 挂载缺失 | 核对 /opt/flink/lib 下 25 个 jar，按 3.2 节重建 |
| 容器名冲突 | 同名容器已存在 | 先 docker rm -f flink |
| checkpoint 目录权限错 | 挂载目录属主不对 | 确认 checkpoints/ 是目录且当前用户可写 |

## 七、小结

1. 独立安装只起一个容器。JM 与 TM 由 start-cluster.sh 在同一容器内启动。
2. SQL Client 不是服务，是镜像自带命令行工具。用 docker exec 进入容器调用。
3. 对外只映射 8081。内部 RPC 端口不暴露，跨容器访问用别名 flink。
4. 验收两条：overview 显示 1 个 TM、2 个槽位；SQL Client 返回 default_catalog。
5. Doris、Paimon、MinIO 的对接不在本次范围。需要写湖时读外部对接.md。

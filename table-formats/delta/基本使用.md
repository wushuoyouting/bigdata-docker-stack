# Delta Lake 基本使用

> **一句话结论**：Delta Lake 用法是「加 jar、配 Spark、建表、读写」。对象存储统一用 MinIO，warehouse 指向 s3://lakehouse/delta/。日常运维靠 OPTIMIZE 与 VACUUM 两个动作。

> **本文解决什么**：给出从零建表到 MERGE、时间旅行、维护的完整命令。
>
> **适用谁**：已装好 MinIO，用 Spark 操作 Delta Lake 的人。
>
> **读完能做什么**：独立建表、批量写、upsert、时间旅行、合并小文件，并排查常见错误。

---

## 一、前置条件

| 项 | 取值 |
| --- | --- |
| 对象存储 | MinIO，桶 lakehouse |
| S3 API | http://minio:9000 |
| 凭据 | 占位符 &lt;MINIO_AK&gt; 与 &lt;MINIO_SK&gt; |
| warehouse | s3://lakehouse/delta/ |
| 计算引擎 | Spark 3.5 |
| Delta 版本 | 与 Spark 大版本匹配 |

前提：lakehouse 桶已建，path-style 已开启。

## 二、依赖 jar 与 Spark 配置

### 2.1 jar

下 delta-spark bundle jar，放进 Spark 的 jars 目录。

```
delta-spark_2.12-<DELTA_VERSION>.jar
```

### 2.2 启动配置

```
spark-sql \
  --jars /path/to/delta-spark_2.12-<DELTA_VERSION>.jar \
  --conf spark.sql.extensions=io.delta.sql.DeltaSparkSessionExtension \
  --conf spark.sql.catalog.spark_catalog=org.apache.spark.sql.delta.catalog.DeltaCatalog \
  --conf spark.hadoop.fs.s3a.endpoint=http://minio:9000 \
  --conf spark.hadoop.fs.s3a.access.key=<MINIO_AK> \
  --conf spark.hadoop.fs.s3a.secret.key=<MINIO_SK> \
  --conf spark.hadoop.fs.s3a.path.style.access=true \
  --conf spark.hadoop.fs.s3a.impl=org.apache.hadoop.fs.s3a.S3AFileSystem
```

注意：两项 SQL 配置必配。缺了无法识别 USING delta 语法。

## 三、建表

### 3.1 标准建表

```
CREATE TABLE IF NOT EXISTS delta_lake.events (
  id BIGINT,
  user_id BIGINT,
  event_name STRING,
  event_time TIMESTAMP,
  dt STRING
)
USING delta
PARTITIONED BY (dt)
LOCATION 's3://lakehouse/delta/demo_db/events'
TBLPROPERTIES (
  'delta.enableDeletionVectors' = 'true'
);
```

### 3.2 从 Parquet 转换

```
CREATE TABLE delta_lake.events
USING delta
LOCATION 's3://lakehouse/delta/demo_db/events'
AS SELECT * FROM parquet.`s3://lakehouse/ods/user_event/`;
```

预期：目标目录出现 _delta_log。

## 四、写入与更新

### 4.1 批量追加

```
INSERT INTO delta_lake.events VALUES
  (1, 1001, 'login',   TIMESTAMP'2026-11-17 09:00:00', '2026-11-17'),
  (2, 1002, 'purchase',TIMESTAMP'2026-11-17 10:30:00', '2026-11-17');
```

预期：SELECT count(*) 返回 2。

### 4.2 覆盖写

```
INSERT OVERWRITE delta_lake.events
SELECT * FROM delta_lake.events WHERE dt = '2026-11-17';
```

### 4.3 MERGE upsert

```
MERGE INTO delta_lake.events AS t
USING (
  SELECT 1 AS id, 'logout' AS event_name,
         TIMESTAMP'2026-11-17 11:00:00' AS event_time,
         '2026-11-17' AS dt
) AS s
ON t.id = s.id
WHEN MATCHED THEN UPDATE SET
  t.event_name = s.event_name,
  t.event_time = s.event_time
WHEN NOT MATCHED THEN INSERT *;
```

预期：id 为 1 的行 event_name 变成 logout。

### 4.4 删除

```
DELETE FROM delta_lake.events WHERE id = 2;
```

开了删除向量时，该操作只写位图，不重写 Parquet。

## 五、查询与时间旅行

### 5.1 普通查询

```
SELECT * FROM delta_lake.events WHERE dt = '2026-11-17';
```

### 5.2 查版本历史

```
DESCRIBE HISTORY delta_lake.events;
```

预期：每次写入占一行，含 version、timestamp、operation。

### 5.3 按版本号读

```
SELECT * FROM delta_lake.events VERSION AS OF 0;
```

### 5.4 按时间戳读

```
SELECT * FROM delta_lake.events TIMESTAMP AS OF '2026-11-17 09:30:00';
```

### 5.5 回滚

```
RESTORE TABLE delta_lake.events TO VERSION AS OF 0;
```

注意：RESTORE 生成新版本，不删除历史。

## 六、流式读写

### 6.1 流读

```
SELECT * FROM stream_delta_events;
```

需先建流表，或用 Structured Streaming 的 readStream。

```
spark.readStream.format("delta").load("s3://lakehouse/delta/demo_db/events")
```

### 6.2 流写

```
df.writeStream.format("delta")
  .outputMode("append")
  .option("checkpointLocation", "s3://lakehouse/delta/_chk/events")
  .start("s3://lakehouse/delta/demo_db/events")
```

注意：checkpointLocation 必须独立目录，且不能与被写表共用。

## 七、维护

### 7.1 合并小文件

```
OPTIMIZE delta_lake.events;
```

### 7.2 按分区合并

```
OPTIMIZE delta_lake.events WHERE dt = '2026-11-17';
```

### 7.3 清理旧文件

```
VACUUM delta_lake.events RETAIN 168 HOURS;
```

预期：删除 7 天前且不再被引用的数据文件。

注意：RETAIN 值小于 168 时，Spark 会拒绝执行。要放宽需改保留时长配置。

### 7.4 查看文件明细

```
SELECT * FROM delta_lake.events.detail;
```

输出每个文件的路径、大小、行数、修改时间。

## 八、使用案例

### 8.1 场景背景

订单表在数仓里，需要每天增量同步到湖上，支持行级更正和历史回溯。

### 8.2 数据流

```
业务库
  └─ Spark 每日增量抽取
       └─ Delta 表 s3://lakehouse/delta/demo_db/orders/
            ├─ MERGE 做 upsert
            ├─ OPTIMIZE 合并小文件
            └─ DESCRIBE HISTORY 做审计
```

### 8.3 落地步骤

① 建目标表，开删除向量。

```
CREATE TABLE delta_lake.orders (
  order_id BIGINT,
  status STRING,
  amount DECIMAL(18,2),
  updated_at TIMESTAMP
)
USING delta
LOCATION 's3://lakehouse/delta/demo_db/orders'
TBLPROPERTIES (
  'delta.enableDeletionVectors' = 'true'
);
```

② 把当日增量落临时视图，再 MERGE。

```
MERGE INTO delta_lake.orders AS t
USING daily_orders AS s
ON t.order_id = s.order_id
WHEN MATCHED THEN UPDATE SET *
WHEN NOT MATCHED THEN INSERT *;
```

③ 查审计历史。

```
DESCRIBE HISTORY delta_lake.orders;
```

④ 合并小文件。

```
OPTIMIZE delta_lake.orders;
```

⑤ 在 MinIO 上确认日志与数据落盘。

```
docker run --rm --network whd-net --entrypoint /bin/sh minio/mc:<MC_TAG> -c '
  mc alias set lake http://minio:9000 "<MINIO_AK>" "<MINIO_SK>" &&
  mc ls --recursive lake/lakehouse/delta/demo_db/orders/ | head -40
'
```

预期：看到 _delta_log 目录与 parquet 数据文件。

### 8.4 验证判据

| 项 | 判据 |
| --- | --- |
| 写入 | SELECT count(*) 与源表一致 |
| upsert | 改源表一行，湖上值同步变化 |
| 历史 | DESCRIBE HISTORY 每次提交占一行 |
| 落盘 | MinIO 上有 _delta_log 与 parquet |

### 8.5 踩坑表

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| USING delta 不识别 | 缺两项 SQL 配置 | 加 DeltaSparkSessionExtension 与 DeltaCatalog |
| No FileSystem for scheme s3a | 缺 hadoop-aws | 补 hadoop-aws 与 aws-java-sdk-bundle |
| SignatureDoesNotMatch | 未开 path-style | 设 fs.s3a.path.style.access=true |
| MERGE 报并发冲突 | 两任务改同一分区 | 错峰写入，或按分区拆分作业 |
| 查询变慢 | 小文件与删除向量堆积 | 跑 OPTIMIZE |
| VACUUM 报保留期太短 | RETAIN 小于 168 小时 | 调大保留期或改配置 |
| 时间旅行读不到旧版本 | 跑过 VACUUM | 调大保留期，或避免频繁清理 |

---

## 九、本篇小结

① Delta Lake 用法是加 jar、配两项 SQL 配置、建表、读写。

② MERGE INTO 做 upsert，DELETE 在开删除向量后只写位图。

③ DESCRIBE HISTORY 看版本，VERSION AS OF 做时间旅行。

④ OPTIMIZE 合并小文件，VACUUM 清理旧文件但会破坏历史。

⑤ 并发控制按分区判定冲突，写不同分区通常不冲突。

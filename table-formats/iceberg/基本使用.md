# Iceberg 基本使用

本文指导在已启动的 Quickstart 环境中操作 Iceberg 表。适用对象已完成安装教程并进入 Flink SQL 客户端。读完能完成建 Catalog、建表、写入、查询、时间旅行、增量读取与 Schema 演进。

所有 SQL 在 Flink SQL 客户端内执行。执行前先按安装教程进入客户端。

## 一、创建 Catalog

执行以下语句创建名为 iceberg_catalog 的 Catalog。

```sql
CREATE CATALOG iceberg_catalog WITH (
  'type' = 'iceberg',
  'catalog-impl' = 'org.apache.iceberg.rest.RESTCatalog',
  'uri' = 'http://iceberg-rest:8181',
  'warehouse' = 's3://warehouse/',
  'io-impl' = 'org.apache.iceberg.aws.s3.S3FileIO',
  's3.endpoint' = 'http://object-store:9000',
  's3.access-key-id' = 'admin',
  's3.secret-access-key' = 'password',
  's3.path-style-access' = 'true'
);
```

各配置项含义如下。

| 配置项 | 值 | 含义 |
| --- | --- | --- |
| type | iceberg | 连接器类型 |
| catalog-impl | org.apache.iceberg.rest.RESTCatalog | Catalog 实现类 |
| uri | http://iceberg-rest:8181 | REST 服务内网地址 |
| warehouse | s3://warehouse/ | 数据根路径 |
| io-impl | org.apache.iceberg.aws.s3.S3FileIO | 文件读写实现 |
| s3.endpoint | http://object-store:9000 | 对象存储内网地址 |
| s3.access-key-id | admin | 存储访问账号 |
| s3.secret-access-key | password | 存储访问密钥 |
| s3.path-style-access | true | 启用路径风格访问 |

执行 USE 语句切换到该 Catalog。

```sql
USE CATALOG iceberg_catalog;
```

## 二、创建数据库与表

执行以下语句创建数据库 nyc。

```sql
CREATE DATABASE IF NOT EXISTS nyc;
```

执行以下语句在 nyc 下创建表 taxis。

```sql
CREATE TABLE nyc.taxis
(
  vendor_id BIGINT,
  trip_id BIGINT,
  trip_distance FLOAT,
  fare_amount DOUBLE,
  store_and_fwd_flag STRING
);
```

表名由三段组成。第一段是 Catalog 名，第二段是数据库名，第三段是表名。当前已切换到 iceberg_catalog，故此处省略第一段。

## 三、写入数据

写入前设置 checkpoint。Flink 依靠 checkpoint 提交 Iceberg 事务。未开启时数据可能无法完整落盘。

```sql
SET 'execution.checkpointing.interval' = '10s';
```

执行以下语句插入四行数据。

```sql
INSERT INTO nyc.taxis
VALUES
  (1, 1000371, 1.8, 15.32, 'N'),
  (2, 1000372, 2.5, 22.15, 'N'),
  (2, 1000373, 0.9, 9.01, 'N'),
  (1, 1000374, 8.4, 42.13, 'Y');
```

## 四、查询数据

执行以下语句查看全部记录。

```sql
SELECT * FROM nyc.taxis;
```

预期返回四行，vendor_id 为 1 或 2。

## 五、查看快照

每次写入生成一个快照。查询快照元数据表可列出全部快照。

```sql
SELECT * FROM nyc.taxis$snapshots;
```

返回结果中，snapshot_id 字段是快照编号。增量读取会用到该编号。

## 六、按分支与标签读取

Iceberg 用分支与标签标记历史版本。Flink SQL 支持按已存在的标签或分支读取数据。

标签由其他引擎创建。Spark 可用 CALL 过程给指定快照建标签。本机 Quickstart 只提供 Flink SQL 客户端，无法直接创建标签。

按标签读取时，在表名后加 OPTIONS 提示。

```sql
SELECT * FROM nyc.taxis /*+ OPTIONS('tag'='t1') */;
```

把 t1 替换为实际的标签名。替换时保留两侧单引号。

按分支读取使用 branch 参数。

```sql
SELECT * FROM nyc.taxis /*+ OPTIONS('branch'='b1') */;
```

需说明能力边界。Flink SQL 没有按快照编号直接读取历史数据的语法。快照编号只用于增量读取的起点。需要按编号回溯时，请通过 Spark 或 Java API 操作。通用操作册给出 Spark 的回滚写法。

## 七、增量读取

增量读取只消费两个快照之间的新记录。该操作在流模式下运行。

先切换到流模式并开启动态表选项。

```sql
SET 'execution.runtime-mode' = 'streaming';
SET 'table.dynamic-table-options.enabled' = 'true';
```

执行以下语句从当前快照开始持续读取。

```sql
SELECT * FROM nyc.taxis /*+ OPTIONS('streaming'='true', 'monitor-interval'='1s') */;
```

执行以下语句从指定快照之后开始读取。该快照自身的记录不包含在内。

```sql
SELECT * FROM nyc.taxis /*+ OPTIONS('streaming'='true', 'monitor-interval'='1s', 'start-snapshot-id'='3821550127947089987') */;
```

把 3821550127947089987 替换为实际快照编号。流模式查询会持续运行，按 Ctrl-C 停止。

## 八、Schema 演进

Iceberg 支持加列、删列、改列与重命名。演进行为只修改元数据，不重写数据文件。

执行以下语句增加一列。

```sql
ALTER TABLE nyc.taxis ADD COLUMN driver_id BIGINT;
```

执行以下语句重命名该列。

```sql
ALTER TABLE nyc.taxis RENAME COLUMN driver_id TO driver_key;
```

执行以下语句删除该列。

```sql
ALTER TABLE nyc.taxis DROP COLUMN driver_key;
```

每次演进生成新快照。历史快照仍按当时的 Schema 解析数据。

## 九、Inline 配置建表

除创建 Catalog 外，也可在建表时直接写连接配置。这种方式注册在 Flink 默认 Catalog 下。

```sql
CREATE TABLE taxis_inline_config
(
  vendor_id BIGINT,
  trip_id BIGINT,
  trip_distance FLOAT,
  fare_amount DOUBLE,
  store_and_fwd_flag STRING
) WITH (
  'connector' = 'iceberg',
  'catalog-name' = 'foo',
  'catalog-type' = 'rest',
  'uri' = 'http://iceberg-rest:8181',
  'warehouse' = 's3://warehouse/',
  'io-impl' = 'org.apache.iceberg.aws.s3.S3FileIO',
  's3.endpoint' = 'http://object-store:9000',
  's3.access-key-id' = 'admin',
  's3.secret-access-key' = 'password',
  's3.path-style-access' = 'true'
);
```

catalog-name 是 Flink 连接器必填项。Inline 方式下该值不影响数据落点。数据与元数据仍写入同一个 REST Catalog 与对象存储。

两种方式的区别如下。

| 方式 | 适用 | 特点 |
| --- | --- | --- |
| 创建 Catalog | 多表共享配置 | 配置一次，三段式表名引用 |
| Inline 配置 | 单表临时验证 | 每表重复写连接参数 |

## 十、本篇小结

① 本机 Quickstart 用 REST Catalog，Catalog 名 iceberg_catalog。

② 写入前必须设置 checkpoint，否则 Iceberg 事务无法完整提交。

③ 快照元数据表是 nyc.taxis$snapshots，快照编号用于增量读取起点。

④ Flink SQL 不支持按快照号直接回溯。该操作见通用操作册。

⑤ Schema 演进只改元数据，每次演进生成一个新快照。

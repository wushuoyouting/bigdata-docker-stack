# Kafka 基本操作文档

> 一句话结论：本文档给出 topic、消息、消费者组与诊断的常用命令。命令在 kafka 容器内执行，调用 /opt/kafka/bin 下的脚本。本机用 localhost:9092，同网络容器用 kafka:29092。

> 核对时点：2026-11-21。镜像 apache/kafka:4.3.2。容器状态以安装文档为准，本次未启动。

> 安装步骤见 README.md。CLI 路径复核见 组件手册。

---

## 一、地址与命令约定

### 1.1 地址判据

表 1-1 客户端地址

| 客户端所在位置 | bootstrap.servers 取值 | 结果 |
| --- | --- | --- |
| 宿主机 | localhost:9092 | 连回宿主映射端口 |
| kafka 容器自身 | localhost:9092 | 连回 EXTERNAL listener |
| 同网络容器 | kafka:29092 | 连回 INTERNAL listener |
| 同网络容器 | host.docker.internal:9092 | 失败，元数据返回 localhost:9092 后指向自身 |

最后一行的原因：EXTERNAL listener 向客户端宣告 localhost:9092。客户端在其他容器里会把该地址解析成自己。同网络容器统一写 kafka:29092。

### 1.2 命令写法

本文档的命令把 CLI 全路径写在 docker exec 之后。每行单独复制即可执行。

```bash
docker exec kafka /opt/kafka/bin/kafka-topics.sh --bootstrap-server localhost:9092 --list
```

同网络容器内的程序不使用 docker exec。程序配置里写 kafka:29092。

💡 提示：本文档所有 topic 名以 _whd_smoke 为例。示例 topic 用完即删，公共层交付时 topic 列表为空。

## 三、Topic 操作

### 3.1 列出与描述

```bash
docker exec kafka /opt/kafka/bin/kafka-topics.sh --bootstrap-server localhost:9092 --list

docker exec kafka /opt/kafka/bin/kafka-topics.sh --bootstrap-server localhost:9092 \
  --describe --topic _whd_smoke
```

### 3.2 创建

```bash
docker exec kafka /opt/kafka/bin/kafka-topics.sh \
  --bootstrap-server localhost:9092 --create \
  --topic _whd_smoke --partitions 3 --replication-factor 1
```

单节点只有 1 个 broker。replication-factor 必须写 1。写 3 会报副本不足。

### 3.3 增加分区

```bash
docker exec kafka /opt/kafka/bin/kafka-topics.sh \
  --bootstrap-server localhost:9092 --alter --topic _whd_smoke --partitions 6
```

分区数只增不减。增加分区会改变带 key 消息的分区归属。

### 3.4 删除

⚠️ 注意（设备·数据）：删除 topic 会清除该 topic 的全部消息。操作不可恢复。执行前核对 topic 名。

```bash
docker exec kafka /opt/kafka/bin/kafka-topics.sh \
  --bootstrap-server localhost:9092 --delete --topic _whd_smoke
docker exec kafka /opt/kafka/bin/kafka-topics.sh --bootstrap-server localhost:9092 --list
```

### 3.5 红线

① 公共层交付时 topic 列表为空。
② 业务 topic 由项目阶段创建。
③ 本文档不预置任何业务 topic。

## 四、生产与消费

### 4.1 控制台生产

① 不带 key，交互式写入。每行一条消息。按 Ctrl+D 结束。

```bash
docker exec -it kafka /opt/kafka/bin/kafka-console-producer.sh \
  --bootstrap-server localhost:9092 --topic _whd_smoke
```

② 带 key，用 key 分隔符。

```bash
docker exec -it kafka /opt/kafka/bin/kafka-console-producer.sh \
  --bootstrap-server localhost:9092 --topic _whd_smoke \
  --property parse.key=true --property key.separator=:
# 输入形如 k1:v1
```

③ 管道写入单条消息。

```bash
printf 'whd-kafka-smoke\n' | docker exec -i kafka /opt/kafka/bin/kafka-console-producer.sh \
  --bootstrap-server localhost:9092 --topic _whd_smoke
```

### 4.2 控制台消费

① 从头读取，限时退出。

```bash
docker exec kafka /opt/kafka/bin/kafka-console-consumer.sh \
  --bootstrap-server localhost:9092 --topic _whd_smoke \
  --from-beginning --timeout-ms 8000 --max-messages 10
```

② 读取 key 与 value，指定消费者组。

```bash
docker exec kafka /opt/kafka/bin/kafka-console-consumer.sh \
  --bootstrap-server localhost:9092 --topic _whd_smoke \
  --group whd_demo_group --from-beginning --timeout-ms 8000 \
  --property print.key=true --property key.separator=:
```

③ 只读取指定分区。

```bash
docker exec kafka /opt/kafka/bin/kafka-console-consumer.sh \
  --bootstrap-server localhost:9092 --topic _whd_smoke \
  --partition 0 --offset 0 --timeout-ms 8000 --max-messages 5
```

💡 提示：--timeout-ms 让命令在无新消息时自动退出。不带该参数时命令持续等待。

### 4.3 一次性冒烟流程

```bash
docker exec kafka /opt/kafka/bin/kafka-topics.sh \
  --bootstrap-server localhost:9092 --create \
  --topic _whd_smoke --partitions 1 --replication-factor 1

printf 'whd-kafka-smoke\n' | docker exec -i kafka /opt/kafka/bin/kafka-console-producer.sh \
  --bootstrap-server localhost:9092 --topic _whd_smoke

docker exec kafka /opt/kafka/bin/kafka-console-consumer.sh \
  --bootstrap-server localhost:9092 --topic _whd_smoke \
  --from-beginning --timeout-ms 8000 --max-messages 1

docker exec kafka /opt/kafka/bin/kafka-topics.sh \
  --bootstrap-server localhost:9092 --delete --topic _whd_smoke
```

期望第三条命令输出 whd-kafka-smoke。

## 五、消费者组

### 5.1 列出与描述

```bash
docker exec kafka /opt/kafka/bin/kafka-consumer-groups.sh \
  --bootstrap-server localhost:9092 --list

docker exec kafka /opt/kafka/bin/kafka-consumer-groups.sh \
  --bootstrap-server localhost:9092 --describe --group whd_demo_group
```

describe 输出包含 CURRENT-OFFSET、LOG-END-OFFSET 与 LAG。LAG 为积压条数。

### 5.2 重置位点

⚠️ 注意（设备·数据）：--execute 会让该组重新消费已有消息。执行前先跑 --dry-run。组内有活跃消费者时，该命令会被拒绝。

① 先演练，只打印计划。

```bash
docker exec kafka /opt/kafka/bin/kafka-consumer-groups.sh \
  --bootstrap-server localhost:9092 --group whd_demo_group \
  --topic _whd_smoke --reset-offsets --to-earliest --dry-run
```

② 再执行。

```bash
docker exec kafka /opt/kafka/bin/kafka-consumer-groups.sh \
  --bootstrap-server localhost:9092 --group whd_demo_group \
  --topic _whd_smoke --reset-offsets --to-earliest --execute
```

### 5.3 删除组

⚠️ 注意（设备·数据）：删除组会丢弃该组的位点。组内有活跃消费者时，该命令会被拒绝。

```bash
docker exec kafka /opt/kafka/bin/kafka-consumer-groups.sh \
  --bootstrap-server localhost:9092 --delete --group whd_demo_group
```

## 六、配置与诊断

### 6.1 查看配置

```bash
# broker 级配置
docker exec kafka /opt/kafka/bin/kafka-configs.sh \
  --bootstrap-server localhost:9092 --describe \
  --entity-type brokers --entity-name 1 | head -40

# topic 级配置
docker exec kafka /opt/kafka/bin/kafka-configs.sh \
  --bootstrap-server localhost:9092 --describe \
  --entity-type topics --entity-name _whd_smoke
```

### 6.2 查看元数据与数据目录

```bash
docker exec kafka /opt/kafka/bin/kafka-broker-api-versions.sh \
  --bootstrap-server localhost:9092 | head -10

docker exec kafka sh -c 'ls -la /var/lib/kafka/data | head -20'
```

meta.properties 保存 KRaft 集群 ID 与节点号。该文件随数据卷持久化。

### 6.3 常见异常定位

表 6-1 异常定位

| 现象 | 首查命令 | 处理 |
| --- | --- | --- |
| 客户端超时 | 表 1-1 地址核对 | 同网络容器改回 kafka:29092 |
| 报副本不足 | --describe 看 ReplicationFactor | 单节点建 topic 用 replication-factor 1 |
| 组位点不动 | --describe --group 看 LAG | 核对消费者是否仍在运行 |
| healthcheck 失败 | docker logs kafka --tail 80 | 按 组件手册复核 CLI 路径 |

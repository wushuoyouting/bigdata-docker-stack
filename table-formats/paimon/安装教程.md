> **本文范围**：把 Paimon 表格式装进 Flink，让 Flink 能读写 MinIO 上的 Paimon 湖表。本文不建业务表、不接 Doris 回查，只做安装与冒烟。

# Paimon 安装教程

> **一句话结论**：Paimon 不是服务，没有安装包。安装 = 往 Flink 挂六个 connector jar + 建 filesystem catalog 指向 MinIO。验收两条：SHOW CATALOGS 返回 paimon_lake，写一条数据后 MinIO 出现 data 文件。

> **本文解决什么**：本机已有 Flink 与 MinIO，怎么让 Flink 具备读写 Paimon 表的能力。
>
> **适用谁**：已完成 Flink 独立安装、想在本机写湖的人。
>
> **读完能做什么**：挂齐 jar、建好 catalog、验证 Paimon 能落盘，再进入基本使用建表读写。

> **核对时点**：2026-11-22。本机 Flink 单容器 1.20.5，MinIO 桶 lakehouse。Paimon 版本 1.3.1，与 Doris FE 内置版本一致。

---

## 一、验收对照

| # | 判据 | 验证命令 |
| --- | --- | --- |
| ① | 六个 jar 已加载 | docker exec flink ls -l /opt/flink/lib |
| ② | catalog 建成功 | SHOW CATALOGS 返回 paimon_lake |
| ③ | 写一条数据落盘 | MinIO 出现 data、manifest、snapshot |

**基线参数**：warehouse 固定 s3://lakehouse/paimon，catalog 类型 filesystem，S3 地址 http://minio:9000。

## 二、先厘清：Paimon 没有安装包

Paimon 是表格式，本体是一组 jar。它没有容器、没有进程、没有端口、没有 Web UI。

所谓安装，就是做三件事。

① 把 connector jar 放进 Flink 的 lib 目录。

② 约定 warehouse 路径，本例是 MinIO 的 s3://lakehouse/paimon。

③ 建 filesystem catalog 指向该路径。

做完这三件事，Paimon 就装好了。后续建表读写都走 Flink SQL。

| 项 | 取值 | 判据 |

| Flink 集群 | 1.20.5，单容器 | curl http://localhost:8081/overview 有 slots-total=2 |

## 四、jar 规划

Paimon 写湖最小需要六份 jar。缺任一都会在建表或提交时报错。

| 文件名 | 作用 | 缺失时的报错 |
| --- | --- | --- |
| paimon-flink-1.20-1.3.1.jar | Flink 读写 Paimon 表 | ClassNotFoundException: org.apache.paimon.flink |
| flink-s3-fs-hadoop-1.20.5.jar | 让 s3:// 路径被识别 | No FileSystem for scheme s3 |
| paimon-s3-1.3.1.jar | 识别 s3 凭据 | Unable to load AWS credentials |
| hadoop-hdfs-client-3.3.4.jar | 补 HdfsConfiguration | ClassNotFoundException: HdfsConfiguration |
| hadoop-mapreduce-client-core-3.3.4.jar | 补 FileInputFormat | 只产 data 文件，作业反复重启 |
| flink-doris-connector-1.20-25.1.0.jar | 读 Doris 表，回查链路用 | 建 Doris 源表失败 |

> 前五份是 Paimon 写湖的最小集。第六份只在「从 Doris 读结果表写回」时需要。本机写湖链路用六份一起挂。

**版本对齐**：Paimon 用 1.3.1，与 Doris FE 内置版本一致。jars/ 下的 paimon-flink-1.20-2.0.0.jar 是历史命名，实际内容是 1.3.1，已归档到 jars/archive/。以 1.3.1 为准。

## 五、挂载 jar

单容器里 JobManager 与 TaskManager 共用 /opt/flink/lib，jar 挂一次即可。挂载要重建容器。

```bash
JARS=/Users/wenhuadong/docker/streaming/flink/jars

FLINK_PROPERTIES="jobmanager.rpc.address: localhost
rest.address: 0.0.0.0
rest.bind-address: 0.0.0.0
taskmanager.numberOfTaskSlots: 2
taskmanager.memory.process.size: 1024m
parallelism.default: 2
state.checkpoints.dir: file:///checkpoints
execution.checkpointing.interval: 10s"

docker rm -f flink

docker run -d \
  --name flink \
  --network whd-net \
  --network-alias flink \
  --ip 172.30.0.14 \
  -p 8081:8081 \
  -e FLINK_PROPERTIES="$FLINK_PROPERTIES" \
  -v /Users/wenhuadong/docker/streaming/flink/checkpoints:/checkpoints \
  -v "$JARS/paimon-flink-1.20-1.3.1.jar:/opt/flink/lib/paimon-flink.jar:ro" \
  -v "$JARS/flink-s3-fs-hadoop-1.20.5.jar:/opt/flink/lib/flink-s3-fs-hadoop.jar:ro" \
  -v "$JARS/paimon-s3-1.3.1.jar:/opt/flink/lib/paimon-s3.jar:ro" \
  -v "$JARS/hadoop-hdfs-client-3.3.4.jar:/opt/flink/lib/hadoop-hdfs-client.jar:ro" \
  -v "$JARS/hadoop-mapreduce-client-core-3.3.4.jar:/opt/flink/lib/hadoop-mapreduce-client-core.jar:ro" \
  -v "$JARS/flink-doris-connector-1.20-25.1.0.jar:/opt/flink/lib/flink-doris-connector.jar:ro" \
  flink:1.20.5-java11 \
  bash -c '/opt/flink/bin/start-cluster.sh && tail -f /dev/null'
```

预期输出：返回容器 ID。docker ps 显示 Up。

| 参数 | 作用 |
| --- | --- |
| -v 单个 jar | 把宿主机 jar 以只读挂进 lib 目录 |
| :ro | 只读挂载，防止容器改 jar |

> **单文件挂载前提**：宿主机 jar 必须已存在且是文件。文件缺失时 Docker 会创建同名目录挂进去，Flink 启动报类加载异常。执行前先 ls -l 核对六个文件都在。

## 七、建 catalog 冒烟

方言：Flink SQL。客户端：Flink SQL Client。

先开 checkpoint，再建 filesystem catalog。

```
SET 'execution.checkpointing.interval' = '10s';
SET 'execution.checkpointing.mode' = 'EXACTLY_ONCE';

CREATE CATALOG paimon_lake WITH (
  'type' = 'paimon',
  'metastore' = 'filesystem',
  'warehouse' = 's3://lakehouse/paimon',
  's3.endpoint' = 'http://minio:9000',
  's3.access-key' = '<MINIO_AK>',
  's3.secret-key' = '<MINIO_SK>',
  's3.path.style.access' = 'true'
);

SHOW CATALOGS;
```

用 stdin 喂给 SQL Client，占位符在内存替换，不落盘。

```
python3 -c "
import os
s = open('01_paimon_catalog.sql').read()
s = s.replace('<MINIO_AK>', os.environ['MINIO_AK'])
s = s.replace('<MINIO_SK>', os.environ['MINIO_SK'])
print(s)
" | docker exec -i flink /opt/flink/bin/sql-client.sh embedded
```

预期输出：SHOW CATALOGS 列出 paimon_lake 与 default_catalog。

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| type | paimon | 固定 |
| metastore | filesystem | 元数据落在 warehouse 目录，不用 Hive Metastore |
| warehouse | s3://lakehouse/paimon | 必须与读方完全一致 |
| s3.endpoint | http://minio:9000 | 容器内地址，不能写 localhost |
| s3.path.style.access | true | MinIO 需要路径风格访问 |

> **Paimon 提交绑定 checkpoint**：不开 checkpoint，作业在跑但湖里没有可读数据。上面两条 SET 是前提，不能省。

## 八、写一条数据验收落盘

建 catalog 成功后，写一条数据验证端到端可用。

```
USE CATALOG paimon_lake;
CREATE DATABASE IF NOT EXISTS game_db;

CREATE TABLE IF NOT EXISTS game_db.install_check (
  id BIGINT,
  name STRING,
  PRIMARY KEY (id) NOT ENFORCED
) WITH (
  'bucket' = '1'
);

INSERT INTO game_db.install_check VALUES (1, 'ok');

SELECT * FROM game_db.install_check;
```

预期输出：SELECT 返回一行，id 为 1，name 为 ok。

再确认 MinIO 落盘。

```
docker run --rm --network whd-net --entrypoint /bin/sh minio/mc:<MC_TAG> -c '
  mc alias set lake http://minio:9000 "<MINIO_AK>" "<MINIO_SK>" &&
  mc ls --recursive lake/lakehouse/paimon/ | head -30'
```

预期输出：出现 data-*.parquet、manifest 与 snapshot 三类文件。

> 有界写会自己结束，作业显示 FINISHED 属正常。判据是 MinIO 出现文件，不是作业长期 RUNNING。

## 九、故障速查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| No FileSystem for scheme s3 | 缺 S3 文件系统 jar | 挂 flink-s3-fs-hadoop 与 paimon-s3 |
| Unable to load AWS credentials | 缺 paimon-s3 bundle | 挂 paimon-s3-1.3.1.jar |
| ClassNotFoundException: HdfsConfiguration | 缺 HDFS 客户端 | 挂 hadoop-hdfs-client |
| 只产 data 文件作业反复重启 | 缺 FileInputFormat | 挂 hadoop-mapreduce-client-core |
| 单文件挂载后类加载异常 | jar 在宿主机不存在，Docker 建了同名目录 | ls -l 核对是文件 |
| 作业在跑湖里没文件 | checkpoint 未开 | 设 10s 间隔，等一个周期 |
| SignatureDoesNotMatch | endpoint 写成 localhost | 统一用 http://minio:9000 |
| 建好 catalog 查不到表 | 两边 warehouse 不一致 | 统一 s3://lakehouse/paimon |

---

## 十、小结

1. Paimon 不是服务。安装 = 挂 jar 加建 catalog，不新增容器。
2. 写湖最小集五份 jar，回查链路再加 doris connector，共六份。
3. 单容器下 jar 挂一次即可，JM 与 TM 共用 lib 目录。
4. checkpoint 必须开，Paimon 的 commit 绑定 checkpoint。
5. 验收三条：jar 加载、catalog 建成、写一条数据落盘。

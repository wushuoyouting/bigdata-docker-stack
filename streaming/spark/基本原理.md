# Spark 基本原理

> **一句话结论**：Spark 是分布式内存计算引擎。Driver 编排作业，Executor 执行任务，Master 与 Worker 负责资源。本机把三个角色放进一个容器，客户端按需进入。

> **本文解决什么**：理解 Spark 为什么要有 Driver，standalone 模式下 Master 与 Worker 各管什么，本机为何用单容器装一套集群。
>
> **适用谁**：准备安装 Spark，或想弄清安装命令背后逻辑的用户。
>
> **读完能做什么**：说清一个 SQL 从提交到出结果的完整路径，解释 shuffle 为什么慢，判断 Spark 与 Flink 各自该干什么。

---

## 一、Spark 解决什么问题

Spark 把一批数据读进来，在内存里反复计算，最后写出结果。它替代的是 MapReduce。MapReduce 每步都落盘，Spark 把中间结果留在内存。

| 能力 | 说明 |
| --- | --- |
| 内存计算 | 中间结果驻留内存，迭代计算不再反复读写磁盘 |
| DAG 调度 | 把多个算子合成一张有向无环图，整体优化后执行 |
| 统一栈 | SQL、DataFrame、流处理、机器学习、图计算共用一个引擎 |
| 多语言 | Scala、Java、Python、R 四种接口 |

> Spark 的强项是批量计算。它也能做流处理，但走的是微批模型。毫秒级实时计算交给 Flink。

## 二、四类角色

| 角色 | 英文名 | 职责 | 是否常驻 |
| --- | --- | --- | --- |
| 驱动器 | Driver | 跑 main 方法、建 DAG、切分阶段、调度任务、汇总结果 | 随应用 |
| 执行器 | Executor | 在工作节点上跑具体任务、缓存数据、上报状态 | 是 |
| 集群管理器 | Cluster Manager | 分配资源、管理 Worker 注册 | 是 |
| 工作节点 | Worker | 向 Master 注册、按指令启动 Executor | 是 |

**Driver** 是作业的大脑。它把用户代码转成执行计划，决定每个任务去哪台机器跑。Web UI 的 4040 端口也由 Driver 提供。Driver 退出，应用就结束。

**Executor** 是干活的手脚。它是 Worker 节点上的一个进程，内部按核数并行跑任务。数据缓存、shuffle 写盘、结果上报都在这里发生。

**Cluster Manager** 在本机是 Standalone Master。它记录有哪些 Worker、多少核、多少内存，按应用申请的资源派发。

**Worker** 是 Standalone 模式特有的从节点进程。它启动后主动向 Master 注册。Master 让它起 Executor，它才起。

> 提交端还有一个客户端角色，例如 spark-submit、spark-sql、spark-shell。它负责把代码和依赖交给集群。集群模式提交完就退出，客户端模式的 Driver 跑在客户端进程里。

## 三、两种运行模式

| 模式 | Driver 位置 | 资源来源 | 适用 |
| --- | --- | --- | --- |
| local | 客户端进程内 | 本机线程，无需集群 | 语法调试、小数据验证 |
| standalone | 客户端进程或集群 | Master 与 Worker | 学习角色协作、验证提交链路 |

local 模式写 spark:// 地址会连不上。它用一个 JVM 内的线程池模拟集群，例如 local[2] 表示两个线程。这套集群不需要 Master。

standalone 模式才需要 Master 与 Worker。本机装的就是这一种。应用提交后，Driver 向 Master 申请 Executor，Master 让 Worker 起进程。

> **本机取舍**：装 standalone，不装 local 专用环境。同一个容器里既能提交到集群，也能用 local 模式做语法调试。两种模式共用一份配置与依赖。

**集群模式与客户端模式的区别**在 Driver 跑在哪。本机容器内提交，Driver 就在容器里。这也是容器不映射 7077 也能工作的原因。

## 四、作业执行链路

① 保存 spark-sql 或 spark-submit，客户端把应用交给 Master。
② Master 选一个有资源的 Worker，通知它启动 Executor。
③ Executor 启动后向 Driver 注册，报告可用核数与内存。
④ Driver 解析 SQL 或代码，生成逻辑计划。
⑤ 优化器改写逻辑计划，生成物理计划。
⑥ 物理计划按宽依赖切成分阶段。
⑦ 每个阶段的任务打包成任务集，发给 Executor。
⑧ Executor 执行任务，shuffle 数据写本地磁盘，结果回传 Driver。

> 阶段切分是关键。窄依赖的算子串在同一个阶段里流水执行。遇到宽依赖必须断开，前一段全部算完才能开始下一段。

## 五、三层接口

| 层次 | 形态 | 特点 |
| --- | --- | --- |
| RDD | 弹性分布式数据集 | 最底层，直接描述分布式集合与算子 |
| DataFrame | 带 schema 的表 | 有列名与类型，可被优化器改写 |
| SQL | 文本语句 | 与 DataFrame 等价，最终走同一套优化 |

三者不是三套引擎。DataFrame 与 SQL 都被 Catalyst 优化器解析成同一棵逻辑计划树，再生成同一份物理计划。RDD 接口绕过优化器，性能靠用户自己调。

Catalyst 做四件事：解析、分析、优化、生成物理计划。分析阶段查元数据，确认表和列存在。优化阶段做谓词下推、列裁剪、常量折叠。生成阶段选连接算法与广播策略。

Tungsten 负责执行效率。它用二进制格式存数据，减少对象开销。它做全阶段代码生成，把多个算子合成一段字节码。

> 3.5 默认开启自适应查询执行。它在运行时按实际数据量合并小分区、切换连接策略。分区数不再需要靠猜。

## 六、惰性求值与 shuffle

**转换算子**只记录计算步骤，不立刻执行。例如 filter、select、join。**行动算子**才触发真正计算，例如 count、show、write。

Spark 用血缘关系记录每一步转换。某个分区丢了，按血缘重算即可，不必重跑整个作业。

依赖分两类：

| 类型 | 含义 | 例子 | 是否触发 shuffle |
| --- | --- | --- | --- |
| 窄依赖 | 父分区只被一个子分区使用 | map、filter、union | 否 |
| 宽依赖 | 一个子分区依赖多个父分区 | groupBy、join、repartition | 是 |

shuffle 是 Spark 最贵的操作。它要把数据按 key 重分发，跨网络传输，落本地磁盘，再按分区读取。数据量一大，磁盘与网络就成为瓶颈。

减少 shuffle 的三个做法：提前过滤数据、用广播连接处理小表、按分区键建表避免再次重分布。

> 判断一条 SQL 快不快，先看执行计划里有没有 Exchange 节点。它代表一次 shuffle。

## 七、Spark 与 Flink 的分工

| 维度 | Spark | Flink |
| --- | --- | --- |
| 计算模型 | 批为主，流为微批 | 原生流，批是流的特例 |
| 延迟 | 秒级 | 毫秒级 |
| 状态管理 | 无托管状态，靠血缘重算 | 托管状态加 checkpoint |
| 典型用途 | 离线分析、批量回刷、特征加工 | 实时入湖、实时指标、变更捕获 |
| 本仓库定位 | 批量分析与历史数据重算 | 实时链路写入 Paimon |

两者不冲突。Flink 把实时数据写进 Paimon 湖表，Spark 读同一批湖表做批量分析。存储是共享的，计算各管一段。

> Spark 的 Structured Streaming 也能写湖。它按微批提交，端到端延迟以秒计。需要亚秒级时选 Flink。

## 八、单容器与分容器的取舍

| 维度 | 单容器 | 分容器 |
| --- | --- | --- |
| 容器数 | 1 | 1 Master 加 N Worker |
| 角色隔离 | 无，共命运 | 有，独立重启 |
| 扩 Worker | 不支持 | 支持 |
| RPC 配置 | 容器内主机名 | 服务名或固定 IP |
| 内存占用 | 低 | 高 |
| 适用 | 本机学习、功能验证 | 生产、多用户、大作业 |

生产环境按 Master 与 Worker 分容器部署，Worker 可加到几十台。Master 重启不影响正在跑的任务。

本机 16G 内存还要跑 Doris、MinIO、Flink 等组件。单容器省内存，配置也少一层网络。代价是一个进程组退出，整个容器结束。这个代价在学习环境可接受。

> 两种形态的 SQL 写法完全一致。迁移时改的是容器数量与 Master 地址，不改业务语句。

## 九、端口与网络

| 端口 | 用途 | 本机处理 |
| --- | --- | --- |
| 7077 | Master 与 Worker、Driver 之间的 RPC | 只在容器内，不映射宿主 |
| 8080 | Master Web UI | 映射宿主 18083 |
| 8081 | Worker Web UI | 不映射，经 Master 反向代理访问 |
| 4040 | 应用 Web UI，由 Driver 提供 | 不映射，经反向代理访问 |
| 18080 | History Server UI | 映射宿主 18084 |

**为什么不开 4040**：Driver 端口随应用变化，同时跑两个应用会撞端口。本机开启 Master 的反向代理，把 Worker UI 与应用 UI 统一挂到 Master UI 的链接下。宿主只需访问 18083 一个入口。

**为什么不开 7077**：客户端在容器内提交，与 Master 走容器内回环。宿主上的 IDE 要直连时，再单独映射并调整 Driver 主机名。

> 同网络其他容器访问 Master 写 spark://spark:7077。宿主浏览器访问 UI 写 localhost:18083。两个地址指向同一个服务。
